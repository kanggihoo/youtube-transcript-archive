Explanatory는 Claude가 자신이 하는 일을 더 많이 설명하는 스타일입니다. Learning 스타일은 Claude가 작업 일부를 여러분에게 직접 써 보라고 해서 만들면서 배우게 하는 스타일입니다. 이 중 하나로 바꾸려면 명령어 뒤에 원하는 스타일 이름을 입력하기만 하면 됩니다. 그때부터 Claude는 그 output style을 사용합니다.

**10:12** · Claude Code는 예전에 control과 O를 누르면 Claude가 한 모든 추론의 요약을 보여 줬습니다. 하지만 이제 Claude Code는 그 요약을 보여 주지 않습니다. 되돌리려면 메인 .claude 폴더의 settings.json 파일에 show thinking summaries라는 설정을 추가하고 true로 설정하면 됩니다. Claude에게 긴 작업을 맡겨 두고 돌아오면 여러분의 프롬프트와 Claude의 답을 찾으려고 한참 위로 스크롤해야 합니다.

### Focus Mode

**10:37** · Claude Code가 보통 매 단계에서 하는 모든 변경을 보여 주기 때문입니다. 하지만 Claude Code에는 여러분의 프롬프트와 Claude의 답만 보여 주는 focus mode도 있습니다. Claude가 한 일의 짧은 요약도 함께 보여 줍니다. focus mode를 쓰려면 먼저 터미널에서 Claude Code의 화면 배치를 제어하는 TUI 명령어를 실행해 full screen으로 설정해야 합니다. focus mode는 full screen 모드에서만 동작하기 때문입니다. 그다음 focus 명령어를 실행합니다. 이제 Claude에게 어떤 작업을 시켜도 무엇을 하고 있는지, 어떤 파일을 읽고 있는지 여전히 볼 수 있습니다.

**11:05** · 하지만 그 단계들은 Claude가 끝나면 화면에서 사라집니다. 그래서 긴 작업 후 돌아오면 Claude의 답만 보이고, 뭔가를 찾으려고 많이 스크롤할 필요가 없습니다. 대화 도중에 Claude가 이미 한 일을 잃지 않고 다른 아이디어를 시도해 보고 싶을 때가 있습니다. 그럴 때 Claude Code에는 branch라는 명령어가 있습니다.

### Side Tasks

**11:24** · Branch는 지금 대화를 복사해 그 복사본을 새 세션으로 엽니다. 그래서 복사본에서 새 아이디어를 시도하면서도 첫 번째 세션에서의 위치를 그대로 유지할 수 있습니다.

**11:32** · 하지만 branch는 여전히 프롬프트를 직접 입력해야 합니다. 그냥 곁다리 작업이 처리되기만 바랄 때는 대신 fork를 씁니다. Fork는 기본적으로 branch와 같지만, 복사본을 백그라운드에서 시작하고 여러분이 원하는 작업을 그 복사본에 줍니다. 그래서 복사본이 그 작업을 하는 동안 여러분은 평소처럼 메인 세션을 계속 쓸 수 있습니다. 작업이 끝나면 백그라운드 세션은 저절로 종료됩니다. 하지만 fork는 항상 완전히 새 세션을 만듭니다.

**11:53** · 곁다리 작업을 지금 세션 안에서 처리하고 싶다면 Claude가 그것을 sub agent에게 넘깁니다. 보통 Claude가 시작하는 sub agent는 컨텍스트가 비어 있습니다. 즉 여러분의 대화에 대해 아무것도 모르고, 메인 에이전트가 시작할 때 준 프롬프트만 받습니다. 그래서 subtask 명령어가 필요합니다. 이 명령어는 여러분의 전체 컨텍스트를 가진 sub agent를 시작합니다. 사용하려면 subtask를 실행하고 원하는 작업을 말하기만 하면 됩니다. 그러면 sub agent가 여러분의 대화 전체를 컨텍스트에 담고 그 작업을 합니다. 저희는 같은 프로젝트를 Claude Code 세션 여러 개에서 작업하는 일이 자주 있는데, 각 세션은 자기 대화만 압니다.

### Multi-Session Fixes

**12:24** · 이제 Claude Code에는 이 세션들이 서로 대화할 수 있게 하는 기능이 있습니다. 연락할 수 있는 세션을 보려면 list agents 명령어를 실행합니다. 예를 들어 같은 프로젝트의 서로 다른 부분을 작업하는 세션이 둘 있다고 합시다. 첫 번째 세션이 어떤 것을 알아야 하는데, 두 번째 세션이 이미 알아낸 내용입니다. 하지만 그 컨텍스트를 직접 복사해 옮기고 싶지는 않습니다. 그러면 첫 번째 세션에게 두 번째 세션에 메시지를 보내라고 하면 됩니다. 두 번째 세션이 아직 작업 중이어도 첫 번째 세션은 두 번째에게서 곧바로 답을 받습니다. 그리고 그 답을 가지고 작업을 이어 갑니다. 세션을 많이 돌리고 있으면 전부를 지켜볼 수는 없습니다.

**12:55** · 그리고 Claude가 여러분에게 무언가 필요하면 질문을 하고 답을 기다립니다. 그 세션을 지켜보고 있지 않으면 Claude가 막혀 있다는 걸 알 수 없습니다. 나중에 돌아와 보면 Claude가 여전히 기다리고 있을 수 있습니다. 이를 고치기 위해 ask user question timeout이라는 설정이 있습니다. 메인 .claude 폴더의 settings.json 파일에 추가하고 60초나 원하는 다른 시간으로 설정하면 됩니다. 그 시간이 지나면 Claude는 제안된 답을 스스로 고르고 계속 작업합니다. 그래서 돌아왔을 때 Claude는 질문을 기다리는 대신 계속 일하고 있습니다.

**13:24** · 하지만 Claude는 여러분 없이도 진행할 수 있을 때만 이렇게 합니다. 질문이 더 나아가기 전에 여러분의 답이 꼭 필요하다면 어떤 옵션도 고르지 않습니다. 대신 여러분이 답할 때까지 계속 기다립니다. 그리고 세션이 많이 열려 있으면 어느 것이 답을 기다리고 있고 어느 것이 이미 끝났는지도 알 수 없습니다. 이를 고치려면 config 명령어를 실행해 목록 아래쪽에서 local notifications를 찾으세요. 엔터를 누르면 원하는 알림 종류를 고를 수 있습니다. 저희는 terminal bell을 골랐지만 어느 것이든 고를 수 있습니다.

**13:53** · 이 설정을 켜 두면 Claude가 끝났을 때나 여러분의 답이 필요할 때 Claude Code가 알려 줍니다. plan mode로 전환하면 Claude Code는 세션을 시작할 때 쓴 것과 같은 모델을 사용하지만, model 명령어를 실행하고 그 뒤에 opus plan을 입력하면 바꿀 수 있습니다.

### Model Routing

**14:07** · Claude Code는 plan mode에서만 opus를 씁니다.

**14:10** · 그 밖의 모든 작업에는 sonnet 모델을 씁니다. 그래서 계획에는 더 강한 모델을 쓰고, 구현은 sonnet으로 돌립니다.

**14:16** · Opus plan은 사용량도 아껴 줍니다. sonnet이 opus보다 한도를 덜 쓰기 때문입니다. 이는 pro 플랜에서 가장 중요한데, 그 플랜에서는 한도에 훨씬 빨리 도달하기 때문입니다. Claude가 시작하는 sub agent도 여러분의 한도를 쓰며, 어떤 모델을 쓸지 고를 수 있습니다.

**14:30** · 기본적으로 각 sub agent는 세션과 같은 모델이나 Claude Code가 골라 준 모델을 씁니다. 모든 sub agent가 더 작은 모델 하나를 쓰게 하려면 claude code sub agent model을 원하는 모델로 설정하면 됩니다.

**14:42** · 그다음 claude code sub agent model force를 1로 설정합니다. 이 두 번째 설정이 필요한 이유는 없으면 sub agent 자신의 파일이 여전히 다른 모델을 고를 수 있기 때문입니다. 하지만 sub agent 자신의 파일이 모델을 고르게 하고 싶다면 이 설정은 건너뛰어도 됩니다. 두 설정 모두 메인 .claude 폴더의 settings.json 파일에 들어갑니다. Claude Code는 시작할 때 이 설정을 읽습니다. 그래서 다음 세션부터는 모든 sub agent가 여러분이 고른 모델을 씁니다. 이런 설정 외에도 작업 흐름에 도움이 되는 키보드 단축키가 몇 가지 있습니다. 첫 번째는 prompt stashing입니다.

### Shortcuts
