# AI 네이티브 조직은 스킬로 움직입니다: 구조화 및 확장 전략

## 한 줄 요약

AI 네이티브 조직의 성패는 개별 프롬프팅이 아니라 마이크로서비스 설계 원칙을 적용한 재사용 가능하고 결정론적인 스킬(Skills)의 전사적 거버넌스와 중앙 플랫폼 구축에 달려 있다.

## 에이전틱 소프트웨어 스택과 전체 수명주기(SDLC)

- **내부 루프 vs 외부 루프**: 내부 루프는 코딩 에이전트 하네스(컨텍스트 관리자, 툴/MCP, 메모리, 스킬 로더)이며, 외부 루프는 스킬, 서브 에이전트, 워크플로가 유기적으로 결합된 런타임 시스템
- **단일 워크플로의 한계**: 명세-계획-작업-구현의 4단계는 전체 제품 수명주기의 일부일 뿐임. 엔터프라이즈 환경은 프로덕트 전략, 데이터 제품 배포, 플랫폼 엔지니어링, 운영/관측성 등 부서별로 복잡한 다중 SDLC가 얽혀 있음

## 스킬(Skills)의 마이크로서비스 설계 원칙

조직의 실질적인 노하우는 도구(MCP)나 훅이 아닌 스킬 레벨에 축적됩니다. 스킬을 구축할 때는 다음의 마이크로서비스 원칙을 준수해야 합니다:

1. **재사용성 및 모듈화**: 여러 워크플로에서 공통으로 조립 가능한 독립된 단위
2. **발견 가능성(Discoverability)**: 전사 엔지니어가 필요한 스킬을 즉시 검색하고 식별 가능
3. **이식성(Portability)**: 오픈 표준을 준수하여 Claude Code, Cursor, Codex 등 하네스에 구애받지 않고 동작
4. **전문화(Specialized)**: 단일 모놀리스 스킬 대신 하나의 특정 작업을 명확히 수행하도록 설계
5. **조합 가능성(Composable)**: 여러 스킬이 충돌 없이 결합되어 규제 준수, 데이터 보존, 감사 리포트 등을 결정론적으로 산출
6. **점진적 공개(Progressive Disclosure)**: 필요한 시점에 필요한 최소한의 지침만 주입하여 컨텍스트 낭비 및 토큰 비용 절감

## 거버넌스 없는 스킬이 초래하는 6대 기술 부채

거버넌스 없이 각 팀이 무분별하게 스킬을 생성할 경우 다음과 같은 부채가 발생합니다:

- **중복(Duplication)**: 동일한 기술 스택을 다루면서도 팀 간 공유 없이 중복 스킬 양산
- **품질 저하(Quality Degradation)**: 모델 업그레이드에 맞춰 테스트/유지보수되지 않아 시간 경과에 따라 오작동
- **소유권 부재(Lack of Ownership)**: 유지보수 주체가 없어 스킬이 방치됨
- **보안 위협(Security Risks)**: 외부 공개 스킬의 프롬프트 주입 및 임의 스크립트 실행 위험
- **권한 관리 부재**: 민감한 비즈니스 로직에 대한 접근 제어 실패
- **비용 폭증**: 불명확한 지침으로 인한 토큰 과소비

## 중앙 집중형 스킬 플랫폼 및 로드맵

- **개인 → 팀 → 전사 중앙 플랫폼**: 개인의 스킬 생성 및 팀 공유를 넘어 메타데이터 기반 카탈로그, 버전 관리, 접근 제어, MCP 검색, CLI 배포가 결합된 전사 플랫폼 필요
- **도메인별 오너십 분배**: 아키텍트, 엔지니어링 리드, 보안 리드가 도메인별 스킬을 직접 소유하고 정책 정렬 관리
- **향후 과제**: 사내 개발자 포털(IDP)과 연계된 스킬 레지스트리, Anthropic 모범 사례 기반의 정적 평가(Eval) 파이프라인 구축
