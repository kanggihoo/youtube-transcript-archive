# Claude Code와 1000시간 넘게 함께하며 배운 것들

## 한 줄 요약

Claude Code의 핵심은 비싼 토큰 한도와 '멍청이 구간(Dumb zone)'을 피해 작업마다 세션을 분리하고, 계획 모드와 테스트 기반 검증 하네스로 제어하는 것이다.

## 컨텍스트 관리와 토큰 절약 전략

Claude Code는 컨텍스트가 10만~20만 토큰을 넘어가면 환각과 실수가 급증하는 **'멍청이 구간(Dumb zone)'**에 진입합니다.

- **작업마다 새 세션 시작**: 이전 대화 히스토리가 쌓인 세션에 이어서 작업하면 토큰 소모가 급증하고 품질이 급락합니다.
- **구체적인 프롬프트와 리서치 경로 차단**: 모호하게 지시하면 Claude가 온갖 파일을 읽어대며 토큰을 낭비합니다. 정확히 수정할 파일과 참조 경로만 지정해야 합니다.
- **`/compact`에 의존하지 말 것**: 중간에 자동 압축이 발생하면 기억이 손상되므로, 압축 대신 새 세션을 여는 것이 낫습니다.

## 필수 기능 티어 분류

| 등급 | 기능/도구 | 설명 |
|---|---|---|
| **SSS** | **검증(Verification)** | 단순 완료 보고가 아닌 테스트 선작성, 타입 체커, 린터, 브라우저 스크린샷으로 통과 증명 |
| **S** | **계획 모드 (Shift+Tab)** | 코드를 바로 수정하지 않고 철저히 읽어 전체 계획을 먼저 제시하고 사용자 승인을 받음 |
| **S / A** | **스킬(Skills)** | 반복 워크플로, 모범 사례를 마크다운(`SKILL.md`)으로 주입 (과도한 설치는 지양) |
| **A** | **MCP** | DB 시딩, 브라우저 테스트, GitHub 등 외부 시스템 연동에만 한정해 사용 |
| **A** | **Git Worktrees** | 각 에이전트 세션마다 독립된 워크트리 폴더를 배정해 충돌 없는 병렬 개발 |
| **A** | **`/loop` & 서브 에이전트** | 반복 크론 자동화(이슈 구현, 버그 스캔) 및 독립 컨텍스트를 갖는 서브 에이전트 위임 |
| **C / D** | `/init` & 기본 `claude.md` | 초기 자동 생성 문서에 과도하게 의존할 필요 없음 |

## 추천 스킬 및 조합

- **계획과 구현 모델 분리**: Opus 같은 상위 모델로 계획을 짜고(`improve` 스킬 활용), 빠른 모델로 구현을 위임해 비용 절감
- **코드 품질 & 아키텍처**: `improve-codebase-architecture` + `Thermonuclear code quality review` 결합으로 슬롭(조잡한 코드) 제거
- **요구사항 정제**: 맷 포콕의 `grow-with-doc`

## 도구에 종속되지 마라

루프 자동화나 프롬프팅 기법도 결국 기본 프로그래밍 개념(for 루프, 모듈화 등)의 재발명에 불과합니다. 코드를 읽고 아키텍처를 판단할 줄 모르면 AI에 휘둘려 도태되므로, AI가 작성한 변경 사항을 이해하고 자신을 성장시키는 수단으로 삼아야 합니다.
