# 한국어 번역

안녕하세요. 오늘은 개발자들이 Jev를 활용해 만드는 흥미로운 사례를 살펴보겠습니다. Klein은 Jev에 브라우저를 연결했고, Browser Use는 약 7초 만에 항공편을 검색하는 데모를 공개했습니다. 다른 개발자들은 코딩 모델 선택, 에이전트 메모리 정리, 작업 완료 여부 판단에 Jev를 쓰고 있습니다. 자연어 조건을 SQL에 넣거나 영어로 코딩 규칙을 작성하고, Vampire Survivors를 플레이하게 한 사례도 있습니다. 작은 의사결정 모델 하나가 여러 위치에서 쓰이는 방식이 흥미롭습니다. 실제로 살펴볼 만한 활용 사례를 프로젝트 저장소, X 게시물, Reddit 토론, 공개 실험에서 찾아봤습니다.

대부분 아직 초기 단계입니다. 사용 가능한 통합, 실험, 초기 데모를 구분해 설명하겠습니다.

Jev는 TypeSafe AI의 의사결정 모델입니다. 정보와 구체적인 질문을 주면 선택지, 점수 또는 예/아니요 판단의 확률을 돌려줍니다. 더 큰 모델은 계획을 세우고 코드를 작성하며, Jev는 어떤 버튼을 누를지, 어떤 스킬을 불러올지, 결과를 더 확인해야 할지를 판단할 수 있습니다. 같은 정보에 대한 여러 질문을 요청 하나로 묶을 수도 있습니다.

## 브라우저 자동화

Klein의 Jev 브라우저 플러그인은 코딩 에이전트와 분리된 Chromium 세션을 제공합니다. Klein이 브라우저 작업 목표를 넘기면 Jev가 페이지에서 발견한 컨트롤을 대상으로 행동을 고릅니다. 입력할 텍스트가 필요하면 작은 Gemini 모델이 Verscell AI 게이트웨이를 통해 문구를 만듭니다. 플러그인은 스크린샷, 브라우저 오류, 녹화 정보를 돌려주므로 에이전트가 실제 동작을 확인할 수 있습니다. 개발자는 고장 난 필터를 수정한 뒤 브라우저 작업자가 기능을 시험하고, Klein이 결과를 검토하도록 할 수 있습니다.

플러그인은 반복 절차가 끝난 것과 성공이 검증된 것을 구분합니다. 결과 확인은 여전히 Klein의 몫입니다. 이 플러그인의 종단 간 속도 벤치마크는 아직 공개되지 않았으므로 핵심은 작업 흐름입니다.

Browser Use의 Jev Ultrafast 프로젝트는 취리히에서 런던으로 가는 Google 항공편을 약 7초 동안 검색하는 녹화 데모를 공개했습니다. 이 시간 안에 표를 구매한 것은 아닙니다. 브라우저가 현재 컨트롤 목록을 제공하고, Jev가 동작과 대상을 골라 브라우저가 실행한 뒤 반복합니다. 도시 이름처럼 텍스트 입력이 필요하면 텍스트 모델을 부릅니다. 보고된 실행은 Jev 요청 17회와 텍스트 보조 호출 2회로 7초가 조금 넘게 걸렸습니다. 초기 페이지 이동과 사후 독립 검증은 측정 시간에 포함되지 않았습니다.

커뮤니티의 Codex 통합 사례인 Jev Browser Use는 에세이 피드백 앱을 시험하며 평가를 열고, 메모를 펼치고, 인터페이스를 이동하는 데 Jev를 썼습니다. Codex는 피드백이 주석과 맞는지 확인했습니다. 반복 화면을 많이 검사하는 앱에 유용한 역할 분담입니다.

초안 단계의 Stagehand 통합은 페이지 요소 중 정보를 담은 부분을 Jev가 고르고 일반 코드가 값을 복사하도록 합니다. 상품 목록의 제목과 가격처럼 페이지에 이미 있는 데이터를 찾아 구조화하는 방식입니다. 저자의 시험에서는 추출 75회 중 37회가 언어 모델 호출 없이 약 0.5초에 완료됐습니다. 보고된 성공률을 유지하려면 전체 시스템에서 LLM 대체 경로가 필요했습니다. 조사 당시에는 초안 기능이며 선택적으로 켜야 했습니다. 결과 구조를 검증하고 빠른 경로로 부족할 때 대체 경로를 쓰면 웹 스크래핑, 레코드 가져오기, 페이지 간 정보 비교에 응용할 수 있습니다.

## 코딩 에이전트의 컨텍스트와 모델 선택

Fast Jev Compaction은 오래된 도구 호출 중 무엇을 남길지 Jev가 골라 코딩 에이전트 컨텍스트를 줄이는 Clawed Code 플러그인입니다. 내용은 그대로 보존하면서 유지, 축약, 삭제를 결정합니다. 정확한 오류 문구나 파일 경로를 요약으로 바꾸지 않고 남길 수 있다는 장점이 있습니다. 반면 잘못된 결과를 지우면 정보가 사라집니다. Jev가 실패하거나 충분히 줄이지 못하면 Claude Code의 기본 요약으로 돌아갑니다.

관련 프로젝트 Yoshi가 공개한 작은 실험에서는 입력 토큰이 줄었지만 실행이 느려지고 Jev 오류도 발생했습니다. 토큰 감소만으로 에이전트가 나아졌다고 볼 수 없습니다. 작업 해결 여부, 걸린 시간, 전체 비용을 함께 재야 합니다.

Jev Router는 Clawed Code와 Codex를 감싸 사용자 요청이 시작될 때 모델 등급을 고릅니다. 실제 작업은 코딩 모델이 계속 수행합니다. 불확실한 판단에 대한 대체 경로와 모델 전환 비용 검사를 포함합니다. 단순한 수정에는 저렴한 모델을, 어려운 설계 문제에는 강한 모델을 쓰려는 방식입니다. 한 Codex 라우터 프로젝트가 과거 대화의 가격을 다시 계산해 큰 절감률을 보고했지만, 더 저렴한 모델로 작업을 다시 실행해 결과 품질이 같았는지는 검증하지 않았습니다. 유망한 추정치로 보되 실제 작업 결과를 확인해야 합니다.

Jev Skillgate는 관련 스킬을 고르고 Claude Code에 나머지 스킬 정보를 얼마나 보여줄지 줄입니다. 일부는 전체 설명을 유지하고, 일부는 짧은 항목으로 만들며, 나머지는 명시적으로 요청될 때 계속 쓸 수 있게 둡니다. 저자는 스킬 매니페스트 추정 크기를 약 12,700토큰에서 3,200토큰으로 줄였다고 보고했습니다. 이는 스킬 목록의 수치이지 대화 전체가 75% 줄었다는 뜻은 아닙니다. Rust 서비스를 다루는 에이전트가 작업 초반부터 프레젠테이션, 프런트엔드, 영상 제작 스킬과 경쟁하지 않도록 할 수 있습니다. 작업이 바뀔 때 필요한 스킬이 계속 제공되는지가 관건입니다.

Foreman은 Codex 작업자의 진행 상황을 살피는 실험적 감독자입니다. 요구사항 충족 여부, 테스트의 충분성, 막힘 여부, 추가 검증 필요 여부를 점검하고, 일반 정책 코드가 작업을 조정하거나 검증을 요청하거나 완료하도록 둡니다. 첫 버전은 코딩 작업자 하나를 실행합니다. 구현 모델과 별도로 완료 판단을 두고, 완료 선언을 뒷받침할 증거가 있는지 살펴보는 아이디어입니다.

PIWarden은 PI 코딩 에이전트 안에서 프로젝트 규칙 위반, 반복 실패, 근거 없는 완료 주장을 확인합니다. 발견 사항을 에이전트에 피드백해 다시 시도하게 합니다. 예를 들어 하드코딩된 대체 데이터베이스 주소를 프로젝트 규칙 위반으로 지적해 제거한 사례가 저장소에 있습니다.

Jev를 도구 호출 권한 판단에 쓰는 프로젝트도 있습니다. 같은 명령이라도 데이터베이스 초기화를 요청받았을 때와 작은 스키마 변경만 요청받았을 때 적절성이 다를 수 있습니다. 다만 모델 판단은 실제 애플리케이션 권한 규칙 안에서만 사용해야 합니다. TypeSafe 문서는 적대적 콘텐츠가 Jev에 영향을 줄 수 있다고 밝힙니다. 따라서 확률 점수를 무제한 실행 허가로 삼으면 안 됩니다.

Reddit의 ‘Jev as orchestrator’ 게시물에서는 Claude가 코드, 테스트 결과, 실패한 접근, 가능한 설명을 모으고 Jev가 설명의 타당성을 확인해 다음 진단을 고릅니다. 같은 잘못된 가설을 반복하는 에이전트를 다루려는 개인 사례이며 통제된 비용 절감 벤치마크는 없습니다. 가능한 설명을 누가 제안하는지, 전부 틀렸을 때 추가 증거를 요청하거나 상위 단계로 넘길 수 있는지가 남는 질문입니다.

Sergeium 팀은 Codex 기반 장애 대응 에이전트에서 Jev가 진단 테스트 순위를 매기고 증거를 검토하도록 실험했습니다. 에이전트는 계속 시스템을 조사하고 수정했습니다. 문제 10개에 각 5회 시도한 결과, 기준선은 50회 중 20회, Jev 사용 시 24회 통과했습니다. 두 문제는 결과가 나빠졌습니다. 표본이 작고 결과가 섞였지만 전체 방향은 긍정적입니다. 현재 시스템이 정상인 것과 수정이 오래 유지되는 것은 다를 수 있습니다. 근본 원인을 해결했는지, 유지될 증거가 무엇인지 검토하는 것이 중요하다는 점도 드러났습니다.

## 개발 도구와 데이터 처리

Jerep은 의미 설명을 패턴으로 쓰는 명령줄 필터입니다. 텍스트 항목마다 Jev가 의미 일치 여부를 판단하고 원문을 그대로 반환합니다. 스트림 입력도 처리할 수 있습니다. 정확한 오류 코드나 식별자는 기존 검색이 낫지만, 표현이 제각각인 로그에서 불만 신호를 찾거나 메모에서 후속 조치가 필요한 결정을 찾을 때 유용합니다.

Jevant는 코딩 규칙을 의미 질문으로 작성해 선택한 파일을 검사합니다. 이름 있는 상수로 바꿔야 할 문자열이나 목적에 비해 모호한 식별자 이름 등을 기본 검사로 제공합니다. 코딩 에이전트가 코드를 작성하고 린터가 잠재 위반을 보고하면 에이전트가 수정하는 흐름을 의도합니다. 현재 결과는 파일 단위이며 정확한 줄 위치 진단이나 대체 코드 생성은 제공하지 않습니다. 디버그 로그와 의도된 운영 로그처럼 문법만으로 구분하기 어려운 규칙을 실험할 수 있습니다.

Commit Minor는 Git 기록을 거슬러 커밋 메시지와 diff를 버그 수정, 보안 수정 등으로 분류하고 보고서를 남깁니다. 에이전트가 모든 커밋을 자세히 읽기 전에 조사 범위를 좁히는 데 도움을 줄 수 있습니다. 특히 보안 관련 분류는 검토의 단서로 취급해야 합니다.

PGEV는 자연어 조건으로 PostgreSQL의 행을 필터링하거나 순위를 매기게 합니다. 고객지원 티켓에서 이탈 의향이 드러나는 메시지를 찾는 예를 들 수 있습니다. 일반 SQL 날짜·계정 조건과 의미 조건을 결합합니다. 확장은 행 정보를 Jev로 보내 판단을 묶어 처리하고 결과를 캐시하며, 주변 조회는 데이터베이스가 처리합니다. PostgreSQL 기능과 권한이 필요해 관리형 호스팅에서는 사용할 수 없는 경우가 많고 선택한 데이터가 외부 API로 전송됩니다.

Zodv는 Zod 스키마에 의미 검사를 추가합니다. 문자열이나 구조 형태 확인을 넘어 범주가 설명과 일치하는지 질문할 수 있습니다. 승인, 거부, 불확실, 사용 불가 결과를 코드가 처리할 수 있습니다. 서비스가 판단하지 못했을 때 검증이 성공한 척하지 않고 다른 경로로 보낼 수 있습니다.

Honner는 HTTP 라우팅에 같은 생각을 적용합니다. 요청 핸들러가 처리할 유형을 설명하고 Jev가 들어온 요청이 맞는지 판단합니다. AI 클라이언트와 일반 브라우저에 서로 다른 문서 형식을 제공하는 예가 있습니다. 실험적 프로젝트이며 의미 라우팅 요청마다 모델 호출이 추가됩니다. 인증이나 권한 부여에는 쓰지 말라고 저자가 명시합니다.

## 게임과 비용

Reddit의 개발자는 Clawed Code로 Vampire Survivors 모드와 Jev 기반 Python 컨트롤러를 만들었습니다. 모드는 250밀리초마다 게임 정보를 컨트롤러에 보냅니다. 다만 장애물 정보를 넣지 못해 벽에 걸리거나 구석에 들어가 죽는다고 저자는 솔직하게 밝혔습니다. 빠른 판단도 필요한 환경 정보를 입력받아야 도움이 됩니다.

영상에서 소개한 TypeSafe의 출시 가격은 입력 토큰 10억 개당 42달러이며 출력 토큰 요금은 없습니다. 단순 계산으로 평균 입력 1,000토큰인 판단 100만 회는 Jev 입력 비용이 42달러입니다. 실제 청구액은 재시도, 계획·작성 모델, 브라우저 인프라에 따라 달라집니다. 조사 당시 Verscell 모델 페이지에는 2026년 9월 25일 종료 예정인 무료 프로모션이 표시돼 있었습니다. 현재 조건은 다시 확인해야 합니다. Verscell AI SDK에서 Jev는 실험적 평가 API를 사용하므로 일반 채팅 모델처럼 선택해 앱을 작성시키는 용도가 아닙니다.

발표자가 가장 관심을 둔 활용 사례는 브라우저 작업자, 디버깅 검증, 모델·스킬 선택입니다. 기존 작업 하나에 Jev 단계를 추가하고 에이전트가 더 적은 시간이나 비용으로 정확히 완료하는지 비교해 보는 방식을 제안합니다. 모델이 판단을 몇 번 할 수 있는지만 세는 것보다 실제 업무 결과를 비교하는 편이 유용합니다.
