# GitHub 1위 개발자가 만든 새로운 Claude 스킬이 대단한 이유입니다

## 한 줄 요약

에이전트가 "다 했다"고 말하는 대신 **증거를 내놓게** 강제하는 스킬 `unlazy` 소개. 큰 작업을 트리로 쪼개고, 작업 전에 검증 명령을 파일에 박아두고, 스킬이 그 명령을 직접 실행해 통과 여부를 판정합니다.

## 게으름은 두 가지 방식으로 나타난다

모델에는 메모리가 없어서 이전 대화 전체를 매 요청에 다시 실어 보냅니다. 그 더미가 커지면 한 번에 주의를 둘 대상이 많아지고, 작업의 각 부분에 집중하지 못합니다. 컨텍스트가 깨끗할 때는 안 보이지만 채워지면서 드러납니다. Opus나 GPT 5.6에도 있고, 작은 모델에서 한계가 빨리 보일 뿐이라고 말합니다.

- **안 했는데 했다고 함** — 여러 파일을 훑으라고 하면 몇 개만 열고 전부 봤다고 보고
- **몰래 범위를 줄임** — 5개 중 어려운 1개를 건너뛰고, 최종 요약에는 빠진 게 있다는 말이 없음

발표자의 구분이 요점입니다. **명백히 미완인 채로 멈추는 건 괜찮습니다.** 다 했다고 말하면서 멈추는 게 문제입니다 — 직접 검증하기 전까지 알 수 없고, 그 위에 더 쌓으면 나중에 터집니다.

## 기존 해법은 모두 판정자가 텍스트나 에이전트였다

| 방식 | 완료 판정 근거 | 한계 |
|---|---|---|
| Ralph loop | 에이전트가 출력에 쓴 문자열 | 기능이 제대로 만들어졌음을 알려주는 단어는 없음 |
| `goal` 커맨드 | 작은 모델이 **대화**를 읽고 판단 | 결과물이 아니라 대화를 보므로 실제 요구에서 흐를 수 있음 |
| 자체 체크리스트 루프 | 체크는 실제, 채점은 에이전트 | 결국 에이전트가 스스로 완료를 결정 |

셋 다 컨텍스트가 신선할 때 잘 되고, 실전 작업 깊이 들어가면 무너집니다. 버텨야 하는 지점이 바로 거기라는 게 문제입니다.

## 트리: 주의를 좁힌다

큰 작업을 받으면 바로 시작하지 않고 쪼갭니다. 쪼갠 것을 또 쪼개서 가지가 벌어지고(그래서 트리), 말단 작업은 각자 서브에이전트에 넘깁니다. 프롬프트에 깊이 숫자를 주면 그만큼만 쪼갭니다. 안 주면 요청에 맞는 최소값을 고릅니다.

목적은 앞의 주의 문제로 되돌아갑니다 — 작업 하나에 목표 하나만 있고, 그걸 하는 에이전트는 나머지 일감을 들고 다니지 않습니다.

다만 너무 작아도 안 됩니다. **말단 하나가 최소 10분치 실작업**이어야 하고, 숫자를 너무 크게 줘서 그보다 작게 쪼개지면 스킬이 기본값 3으로 낮춥니다.

그 숫자가 실행 방식도 정합니다.

- **3 이하 — solo 모드**(기본). 한 세션에서 같은 에이전트가 전부 처리
- **4 이상 — orchestrated 모드**. `plan.md`(전체 분해)와 작업별 체크리스트를 파일로 씀

## 게이트: 지시가 아니라 파일

파일에 쓰는 이유가 이 스킬의 핵심 교훈입니다. **이전 버전은 "꼼꼼히 하라"고 지시해서 게으름을 고치려 했고 실패했습니다** — 지시는 긴 세션에서 가장 먼저 잊히는 것이고, 그게 바로 고치려던 문제였습니다. 그래서 이번 버전은 부탁하는 대신 **작업 시작 전에 파일에 적어둡니다.**

그 파일이 gates 파일이고, 항목 하나가 게이트입니다. 게이트 = 체크박스 + 충족 조건 하나, 그 아래 세 줄:

1. 그 조건이 달성됐음을 증명하는 **명령어**
2. 그 명령어가 돌려줘야 하는 **정확한 문구**
3. **evidence** — 처음엔 `pending`

스킬에 딸린 checker를 돌리면 파일을 따라 내려가며 명령을 **직접 실행**합니다. 기대한 문구가 나오면 체크하고, `pending`을 판정 근거가 된 출력 조각으로 바꿉니다.

이 evidence 줄이 앞의 세 방식이 못 막은 구멍을 막습니다. **체크됐는데 아래가 여전히 `pending`이면 미충족**이고, 빈 박스보다 나쁘게 봅니다 — 에이전트가 스스로 체크했다는 뜻이니 "다 했다"는 말과 같고, 빈 박스는 적어도 어디까지 갔는지 정직하니까요.

같은 규칙이 큰 실행도 붙잡습니다. orchestrated 모드에서는 새 에이전트에 plan과 자기 gates 파일만 주고 나머지는 알려주지 않습니다. 그 에이전트가 끝났다고 돌아와도 **메인이 그 작업의 체크를 다시 돌립니다.** 통과한 뒤에야 plan에 한 줄 기록하고 다음 작업을 넘깁니다.

정직한 퇴로도 있습니다. 정말 불가능한 작업은 조용히 버리는 대신 **게이트 이름과 이유를 적어 포기 선언**을 하고, 그게 최종 리포트에 들어갑니다.

결론: unlazy는 끝에 붙는 검사 하나가 아니라 시스템이고, **어느 지점에서도 에이전트가 완료 여부를 결정하지 않습니다.**

## 설치

공식 GitHub의 install 섹션에서 명령을 복사해 작업 프로젝트 터미널에서 실행합니다.

1. 어느 에이전트를 쓰는지 — Codex는 이미 읽는 `agents` 폴더에 설치되므로 그대로 두면 됨. Claude Code는 메뉴에서 선택하고, 여러 개를 동시에 고를 수 있음
2. 스코프 — 지금 프로젝트에만 vs 전역. 영상은 특정 프로젝트에서 먼저 시험하려고 project를 선택
3. 나머지는 권장 옵션

VS Code로 열면 폴더가 둘 보입니다. **실물은 `agents` 쪽에 있고 `.claude` 쪽은 그걸 가리키는 숏컷**입니다 — 같은 프로젝트에 사본이 두 개 생기지 않으면서 Claude Code도 인식하게 하려는 것입니다. 그 안의 skill 파일이 사용법 전체를 담고 있습니다.

## 속도 문제와 병렬화 수정

영상의 실측 결과가 경고입니다. **그대로 돌리니 3~4시간 만에 로그인 페이지 하나**만 나왔습니다.

원인은 스킬 지시문이었습니다. Claude Code와 Codex 모두 여러 에이전트를 동시에 돌릴 수 있는데, 스킬이 **작업 하나를 넘기고 끝날 때까지 기다린 뒤 다음을 넘기는** 방식이었습니다. 에이전트를 쓰고는 있었지만 능력을 다 쓰지 못한 것이고, 시간은 거기서 다 갔습니다.

그래서 스킬 자체를 고쳐 동시 실행을 쓰게 했습니다(영상에 프롬프트가 나오며, 일시정지해서 복사하라고 안내합니다). 고친 뒤에는 `plan.md`에 **어느 작업이 어느 파일을 다루는지**까지 적어, 동시에 도는 에이전트끼리 서로의 작업을 덮어쓰지 않게 합니다. 그다음 기반을 깔고 작업을 동시에 뿌립니다.

결과: **에이전트 10개 동시, 약 2시간, 원하던 기능이 전부 동작하는 데모 앱 첫 버전.**

## 실행 순서와 숫자 고르기

`스킬 이름 → 트리 깊이 → 만들 것 전부 서술` 순으로 씁니다. 무엇이든 만들기 전에 먼저 `plan.md`, 그다음 `gates.md`를 씁니다.

깊이는 작업 규모로 정합니다. 영상은 데모 앱을 처음부터 만들었으니 5. **앱 전체가 아니라 기능 하나면 2~3이면 충분합니다.** 필요보다 높게 잡아도 알아서 낮춰주니 잘못 고를 걱정은 없습니다.

이 규모로 만든다면 **model router 스킬**과 짝지으라고 덧붙입니다 — 단순 기계적 작업은 싼 모델, 어려운 부분은 강한 모델로 보내면 한도에 빨리 닿지 않습니다.

## 설치본과 영상의 차이

> 이 절은 발표자의 주장이 아니라, [refs/unlazy](../../refs/unlazy/)에 설치한 버전을 확인한 결과입니다.

**영상이 직접 고쳐 넣은 병렬 실행이 이미 스킬에 들어 있습니다.** `references/parallel.md`가 있고, `SKILL.md`가 동시 말단을 뿌리기 전에 그걸 읽으라고 지시합니다. 겹치지 않는 `OWNS:` 경로를 선언하고 claim하는 방식으로, 영상이 `plan.md`에 파일 담당을 적어 충돌을 막은 것과 같은 문제를 스킬 차원에서 다룹니다. 다만 **스코프와 리스는 조율 수단이지 파일시스템 격리나 보안 경계가 아니라고** 명시합니다.

체크 실행 자체는 여전히 순차가 기본이고, 독립적인 게이트에 대해 `--jobs <N>`으로 병렬 검증을 켤 수 있습니다. 결과 출력 순서는 게이트 순서를 유지합니다.

영상에서 다루지 않은 것들:

- **`--approve`** — 게이트 명령을 실행하려면 명시적 동의가 필요하고, 승인은 저장소 밖에 저장되며 명령·기대값·작업 디렉터리·셸·타임아웃 등에 묶입니다
- **`--reverify`** — 이미 체크된 게이트를 다시 실행해, 더 이상 통과하지 않으면 완료 표시를 걷어냅니다
- **Stop 훅** (`scripts/stop-hook.mjs`, `install-hooks.mjs`) — 세션 종료 시점에 개입
- **통과 기준** — 종료 코드 0과 `EXPECT:` 일치를 **둘 다** 요구하고, evidence에 셸·작업 디렉터리·종료 상태·판정 출력을 남깁니다

즉 영상이 지적한 순차 실행 한계는 설치본에서 해소된 상태입니다. 영상의 수정 프롬프트를 그대로 적용하기 전에 `references/parallel.md`와 `SKILL.md`를 먼저 읽는 편이 낫습니다.
