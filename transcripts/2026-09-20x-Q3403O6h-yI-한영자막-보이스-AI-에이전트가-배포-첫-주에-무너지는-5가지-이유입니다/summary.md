# 보이스 AI 에이전트가 배포 첫 주에 무너지는 5가지 이유입니다

## 한 줄 요약

월 10억 건 이상의 음성 통화를 처리하는 Plivo의 창업자 Venky Balasubramanian이 보이스 AI 에이전트를 실전 배포할 때 발생하는 5대 실패 요인(지연 시간 급증, STT 오류 연쇄 전파, 비정형 데이터 수집 실패, TTS 음성 합성 전 텍스트 미정규화, 부자연스러운 턴 감지 및 끼어들기)과 이에 대한 실전 엔지니어링 해법을 제시한다.

## 실패 요인 1: 지연 시간과 첫 음성 응답 시간(TTFA)

- **현실 지연 시간의 괴리**: 플랫폼 홍보 기준인 550ms 미만과 달리 실전 배포 시 750ms~1.2초가 소요되며, 1.2초를 초과하면 통화 이탈률 급증.
- **추론(Thinking) 모델의 역설**: 음성 에이전트는 지연 시간을 맞추기 위해 최신 LLM의 '생각/추론 기능'을 의무적으로 꺼야 함.
- **오픈소스 자체 호스팅 권장**: 상용 프론티어 모델의 P95 지연 시간 스파이크(1.2~1.3초)를 피하기 위해 Qwen 3.5(영어) 또는 Gemma 4(다국어 토큰 생산성 2.5~3배 우수) 기반 8B~12B 모델 자체 서빙이 가장 안정적인 균형점 제공.

## 실패 요인 2: 본질적으로 취약한 음성 전사(STT)와 연쇄 붕괴

- **실제 소음 통화의 오류율**: 정제된 벤치마크(4~6%)와 달리 소음, 억양, 도메인 용어로 인해 실전 오류율이 두 자릿수로 치솟음.
- **코드 스위칭(Code-Switching) 파괴력**: 힌디어-영어 혼용처럼 이종 언어가 뒤섞이면 STT 오작동이 메인 LLM 및 TTS 파이프라인 전체를 연쇄 붕괴시킴.
- **해결책**: 통화 전체가 아닌 발화 단계별로만 컨텍스트를 주입하는 '동적 키워드 부스팅(Dynamic Keyword Boosting)' 적용 및 경량 LLM 기반 '전사 텍스트 후처리(Post-processing)' 교정.

## 실패 요인 3: 데이터 수집을 텍스트가 아닌 '타입 지정 필드'로 취급

- **50~60% 실패의 주원인**: 대화 텍스트 전체를 통으로 모델에 맡기지 말고, Pydantic/Zod처럼 엄격한 타입 필드(전화번호 자릿수 검증, 상대 일자 계산용 Datetime 도구 호출)로 제약해야 정확도가 30%에서 95%로 상승.
- **필드 단위 유닛 테스트**: 전체 대화 E2E 테스트 대신 개별 필드 수집 단위의 세부 유닛 테스트 평가 체계 구축.

## 실패 요인 4: TTS 음성 합성 전 텍스트 정규화

- **LLM 출력 직접 전달 금지**: 이모지, 마크다운 특수문자 제거 필수.
- **자체 발음 사전 및 속도 조절**: 회사명(Plivo), 사용자 성명 등의 고유명사는 포네틱 발음 사전에 등록하고, 이메일/전화번호 발화 시 재생 속도를 0.7x~0.8x로 감속.

## 실패 요인 5: 턴 감지(Turn Detection)와 끼어들기(Barge-in) 제어

- **자연스러운 대화 흐름**: 사용자의 일시적 침묵과 발화 종료를 구분하고, 에이전트 발화 중 사용자 끼어들기 발생 시 지연 없이 즉시 음성 출력을 중단하는 인터럽트 제어 필수.
