# 지금 바로 써야 할 놀라운 Jev 활용 사례

### 한 줄 요약

Jev는 글을 쓰지 않고 선택지 중 하나를 골라 신뢰도와 함께 내놓는 빠르고 저렴한 결정 모델이며, 코딩 에이전트에 결정 담당으로 붙이면 컴팩션, 문서 검사, 스킬 선택, 파일 검색, 코드 리뷰, 브라우저 테스트, 규칙 강제의 일곱 곳에서 속도와 비용이 좋아지고 에이전트의 고질적 문제도 줄어듭니다.

### Jev는 결정 모델이다

- Typesafe가 만든 모델로, Claude나 GPT처럼 텍스트로 답을 쓰지 않고 주어진 선택지(예/아니오, 목록, 점수) 중에서 고릅니다. 선택과 함께 얼마나 확신했는지 나타내는 신뢰도 값도 줍니다
- 토큰을 하나씩 쓰지 않고 모든 질문에 동시에 답해서 결정 하나에 1초도 안 걸립니다
- 보낸 입력에 대해서만 비용을 내고 돌아오는 답은 무료여서 저렴합니다
- 코드를 쓰거나 도구를 쓰는 데는 못 쓰고, Claude Code나 Codex 안에서 결정 역할로만 씁니다
- Typesafe 자체 플랫폼은 수요 때문에 신규 가입이 중단되어 있고, OpenRouter와 Vercel AI Gateway에서도 쓸 수 있습니다. 발표자는 Vercel AI Gateway를 썼습니다

### 설정: AI Gateway 키를 환경 변수로

- Vercel 대시보드의 AI Gateway 안 API 키 페이지에서 키를 만듭니다. 키는 한 번만 보여주므로 바로 복사합니다
- 터미널에서 export 명령으로 환경 변수에 저장하고, 같은 터미널에서 Claude를 열면 키를 찾아 씁니다

### 1. 컴팩션을 1초 안에

- 기존 컴팩션은 대화 전체를 모델에 보내 요약시켜서 오래 걸립니다. Jev가 대화에서 중요한 것을 골라내게 하면 훨씬 빠릅니다
- fast Jev compaction 플러그인이 컴팩션 요약을 Jev의 결정으로 바꿉니다. 이 저장소는 Typesafe 플랫폼용이라 Vercel AI Gateway를 쓰려면 프로젝트에 복사해 Claude Code로 수정해야 하고, 설정도 업데이트해 인식시켜야 합니다
- 훅이 평소 compact 지침을 가로채며, 세션이 25% 미만이면 Jev 대신 일반 컴팩션을 합니다

### 2. 문서 검사기: 테스트 없는 규칙 찾기

- 기능을 만든 기본 모델에게 판단을 맡길 수 없으므로, 접근 권한을 제어하는 파일을 수정할 때마다 훅이 Jev에게 문서의 각 규칙에 테스트가 있는지 묻습니다
- 테스트가 빠진 규칙을 보고서로 보여주고, 그 보고서로 Claude에게 테스트를 쓰게 합니다

### 3. 스킬 선택기

- 스킬이 많으면 모델이 컨텍스트에 올라온 이름과 설명을 전부 고려해 골라야 합니다
- 훅이 모든 스킬의 이름과 설명, 그리고 프롬프트를 읽고 맞는 스킬 하나(또는 없음)를 골라 Claude에게 알려 주어 선택이 빨라집니다

### 4. 파일 검색

- 최근 Explore 에이전트가 Haiku 대신 메인 세션과 같은 모델을 쓰도록 바뀌어, Opus라면 검색이 더 느리고 비싸졌습니다
- 발표자는 에이전트 대신 스크립트를 함께 담을 수 있는 스킬로 만들었습니다. 키워드 검색으로 후보 파일을 찾고, Jev가 20개씩 질문과의 관련도 점수를 매겨 상위 몇 개만 Claude가 엽니다. 35개 파일의 순위를 1.6초에 매겼고 정답 파일이 1위였습니다

### 5. 코드 리뷰 전 사전 점검

- Jev는 리뷰어를 대체하지 않고 리뷰 전에 변경을 읽어 예/아니오 질문 일곱 개에 답합니다. 규칙상 허용되는 변경인지, 애초에 바꿔야 하는 것인지 등입니다
- 모두 아니오면 리뷰어는 빠른 한 차례만 하고, 하나라도 예이거나 Jev가 확신하지 못하면 전체 리뷰를 합니다. 위험한 변경은 제대로 검사받고 작은 변경은 빨리 끝납니다

### 6. 브라우저 테스트에서 클릭 결정 맡기기

- 앱이 작동하는지에 대한 최종 판단은 메인 모델이 하고, 다음에 어디를 클릭할지는 Jev가 정합니다
- 스킬이 페이지의 모든 버튼과 링크 목록을 만들면 Jev가 목표에 가까워지는 것 하나를 고르고, 목표 달성이나 페이지 차단으로 판단할 때까지 반복합니다
- 관리자, 매니저, 직원으로 로그인해 각자 허용된 페이지에만 접근하는지 확인했고, Claude가 결과를 문서의 규칙과 비교했습니다

### 7. 규칙 강제: 훅이 Jev로 편집을 차단

- claude.md의 규칙은 지침일 뿐이라 모델이 매번 따르지는 않지만, 훅은 매번 실행되어 건너뛸 수 없습니다
- Claude가 파일을 수정하려 할 때 훅이 변경 내용과 해당 파일의 규칙을 Jev에게 보내 각 규칙 위반 여부를 묻습니다. 80% 이상 확신하면 수정을 차단하고 어떤 규칙을 어겼는지 Claude에게 알려 고치게 합니다
- 테스트에서 직원 데이터를 브라우저에서 바로 읽는 파일을 만들게 하자 규칙 위반으로 파일이 만들어지기 전에 차단되었습니다
