# 에이전트의 성능은 모델만으로 결정되지 않는다. 도구와 맥락, 검증 규칙, 메모리, 전문 지식을 하네스에 구성하고 작은 검증된 작업을 쌓아 자율성을 넓혀야 한다.

## 하네스는 모델 주변의 실행 환경

LLM은 추론을 담당하지만 실제 날씨 조회, 코드 수정, 테스트 실행은 하네스가 도구와 환경을 통해 수행한다. 모델이 좋아져도 사용자가 원하는 기준을 저절로 알지는 못하므로 문서, 규칙, 도구, 테스트로 좋은 결과의 정의를 제공해야 한다.

## 작은 루프부터 자율성을 키우기

작은 PR과 검증 가능한 변경을 반복해 신뢰를 쌓으면 더 긴 작업과 큰 변경을 맡길 수 있다. 선형 하네스는 정해진 순서로 검사하고 끝나며, 폐루프 하네스는 테스트 실패 이유를 받아 수정과 테스트를 반복한다. 위험 명령을 막는 정책 같은 가드레일도 함께 필요하다.

## 모델·하네스·지식의 결합

영상은 고빈도 반복에 빠른 모델, 복잡한 일에 병렬 하위 에이전트를 조정하는 하네스, 작업 중 불러오는 도메인 스킬을 제안한다. 실용적 목표는 모델 자체를 계속 교체하는 데 그치지 않고, 에이전트가 맥락을 찾고 결과를 검증할 수 있도록 주변 환경을 개선하는 것이다.
