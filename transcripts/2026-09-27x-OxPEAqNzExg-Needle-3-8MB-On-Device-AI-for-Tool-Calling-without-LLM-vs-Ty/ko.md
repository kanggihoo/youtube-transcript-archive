# 한국어 번역

Needle 3은 “현관 조명을 끄고 오븐을 400도로 설정해” 같은 문장을 두 개의 함수 호출로 바꾸는 모델입니다. 인터넷 없이 휴대전화, 시계, 작은 보드에서 작동합니다. 전체 버전은 29MB이고 가장 작은 사용 가능 버전은 약 8MB입니다. TypeSafe AI가 같은 주제를 다루는 더 큰 Jev를 출시한 주에 공개됐습니다. 두 모델은 문제를 정반대 방향에서 접근합니다.

두 모델은 많은 소프트웨어 판단에 긴 문장 대신 함수 선택과 인자 값 같은 선택이 필요하다는 생각을 공유합니다. 일반 LLM은 답을 토큰 단위로 생성하고 JSON을 파싱·검증해야 하며 가짜 필드가 생기면 다시 요청할 수 있습니다. Needle과 Jev는 구조화된 출력만 내도록 해 프로그램이 바로 실행할 수 있게 합니다.

## 모델 크기와 구조

Cactus Compute는 샌프란시스코의 Y Combinator 스타트업입니다. Needle 3은 9월 17일에 나왔고 올해 세 번째 버전입니다. 5월의 Needle은 Gemini의 도구 호출 결과에서 증류한 2,600만 매개변수 모델이었고, 8월 Needle 2는 총 4,500만 매개변수였습니다. Needle 2는 14MB에 들어가고 약 28MB RAM으로 세션 전체를 실행할 수 있습니다. Needle 3은 1억 2,100만 매개변수지만 가중치를 매개변수당 약 2비트로 압축해 파일 크기는 29MB입니다.

“지능 사다리” 설계는 20개 층 중 2~4개 층도 별도 모델처럼 사용할 수 있게 합니다. 파일을 내려받아 시계에는 4층 버전을, 노트북에는 20층 버전을 둘 수 있습니다. 전체 버전은 4층을 사용하면 2,900만 매개변수이고 층을 추가할 때마다 약 103MB가 늘어납니다. 학습 과정의 80%는 전체 모델을 학습하고, 나머지 20%에는 무작위 깊이를 골라 작은 모델이 전체 모델의 예측을 따라하도록 합니다. 저자 시험에서 사다리 방식의 전체 모델은 그렇지 않은 모델보다 검증 손실이 3.9 낮았습니다.

아키텍처는 일반 트랜스포머의 매개변수 대부분을 차지하는 피드포워드 층을 제거하고 Hadamard MLP로 대체한 단순 어텐션 네트워크라고 설명합니다. 층당 약 470만 개 대신 2만 5,600개 매개변수를 사용합니다. 지식 대부분은 짧은 2~3단어 조각을 해시해 찾는 n-gram 테이블에 담깁니다. 총 1억 2,100만 개 중 7,080만 개가 이 테이블에 있고, 전체 모델의 계산량은 5,000만 매개변수 모델과 비슷하다고 합니다. 작은 보드에서 디코딩 속도는 초당 약 400~4,000토큰으로 보고됐습니다.

## 문법으로 구조를 보장하고 확률로 호출을 제어

Needle은 함수 스키마를 바이트 수준 문법으로 컴파일해 토큰이 문법에 맞게 생성되도록 합니다. 따라서 JSON은 항상 파싱되지만 답이 반드시 정확하다는 뜻은 아닙니다. 도구로 처리할 수 없는 금값 조회를 물으면 가장하지 않고 빈 목록을 줄 수 있습니다. 별도로 보정된 헤드가 신뢰도 점수를 반환하며 엔진의 기본 하한은 0.5입니다. 그보다 낮은 호출은 `suppressed calls` 필드로 옮기고 주 호출 목록은 비워 둡니다. 문서에서는 신뢰도 0.7 이상이면 실행, 중간이면 사용자 확인, 호출이 없으면 처리 불가 안내를 하는 세 갈래 분기를 예로 듭니다.

`pip install Cactus-Needle` 후 추론 엔진을 Hugging Face에서 한 번 내려받아 캐시합니다. `@needle.tool` 데코레이터와 타입 힌트, 독스트링으로 함수를 선언하고 도구를 Needle 인스턴스에 전달해 `agent.run`을 호출하면 도구와 인자를 선택하고 코드를 실행해 결과를 반환합니다. 실행 없이 원시 JSON을 원하면 `agent.complete`를 쓸 수 있습니다. 여기에는 함수명, 인자, 짧은 추론 문구, 신뢰도, 최대 메모리 사용량 등이 들어갑니다.

정보 추출도 같은 방식으로 할 수 있습니다. 원하는 필드의 모델을 정의하면 이메일에서 운송장 번호와 배송일 같은 타입 객체를 뽑습니다. 채워진 필드는 입력 텍스트의 구간을 복사하므로 근거가 명확하지만, 글에 없는 값은 만들어낼 수 없습니다. 정보가 흩어진 대화보다 청구서·영수증처럼 명확한 문서에 더 적합합니다.

정확도에는 도구 설계가 중요합니다. 하나의 큰 범주 도구 대신 동작별 도구를 만들고, 사용자 표현에 맞는 옵션 이름을 쓰며, 요청에서 누락될 수 있는 필수 인자에는 기본값을 지정합니다. 필수 값이 문장에 없고 기본값도 없으면 Needle은 추측하지 않고 호출을 보류합니다. 정규식 트리거로 특정 도구 호출을 강제할 수도 있습니다. 도구가 늘수록 잘못 선택할 가능성도 커지므로 도구 수를 작게 유지하라고 권합니다.

## 벤치마크와 미세 조정

홍보 문구는 Needle 3이 모바일 도구 호출에서 크기가 10배인 모델을 앞서고, 미세 조정된 4층 모델이 DeepSeek V4 Flash를 통과한다고 주장합니다. 지능 사다리 게시물의 기본 점수는 4층 모델이 Mobile Action 11.7, Drive Calls 21, 20층 모델은 각각 86, 47입니다. 미세 조정은 DroidCall 점수를 모든 깊이에서 18~36점 높였습니다. 2층 모델도 거의 쓰기 힘든 상태에서 56.5까지 올랐습니다.

하지만 DroidCall은 200개 행뿐입니다. 한 개발자는 자체 시험에서 32.2%를 얻었습니다. Cactus 관계자는 Needle은 작업 특화 모델이므로 프로덕션 전에 미세 조정을 예상해야 한다고 답했습니다. 기본 모델은 시작점이지 완성된 비서는 아닙니다. JSONL 각 줄에 질의, 도구, 기대 답을 넣고 `needle fine-tune`으로 10 epoch 학습합니다. 고정된 기반 위에 LoRA 어댑터를 학습합니다. 자료가 없으면 OpenRouter를 통해 예시를 만드는 명령도 있으며 기본 모델은 DeepSeek V4 Flash입니다. 어댑터를 병합해 선택한 깊이·플랫폼용 `.kct` 파일을 내보냅니다. macOS, Windows, Linux, Android, iOS, watchOS, WebAssembly 브라우저용으로 1MB 미만의 엔진을 제공합니다.

플레이그라운드는 대화 상태를 유지하므로 후속 요청은 같은 세션에서 이어집니다. 온도 조절 요청 뒤 전혀 다른 질문을 연달아 보내면 앞 대화가 다음 호출에 영향을 줄 수 있으므로 독립 작업 사이에는 상태를 초기화해야 합니다. 같은 모델이 텍스트 임베딩도 반환하므로 로컬 의미 검색이나 수백 개 도구 중 가장 가까운 도구 선택에 쓸 수 있습니다.

## Jev와 비교

TypeSafe AI가 9월 15일 얼리 액세스로 공개한 Jev는 Daniel Kahneman의 빠른 직관적 사고인 시스템 1에서 이름을 따왔다고 영상은 설명합니다. Jev는 출력을 왼쪽에서 오른쪽으로 생성하지 않고 한 번의 병렬 단계에서 구조화된 답 전체를 만듭니다. TypeSafe는 응답 시간 70~500ms를 보고했습니다. Doom 데모에서는 초당 약 10회 게임 상태를 텍스트로 읽으며 시간당 약 7달러가 들었다고 합니다. 입력 100만 토큰당 4.2센트, 출력 요금은 없다고 소개합니다.

“환각할 수 없다”는 주장에 대해 영상은 구조가 잘못된 출력을 만들 수 없다는 뜻에 가깝고 잘못된 선택지를 고를 수는 있다고 설명합니다. 한 엔지니어는 일반 모델에 선택지를 미리 채우고 출력 토큰을 하나로 제한해도 비슷한 결과를 낼 수 있다고 지적했습니다.

두 모델은 다른 문제를 풉니다. Jev는 더 크고 클라우드 기반이라 데모에서 수천 개 링크 중 하나를 고르는 등 어려운 결정과 대규모 선택지를 다룹니다. Needle은 문법을 적용한 토큰 단위 디코딩을 하지만 작고 오픈소스(Apache 2.0)이며 호출 비용이 없고 데이터가 기기 밖으로 나가지 않습니다. Jev는 여러 선택지의 확률을 주고 Needle은 도구 호출 신뢰도 점수를 줍니다. 시계에서 음악을 멈추는 등 단순 작업은 Needle이 처리하고 더 복잡한 라우팅 판단은 Jev로 보내 두 모델을 함께 쓸 수도 있습니다.

프론티어 API를 대량 호출해 단순 문장을 함수 호출로 바꾸고 있다면 Needle은 비용을 줄일 후보입니다. 좁은 도구 집합을 정하고 환경과 미세 조정을 준비한 뒤 신뢰도 기반으로 동작하도록 구성하는 것이 제안입니다.
