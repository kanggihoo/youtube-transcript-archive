# 컴파운드 엔지니어링의 시대입니다

## 한 줄 요약

구현은 거의 해결됐고 남은 병목은 판단과 취향이다. 그러니 반복되는 사고를 시스템에 축적해서, 다음 기능이 더 쉬워지게 만들어야 한다.

## 병목의 이동

발표의 뼈대는 2년간 병목이 계속 위로 옮겨갔다는 관찰입니다.

**코드 → 계획 → 무엇을 만들지 → 판단과 취향**

코드 품질이 나빠 막히던 시기가 지나자 계획이 병목이 됐고, 계획도 좋아지자 "무엇을 만들지"가 남았습니다. 결론은 구현 비용은 계속 싸지지만 판단은 그렇지 않다는 것입니다.

발표자는 전 엔지니어링 VP로 팀을 꾸릴 줄 알지만, 일부러 반대로 해봤다고 합니다 — 팀을 키워야 할 때까지 AI로 얼마나 갈 수 있나를 보려고요. 올해 코드를 한 줄도 직접 쓰지 않았고 대부분 읽지도 않았다고 말하며 시작합니다.

## 사람-AI 샌드위치

루프는 **브레인스토밍 → 계획 → 작업 → 리뷰 → 다듬기 → 축적 → 반복**이고, 요점은 양 끝에만 뇌를 켜는 것입니다.

- **시작**: 무엇이 문제이고 무엇을 만들지 결정. 이 사고를 AI에 떠넘기지 말 것
- **중간**: AI가 몇 시간이고 알아서 돌게 둠. 지루해야 하고, 당신이 필요 없어야 함
- **끝**: "이 정도면 됐다"가 아니라 기준을 올림. QA가 아니라 수준을 높이는 단계

중간을 믿고 놓아주려면 그 시스템에 시간을 써야 합니다. 여기서 **50% 규칙**이 나옵니다 — 절반은 기능을 만드는 데, 나머지 절반은 시스템이 틀린 것을 가르치는 데 씁니다. 어렵고 어색하다는 것도 인정합니다. "잘 돌아갔으니 넘어가자"가 자연스럽지만 그걸 참는 게 핵심이라고요.

## 반직관적인 주장 두 가지

**토큰이 오히려 절약된다.** 축적한 해결책을 저장소에 쌓으면 컨텍스트가 커지지만, 정답이 이미 컨텍스트 안에 있으면 리뷰도 수정도 리서치도 필요 없어서 장기적으로 더 효율적입니다.

**코드가 아니라 사고를 문서화하라.** "코드가 곧 산출물"이라는 통념에 반대합니다. 왜 그렇게 했는지의 근거가 있어야 일반화가 되고, 사후 분석 때 어떤 판단이 이걸 낳았는지 추적해 다음 행동을 바꿀 수 있습니다.

## 플러그인 없이 하려면

1. **추출하고, 반복하지 말 것** — 같은 말을 반복하고 있으면 시스템에 넣기
2. **중간이 지루해야 함** — 아직 당신이 필요하다면 수동으로 해보며 어디가 어긋나는지 느껴볼 것
3. **판단 기준** — 3시간 돌려도 늘 결과가 좋다면 도달한 것

마지막 문장이 발표의 요약입니다: **다음 기능이 더 쉬워져야 한다.** 보통의 엔지니어링은 복잡도가 쌓여 다음 기능이 더 어려워지는데, 그걸 뒤집자는 겁니다.

## 발표에서 시연한 스킬

전부 [refs/compound-engineering-plugin](../../refs/compound-engineering-plugin/)에 있습니다.

| 발표에서 부른 이름 | 스킬 | 하는 일 |
|---|---|---|
| C ideate | `ce-ideate` | 열린 이슈를 훑어 무엇을 할지 논거와 함께 구조화 |
| C doc review | `ce-doc-review` | 문서에 날카로운 질문을 되돌려줌 |
| C brainstorm | `ce-brainstorm` | 아이디어가 커서 설명하기 어려울 때 |
| C polish | `ce-polish` | 기준을 올리는 단계 |
| C compound | `ce-compound` | 지적한 내용을 지식으로 추출 |
| CE strategy | `ce-strategy` | 전략 문서 생성 |
| slash LFG | `lfg` | 자동화 루프 전체 |

발표의 루프가 그대로 스킬로 나뉘어 있습니다.

- **브레인스토밍** `ce-ideate` → `ce-brainstorm` → `ce-strategy`
- **계획** `ce-plan`, `ce-doc-review`
- **작업** `ce-work`, `ce-debug`, `ce-worktree`, `ce-prototype`
- **리뷰** `ce-code-review`, `ce-simplify-code`, `ce-dogfood`, `ce-test-browser`
- **다듬기/출하** `ce-polish`, `ce-commit-push-pr`, `ce-babysit-pr`, `ce-resolve-pr-feedback`
- **축적** `ce-compound`, `ce-compound-refresh`

`lfg`가 이 전부를 무인으로 이어 돌립니다. 발표에 안 나온 것 중에는 `ce-retune`(모델이 바뀌면 스킬 뭉치를 다시 튜닝), `ce-skill-work`(스킬 자체를 만들고 고침), `ce-pov`(외부 도입 질문에 등급 매긴 판정) 등이 있습니다.
