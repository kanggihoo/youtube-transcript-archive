# 코드 슬롭(Code Slop)과의 싸움: 소프트웨어 팩토리의 현실을 짚어봅니다 - Dex Horthy

## 한 줄 요약

HumanLayer의 Dex Horthy는 감독 없는 모델은 시간이 갈수록 코드베이스 품질을 올리지 못하고 슬롭만 쌓으므로 무인 소프트웨어 팩토리는 아직 이르며, 당분간은 사람이 코드를 읽되 계획, 시각적 정렬, 테스트, 피드백 루프로 리뷰 부담을 줄여야 한다고 주장합니다.

## 소프트웨어 팩토리는 새 개념이 아니다

- 소프트웨어 팩토리는 1968년부터 있던 개념이며, 2022년 표준 구조는 트래커, 구현, 테스트, PR, CI 검사, 리뷰, 배포, 사용자 피드백, 모니터링의 순환입니다
- 에이전트 시대에는 구현 단계가 몇 분~몇 시간으로 줄지만 리뷰는 여전히 몇 시간~며칠이 걸려 병목으로 남습니다. 에이전틱 리뷰와 회귀 테스트가 사소한 문제를 잡아 줘도 마찬가지입니다
- 이 병목 때문에 리뷰를 아예 없애자는 '무인(lights-off) 팩토리' 발상이 나옵니다

## 무인 공장이 안 되는 이유

- 5월 보고서에 따르면 Opus 4.5 도입 이후 리뷰 품질은 떨어지고 리뷰를 건너뛰는 PR이 늘었으며 PR당 인시던트와 개발자당 버그가 늘었습니다. 발표자는 실력 문제가 아니라고 봅니다
- 핵심 주장은 감독 없는 모델이 코드베이스 품질을 개선하거나 유지하지 못한다는 것입니다. 개선을 시키려면 코드베이스를 이해해야 하므로 이미 감독 중입니다
- 나쁜 아키텍처의 비용은 몇 달, 몇 년 뒤에야 드러나 RL에 쓸 빠른 검증자(오라클)가 없고, 벤치마크는 좋은 구조보다 테스트 통과만 보상하게 되기 쉽습니다

## SlopCodeBench가 보여 주는 것

- 위스콘신 대학교 연구실의 벤치마크로, 문제를 한꺼번에 주지 않고 기능을 조금씩 추가하게 해 실제 개발 방식에 가깝습니다
- 공개 당시 최고 모델 GPT-5.5가 14.8%를 받았습니다. 터미널 벤치가 95%에 가까워 코딩이 해결됐다는 말이 나오는 것과 대조적입니다
- 발표자에 따르면 Anthropic도 사후 분석에서 쌓인 지저분한 코드가 보안 문제로 이어졌음을 인정했습니다. 후속 모델의 개선폭은 GPT-5.5보다 1.5퍼센트포인트 정도입니다
- 한때 코드를 읽으면 뒤처진다고 주장하던 Steve Yegge도 지난주 모델이 슬롭 코드를 쓰고 스스로 디버깅할 수 없을 만큼 복잡한 것을 만든다고 입장을 바꿨습니다

## 12-팩터 팩토리: 실천법

- **만들기 전에 계획하라.** 20~30분의 사전 계획이 리뷰 시간을 아낍니다. 다만 과하게 계획하지 말고, 바뀔 가능성과 바꾸는 고통을 곱한 '기대 고통'을 줄이는 데 집중합니다
- **시각적으로 정렬하라.** 산문의 벽 대신 한눈에 보이는 형태로 정보를 받습니다. 공개한 show me 스킬이 그 예입니다
- **에이전트가 스스로 테스트하게 하라.** 브라우저, 앱 실행, curl, 영상 녹화 같은 백프레셔를 줍니다
- **안티 슬롭 규칙을 쓰라.** TypeScript용으로 Dylan Mulroy가 에이전트의 안티패턴을 분류한 약 100개 규칙이 있고, Slop Code Bench 논문에서도 가져다 쓸 것이 있습니다
- **사용자 피드백을 팩토리에 넣어라.** 지원 티켓은 에이전트가 만든 PR과 함께 읽고, 장애 알림에는 에이전트가 고칠 수 있다고 보는 PR을 붙입니다. 절반만 머지해도 처리량 차이가 큽니다
- **모델이 실험하게 하라.** 기능 플래그로 UI 여러 버전을 사용자에게 내보내 UI에 대한 백프레셔를 얻습니다
- **루프는 순방향 압력과 백프레셔의 조합이다.** 일정, 자동화, 웹훅으로 새 작업을 시작시키고, 작업 중 피드백으로 사람 없이 결과를 향해 개선하게 합니다
- **시간이 지나며 복리로 쌓아라.** 팀의 세션을 분석해 어려워하는 부분을 스킬이나 메모리에 반영합니다

## 새로운 소프트웨어 포지와 4개 레이어

- 세션 트레이스, 계획, 프롬프트, 아키텍처 문서도 SDLC의 일급 요소이므로, 에이전트 대화를 슬랙에 복사해 오가는 대신 중앙의 기록 시스템이 필요하다고 봅니다
- 구성 레이어는 컴퓨트, 개발 환경, 하네스, 컨트롤 플레인이며 각각 사거나 만들 수 있습니다
- HumanLayer는 컨트롤 플레인에서 팀의 모든 세션을 보고, 팀원 세션에 들어가 함께 프롬프트를 쓰고, 노트북에서 도는 세션에도 사람을 부를 수 있는 공유 협업 워크스페이스입니다. 에이전트가 쓰는 diff는 클라우드로 스트리밍되어 PR 전에 리뷰할 수 있고, 커스텀 하네스는 몇 주 안에 오픈소스로 공개할 예정입니다
