# Vercel은 어떻게 AI 에이전트 개발 문제를 해결했을까요?

## 한 줄 요약

Vercel의 소프트웨어 총괄 Andrew Qu는 사내 데이터 사이언스 병목을 해결하는 과정에서 단일 메가 프롬프트와 체인형 구조의 한계를 겪은 뒤, Claude Code의 '파일 시스템 샌드박스' 접근법과 '반복 질의의 스킬(Skill) 자동화'를 통해 평가 점수를 2배로 끌어올렸으며, 이를 에이전트를 위한 Next.js 프레임워크인 'Eve'로 정립해 공개했다.

## 사내 데이터 팀의 병목과 에이전트 도입 배경

- **급증하는 질의와 생산성 저하**: 마케팅, 영업, 경영진의 일상적 데이터 추출 질의로 인해 소수 정예 데이터 팀이 본업을 중단하고 하루 종일 Snowflake 쿼리만 작성해야 하는 병목 현상 발생.
- **궁극적 지향점**: 빌 게이츠의 "모든 책상 위에 컴퓨터를"처럼, 전 직무("모든 책상 위에 에이전트를")의 자동화를 목표로 실전 데이터 에이전트(D0) 구축 착수.

## 데이터 에이전트(D0)의 4단계 진화 과정

1. **V1 (단일 메가 프롬프트)**: 스키마 덤프 전체를 프롬프트에 넣고 SQL을 생성하게 했으나 복잡한 조인과 맥락을 처리하지 못함.
2. **V2 (역할별 파이프라인 체인)**: 질문 분석 → 계획 → SQL 작성 → 결과 보고로 분할했으나, 각 단계가 이전 결과의 짤막한 요약만 전달받아 맥락 손실 및 경직성 발생.
3. **V3 (상태 관리 단일 루프)**: 단일 에이전트가 자체 상태와 메모리를 관리하며 오류 시 되돌아가 재시도하도록 설계했으나, 실전 배포 시 사용자들의 예상 밖 질문에 대량 실패.
4. **V4 (파일 시스템 기반 샌드박스 에이전트 - Claude Code의 교훈)**:
   - 전용 커스텀 툴을 덕지덕지 붙이는 대신, 모델이 가장 잘 훈련된 표준 리눅스 도구(`bash`, `read_file`, `write_file`, `grep`)와 파일 시스템 샌드박스를 제공.
   - 에이전트가 파일 시스템 상에서 시맨틱 레이어를 스스로 탐색하고 쿼리를 검증하게 만들자 사내 평가(Eval) 점수가 즉시 2배로 상승.

## 반복 쿼리의 '스킬(Skill)' 자동 정제

- **크론 기반 지식 추출**: 수천 건의 실제 사용자 질의 중 공통적인 패턴(특정 테이블 집계, 제품/결제 조회 등)을 백그라운드 크론 작업이 자동으로 감지하여 재사용 가능한 100여 개의 '스킬(Skill)' 문서로 정제.
- **콜드 스타트 방지**: 에이전트가 매번 백지에서 시작하지 않고 `skills/` 디렉터리의 정제된 도메인 지식을 즉각 참조하여 실행 효율 극대화 (`skills.sh` 생태계 구축).

## 에이전트를 위한 Next.js: 'Eve' 프레임워크

- **컨벤션 기반 파일 시스템 아키텍처**: Next.js가 웹 라우팅을 단순화했듯, `skills/`, `tools/`, `channels/` 폴더 구조만 선언하면 완전한 엔터프라이즈 에이전트를 자동 조립.
- **오픈소스 코어와 턴키 인프라**: Postgres, Docker, OpenAI 호환 어댑터를 지원하며, Vercel Workflows(내구성), Sandbox(보안 격리), Vercel Connect(OIDC 인증), 내장 관측성(Observability)을 원클릭 제공 (`eve.dev`).
- **도메인 특화 에이전트의 가치**: 범용 기성 에이전트는 기업 고유의 비즈니스 맥락을 알지 못하므로, Eve를 활용해 회사 내부 지식을 결합한 맞춤형 에이전트를 직접 구축하는 것이 핵심 경쟁력.
