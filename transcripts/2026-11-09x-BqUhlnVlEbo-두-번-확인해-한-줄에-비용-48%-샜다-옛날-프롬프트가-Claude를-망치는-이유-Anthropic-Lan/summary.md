# 옛날 프롬프트가 Claude를 망치는 이유

## 결론부터

Tech Bridge는 Anthropic의 Lance Martin 발표를 근거로, "두 번 확인해" 같은 구세대 모델용 프롬프트 주문이 최신 Claude에서는 비용만 올리고 성능을 깎으므로 오래된 지시를 지우고(audit), 캐시를 지키고, 올릴 수 있는 평가를 만들어 과적합 없이 개선하라고 정리한다. 모순된 규칙 두 줄이 고객센터 AI가 환불 4건을 처리하지 못하게 만든 사례로 시작한다.

## 핵심 내용

- **프롬프트 부채:** "답하기 전에 두 번 검증하라" 한 줄이 티켓당 비용을 48% 올렸는데 정확도는 그대로였고, 모순 규칙 한 쌍은 정확도를 9점 가까이 떨어뜨렸다고 한다. 최신 모델은 지시를 글자 그대로 따르기 때문이다. Claude Code의 `/claude-api prompt-audit`로 CLAUDE.md·스킬·프롬프트·도구 설명을 훑어 이런 패턴을 지울 수 있고, 오딧 한 번에 비용이 9% 더 줄고 정확도가 약 2%p 올랐다고 한다.
- **프롬프트 캐시:** 앞부분이 바이트 단위로 같아야 캐시가 맞아서 시스템 프롬프트에 타임스탬프를 넣으면 깨진다. 순서는 공통 지시·도구 → 프로젝트별 CLAUDE.md → 세션 상태 → 매 턴 메시지. 벤치마크에서 통과율 변화 없이 비용이 73%(Tau 2 Bench, 프롬프트 93% 캐시 가능), 약 72%(문서 QA) 줄었다.
- **힐 클라이밍:** 좋은 평가는 더 좋은 모델이 더 높은 점수, 더 생각하면 점수 상승, 최고 모델도 만점이 아님, 점수 변동이 작음을 만족해야 한다. 평가를 학습용·시험용으로 나눠 학습 실패만 보고 고치게 하며, 학습만 오르고 시험이 그대로면 과적합으로 보고 되돌린다. Claude API 스킬에 적용해 66%→87.9%(24라운드). 비용 목표로 돌리면 정확도 74.4%·4.6센트에서 시작해 모델·노력 수준을 바꿔 시험용 티켓에서 78.6%→90.5%, 비용 약 5분의 1이 되었다고 한다.
- **원칙과 앞으로:** 똑똑한 모델을 덜 애쓰게 하는 쪽이 덜 똑똑한 모델을 오래 고민시키는 것보다 싸고 낫다. 최대 설정이 아니라 낮은 effort부터 시작하라는 조언. 며칠짜리 에이전트를 위해 하네스와 샌드박스를 분리하고 세션 로그를 따로 남기며 API 키는 참조만 하게 한다.

## 배울 점과 적용 조건

- 모델을 올릴 때마다 CLAUDE.md와 프롬프트에 남은 "단계별로 생각해", "꼼꼼하게", 모순된 규칙을 정리한다. 가장 싸고 즉시 가능한 조치다.
- 캐시 효율은 프롬프트 앞쪽에 매번 바뀌는 값(시각, ID)이 없는지만 봐도 개선된다.
- 평가 개선 루프는 학습·시험 분할과 반복 실패 문제 점검이 핵심이며, 평가 데이터(트레이스, 정답)가 있어야 쓸 수 있다.

## 근거와 한계

- **영상의 근거:** Lance Martin의 AI Engineer 워크숍과 Anthropic 블로그 내용 인용, 실험 수치(고객센터 벤치마크, Tau 2 Bench, 문서 QA). 영상에서 직접 재현한 시연은 없다.
- **평가:** 수치는 Anthropic 자체 벤치마크이며 모델 버전·노력 수준·표본 수(시험용 티켓 14개)가 작아 비율이 크게 흔들릴 수 있다. "오래된 지시가 비용을 올린다"는 방향성은 설득력 있지만 일반 워크로드에서 같은 크기로 나온다는 근거는 아니다.
- **확인 범위:** 자막 기반이며 원문 블로그·명령어를 열어 보지 않았다. 슬래시 명령 이름과 모델명, 수치는 "영상 내 주장, 외부 미검증"이다. 자막에 음성 인식 오류가 있다(예: '엔트로피'는 Anthropic).
- **홍보성:** Anthropic 제품(Claude Code 명령, Managed Agents) 사용을 권하는 내용이 중심이나 협찬 고지는 없다.
