# 에이전트 프레임워크는 해롭다고 봅니다 — Rémi Louf

## 한 줄 요약

복잡한 프레임워크와 코드 그래프 대신, 마크다운 선언과 이벤트 기반 통신, 프롬프트 해시(컨텐트 어드레싱), 엄격한 타입 경계를 갖춘 가벼운 '커널' 런타임이 운영 가능한 에이전트 시스템의 해답이다.

## 과도기의 터미널과 '로봇 잔디깎이'의 꿈

현재의 코딩 에이전트나 모바일 앱은 스스로 동작하더라도 사람이 계속 붙어서 조종해야 하는 과도기적 단계에 불과합니다. 진정한 자율 백그라운드 에이전트(무인 로봇 잔디깎이처럼)를 구축하려면 복잡한 코드 프레임워크가 아닌 단순한 기본기로 돌아가야 합니다.

## 프레임워크 대신 작은 커널을 만드는 4가지 원칙

### 1. 코드 대신 마크다운(Markdown)과 이벤트(Event)
- 에이전트의 역할과 지시는 마크다운으로 정의해 버저닝 및 PR 리뷰가 가능하게 함
- Cron(언제) 대신 **이벤트(왜)** 기반으로 에이전트를 연결: 복잡한 그래프 엣지를 코드로 짤 필요 없이, 에이전트가 `accepts` / `returns` 이벤트를 발행/구독(pub/sub)하면 시스템 토폴로지가 저절로 형성됨

### 2. 단일 불변 이벤트 로그(Append-Only Log)
- 유실 방지와 인과관계(Causal link) 추적을 위해 모든 이벤트를 단일 불변 로그 테이블에 기록
- 어떤 이벤트가 어떤 에이전트 동작을 트리거했는지 역추적 가능

### 3. 프롬프트 컨텐트 어드레싱 (Content-Addressed Prompts)
- 시스템 프롬프트, 스킬, 도구, 사용자 입력을 문자열이 아닌 **해시 식별자의 리스트(Git/Nix 방식)**로 관리
- **정확한 역추적 & Diff**: 모델 응답 시점에 실제로 컨텍스트에 들어갔던 프롬프트 조각들을 완벽히 복원하고 변경점 비교
- **결정론적 재생(Replay)과 모델 전환**: 동일한 과거 요청 그래프를 다른 오픈소스/로컬 모델로 재전송해 비용 최적화 및 평가(Eval) 수행

### 4. 엄격한 타입 경계 (Typed Boundaries)
- 에이전트와 외부 세계 사이의 오작동을 차단하기 위해 **타입이 정의된 도구 호출(Typed Tool Calls)**과 **타입이 정의된 이벤트(Typed Structured Outputs)**를 강제하여 비정상 데이터 유입을 차단

## 배운 점: 사기 전에 먼저 만들어라

에이전트 오케스트레이션에서 마주치는 난관들은 결국 전통적인 분산 소프트웨어 엔지니어링 문제들(로그, 큐, 재시도, 직렬화)입니다. 시중의 복잡한 프레임워크를 무작정 도입하기 전에, 직접 최소한의 런타임을 만들어 봄으로써 실제 필요한 핵심 제약 조건을 체득해야 합니다.
