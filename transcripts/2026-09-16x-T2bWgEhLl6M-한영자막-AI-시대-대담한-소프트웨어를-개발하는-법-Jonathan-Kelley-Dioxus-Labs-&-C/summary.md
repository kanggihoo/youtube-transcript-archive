# AI 시대, 대담한 소프트웨어를 개발하는 법 — Jonathan Kelley (Dioxus Labs & Cognition)

## 한 줄 요약

AI 코딩 에이전트의 등장으로 코드 작성 자체는 값싸졌지만, 튼튼한 기반 아키텍처 설계와 대여 검사기(Borrow Checker)의 엄격한 제약을 갖춘 Rust가 에이전트의 조잡한 코드 양산을 막아주는 최고의 무기가 되었다.

## Rust의 가파른 러닝커브가 에이전트 시대의 강점이 된 이유

- **개발 부담의 역전**: 과거 인간 개발자에게 진입 장벽이었던 Rust의 엄격한 타입 시스템, 메모리 안전성, 대여 검사기(Borrow Checker) 규칙을 이제는 코딩 에이전트가 대신 처리합니다.
- **슬롭(Slop) 방어선**: 에이전트에게 무작정 구현을 맡기면 '슬롭 대포(Slop cannon)'처럼 조잡한 코드를 쏟아냅니다. Rust의 엄격한 컴파일러 검증은 에이전트가 엉성한 코드를 통과시키지 못하도록 강제하는 자연스러운 안전망 역할을 합니다.
- **기반(Substrate)의 중요성**: 에이전트가 코드를 얹는 프로젝트 기반이 부실하면 그 위에 올라가는 결과물도 망가집니다. 안정적인 기반이 다져져 있어야 에이전트의 개발 속도가 배가됩니다.

## 코딩 에이전트가 탁월한 두 가지 영역

- **방대한 지식과 인내심이 필요한 난제 탐색**: 
  - 수천 페이지의 공식 문서 리서치, 비표준 맞춤 API 분석, 바이너리 분석, API 리버스 엔지니어링 등 인간 개발자가 지치기 쉬운 작업에 탁월합니다.
  - 과거 인간 손으로 수년이 걸렸던 Kotlin/Swift 네이티브 플러그인 빌드 시스템 연동을 에이전트를 활용해 2~3주 만에 구현했습니다.
  - 경량 렌더러 Blitz 개발 시 Chromium/WebKit의 CSS 레이아웃 명세 및 렌더링 동작을 에이전트가 즉각 찾아내어 올바른 방식으로 구현할 수 있었습니다.
- **지루하고 반복적인 유지보수 작업**:
  - 패치 릴리스 체크리스트 검증, 안정화 브랜치 버그 수정 백포팅, 주석 및 문서 예제의 정확성 동기화 등 사람이 놓치기 쉬운 지루한 작업을 자동화하여 주간/다중 릴리스 주기를 유지하게 해줍니다.

## AI 기반 테스트의 한계와 퍼징(Fuzzing) 하네스

- **피상적인 단위 테스트의 한계**: 에이전트에게 단순히 테스트 작성을 맡기면 단순 생성자 호출처럼 실효성 없는 엉성한 테스트를 만들기 쉽습니다. 복잡한 시스템의 핵심 테스트 케이스와 엣지 조건 정의는 여전히 인간의 설계가 필요합니다.
- **퍼징 하네스 구축의 승리**: 수백만 개의 비정상적인 입력이나 악의적인 입력을 시스템에 쏟아붓는 퍼징(Fuzzing) 테스트 하네스를 구축하는 데는 에이전트가 매우 강력한 역량을 발휘합니다.

## 코드를 쓰는 시대에서 읽고 설계하는 시대로

- **아키텍처는 여전히 엔지니어의 예술**: 에이전트는 기존 구조가 맞지 않아도 자발적으로 대규모 리팩터링을 설계하지 않고 억지로 코드를 밀어 넣습니다. 따라서 엔지니어링 시간의 대부분은 코드 작성이 아니라 시스템의 미래 진화를 고려한 소프트웨어 아키텍처 구상에 쓰여야 합니다.
- **철저한 라인 단위 코드 리뷰**: 프롬프트 엔지니어링과 AI 리뷰를 거치더라도, 프로덕션에 나가는 모든 PR은 의도와 아키텍처 부합 여부를 인간의 눈으로 직접 검토해야 합니다. 코드는 저렴해졌지만 품질 기준은 그 어느 때보다 높아졌습니다.
