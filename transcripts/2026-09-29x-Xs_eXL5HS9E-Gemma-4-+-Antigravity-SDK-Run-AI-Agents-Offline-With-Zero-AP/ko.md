### 도입

**0:00** · 구글이 안티그래비티(Antigravity) SDK에 로컬 모델 지원을 추가했는데, 그 뒤에서 돌아가는 모델은 Gemini가 아니라 Gemma 4입니다. 계획을 세우고, 파일을 쓰고, 테스트를 돌리고, 스스로 실수를 고치는 에이전트를 인터넷 연결도 API 요금도 없이 쓸 수 있다는 뜻입니다.

**0:16** · 대부분의 보도는 안티그래비티에 초점을 맞추지만, 저는 이 모든 것이 가능한 이유인 Gemma 4가 더 중요한 이야기라고 생각합니다. 그리고 구글 자체 데모에는 처음 보면 훌륭해 보이지만, 무엇을 세는 숫자인지 확인하고 나면 다르게 읽히는 수치가 하나 있습니다. 이건 영상 후반부에서 다루겠습니다. Gemma 4는 2026년 4월 초에 나왔고, 가장 먼저 바뀐 것은 라이선스입니다. 이제 Apache 2.0입니다. 이전 Gemma 버전은 구글 자체 약관을 썼는데, 많은 기업의 법무팀이 그걸 달가워하지 않았습니다.

### Apache 2.0 라이선스

**0:47** · Apache 2.0은 그런 마찰 대부분을 없애 주기 때문에, 기업이 긴 검토 없이도 이 모델 위에 무언가를 만들 수 있습니다. 업무용 사용을 생각하는 분들께는 어떤 벤치마크 차트보다 이것이 더 중요합니다. E2B와 E4B는 휴대폰과 소형 기기용으로 만든 작은 모델입니다. E는 유효 파라미터(effective parameters)를 뜻하며 각각 약 23억 개와 45억 개이고, 둘 다 오디오 입력도 받습니다.

### 모델 크기와 메모리

**1:10** · 그다음은 가장 강력한 310억 파라미터 밀집(dense) 모델이 있습니다. A4B라는 이름이 붙은 260억 파라미터 전문가 혼합(MoE) 모델도 있는데, 안티그래비티가 쓰는 것이 바로 이 모델입니다. 6월에는 중급 사양 기기에서 텍스트, 이미지, 오디오를 다루는 120억 파라미터 모델이 추가되었습니다. 큰 모델은 최대 256K 토큰의 컨텍스트를, 작은 모델은 128K를 처리합니다.

**1:36** · 260억 모델은 토큰마다 약 38억 개의 파라미터만 활성화됩니다. 그래서 작은 모델의 속도로 돌아가면서도 품질은 310억 모델에 가깝게 나옵니다. 출시 당시 구글은 310억 모델이 Arena 텍스트 리더보드의 오픈 모델 중 3위, 260억 모델이 6위라고 밝혔습니다. 하지만 활성 파라미터는 연산량을 아껴 줄 뿐 메모리를 아껴 주지는 않습니다. 260억 개 전부를 올려야 합니다. 그래서 구글은 24GB를 넘는 VRAM 또는 통합 메모리를 권장합니다. 여기서 문제는 속도가 아니라 메모리입니다.

**2:07** · 채택 현황도 좋은 신호입니다. 제가 찾은 한 가이드에 따르면 Gemma 계열은 8월 20일에 누적 다운로드 10억 회를 넘겼고, Hugging Face에는 커뮤니티 변형 모델이 10만 개가 넘습니다. 같은 가이드는 안드로이드 스튜디오가 9월 1일부터 Gemma 4를 완전 로컬 코딩 모델로 제공하기 시작했다고도 합니다. 두 번째 내용은 구글에서 직접 확인하지 못했으니 조심해서 받아들이세요. 다만 방향은 분명합니다.

**2:33** · 구글은 더 이상 Gemma를 부업 프로젝트로 다루지 않습니다. 런타임, SDK, IDE 지원까지 그 주변을 직접 만들고 있고, 안티그래비티는 그 한 조각입니다. 설치는 간단합니다. 가상 환경을 만든 다음 pip install google-antigravity litert-lm을 실행하면 됩니다.
