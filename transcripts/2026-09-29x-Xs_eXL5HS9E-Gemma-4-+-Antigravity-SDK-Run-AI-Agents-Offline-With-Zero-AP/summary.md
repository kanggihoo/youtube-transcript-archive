# Gemma 4 + Antigravity SDK: Run AI Agents Offline With Zero API Cost

### 한 줄 요약

구글이 Antigravity SDK에 Gemma 4 26B A4B 기반 로컬 모델 지원을 추가해 인터넷과 API 비용 없이 에이전트를 돌릴 수 있게 됐지만, 병목은 속도가 아닌 메모리이고 데모의 97.2% 수치는 토큰 비중일 뿐이라 최선의 경우로 봐야 합니다.

### Gemma 4가 핵심인 이유

- 2026년 4월 초 출시. 라이선스가 Apache 2.0으로 바뀌어 기업이 긴 법무 검토 없이 쓸 수 있습니다
- E2B·E4B는 휴대폰용 소형 모델, 31B 밀집 모델이 가장 강력하고, 26B 전문가 혼합(A4B)이 Antigravity가 쓰는 모델입니다. 6월에 12B 모델도 추가됐습니다
- 26B는 토큰당 약 38억 파라미터만 활성화되어 소형 모델 속도에 31B에 가까운 품질을 냅니다. 하지만 26B 전체를 메모리에 올려야 해서 24GB 넘는 VRAM 또는 통합 메모리가 권장됩니다
- 구글이 런타임, SDK, IDE 지원까지 만들고 있어 Gemma를 부업으로 보지 않는다는 신호입니다

### 설치와 첫 에이전트

- 가상 환경에서 `pip install google-antigravity litert-lm` 후 `litert-lm import`로 모델을 받으면 `model.litertlm` 파일이 홈 디렉터리 숨김 폴더에 생깁니다
- 예제 스크립트는 약 15줄이며, 모델 경로를 지정하고 chat을 호출해 토큰을 스트리밍합니다. `lightweight` 프리셋은 최신 SDK에서 자동 적용됩니다
- 두 번째 예제는 psutil과 rich로 터미널 대시보드를 만들고 requirements 작성과 자체 테스트까지 합니다

### 권한과 컨텍스트

- 에이전트는 기본적으로 읽기 전용이며, workspaces로 쓰기 폴더를 지정하고 allow all 정책으로 무확인 실행을 허용합니다
- 테스트 이상이라면 allow all 대신 deny, allow, ask user 규칙을 쓰는 편이 낫다고 말합니다
- 구글은 64k 컨텍스트를 권장합니다. 모델 파일은 약 195k를 지원하지만 길수록 메모리를 더 씁니다

### 다른 로컬 서버와 실제 속도

- local OpenAI agent config로 Ollama, LM Studio, vLLM, llama.cpp 같은 OpenAI 호환 서버에 연결할 수 있고, 에이전트 로직은 그대로입니다. LiteRT-LM 자체 serve 명령은 9379 포트를 씁니다
- 기기가 26B를 못 돌리면 Ollama에서 작은 E2B로 시작할 수 있습니다. Ollama에서는 기본 컨텍스트가 너무 작으니 직접 설정해야 합니다
- 커뮤니티 수치는 M3 Max(128GB)에서 초당 30~40토큰, M4 Pro(48GB)에서 20~30토큰, 8GB GTX 1080에서 전문가 가중치를 시스템 RAM에 두고 약 24토큰입니다. 백그라운드 에이전트에는 괜찮지만 지켜보기엔 느립니다

### 하이브리드 데모와 97.2%의 의미

- 클라우드 모델(Gemini 3.8 Flash)이 파일 이름과 작업 설명만 보고 설계하고, 로컬 Gemma 4 인스턴스 셋이 파일을 나눠 맡습니다. 버그를 테스트로 증명하고, 빌더 둘이 패치를 쓰고, 블라인드 비평가가 고른 뒤 재테스트하는 리뷰 루프가 로컬 GPU에서 돌아갑니다
- 97.2%는 클라우드 95토큰 대 로컬 3,322토큰의 비율입니다. 작업이나 판단의 비중이 아니고, 계획은 그 95토큰이 만들었습니다
- 소스 코드는 올라가지 않지만 파일 이름은 나가므로 완전한 프라이버시가 아닙니다. 규제 팀은 하이브리드 전에 검토가 필요합니다

### 한계

- 4월 해커 뉴스 댓글은 Gemma 4가 한 번에 끝내는 코딩에선 상위권이지만 도구를 쓰는 에이전트 작업에선 떨어진다고 했습니다. Antigravity 하니스는 다르게 튜닝됐을 수 있으나 독립적인 수치는 아직 없고 발표 3일차입니다
- 26B의 LiteRT-LM 빌드는 텍스트 전용이고, 이미지·오디오·멀티 토큰 예측(다른 런타임 기준 1.4~2.2배 빠름)은 이후 업데이트 예정입니다
- 새로운 기능이라기보다, 훅·정책·오케스트레이션을 갖춘 공식 SDK 지원이 달라진 점입니다. 폐쇄망용 네이티브 바이너리 자바 릴리스도 있습니다

### 누구에게 맞는가

- 엄격한 데이터 규정이 있는 팀, 사용량 제한에 자주 걸리는 사람, 인터넷이 나쁜 환경
- 작은 작업 하나로 시작하고, 권한을 빠듯하게 두고, 메모리를 지켜봅니다. 32GB 이상이면 26B, 그보다 적으면 Ollama의 E4B
- 지켜볼 것은 독립적인 도구 호출 테스트, LiteRT-LM의 멀티 토큰 예측, 구글이 피드백을 요청한 GitHub 이슈 트래커입니다
