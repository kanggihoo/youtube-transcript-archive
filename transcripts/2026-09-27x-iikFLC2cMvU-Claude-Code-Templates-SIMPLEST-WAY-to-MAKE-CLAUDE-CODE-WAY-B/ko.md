# 한국어 번역

Claude Code를 쓴다면 다른 사람들이 공유한 에이전트, 스킬, 사용자 명령과 설정을 본 적이 있을 겁니다. 유용한 것을 찾고, 무엇을 하는지 이해하고, 올바른 폴더에 넣는 일만으로도 별도 프로젝트가 되곤 합니다.

오늘은 aitmpl.com에서 둘러볼 수 있는 Claude Code Templates를 살펴봅니다. 이 프로젝트는 구성 요소를 검색 가능한 카탈로그로 모으고 자신의 설정에 추가하는 설치 명령을 제공합니다. 웹사이트를 둘러보고 작은 검토·테스트 환경을 만든 뒤 Claude Code 안에서 써 보겠습니다. 분석 대시보드와 대화 모니터도 소개합니다. 설치 전에 실제 지침을 열어볼 수 있어 프로젝트에 맞는지 확인하고 나중에 바꿀 수 있다는 점이 좋습니다.

Claude Code Templates는 커뮤니티 프로젝트로 웹사이트와 CLI 설치 프로그램을 제공합니다. Divilla7의 GitHub 저장소에서 관리하며 MIT 라이선스입니다. 포함된 일부 구성요소는 다른 프로젝트에서 가져와 각자 라이선스가 유지되므로 재배포할 때 출처를 확인해야 합니다. Claude Code 사용 비용과 한도는 그대로 적용됩니다. 유료 외부 서비스에 연결되는 요소는 별도 비용이 들 수 있습니다. 무료인 것은 템플릿 모음과 도구이며 무제한 모델 사용량이 포함된 것은 아닙니다.

## 카탈로그 구성 요소

웹사이트 사이드바에는 스킬, 에이전트, 명령, 설정, 훅, MCP가 있습니다. Mods, 플러그인, 인기 목록, 문서, GitHub 링크도 볼 수 있습니다.

에이전트는 코드 검토, 오류 조사, 프런트엔드 작업 같은 전문 역할을 맡고 자체 지침과 컨텍스트를 사용해 작업을 위임받습니다. 스킬은 특정 기능이나 워크플로에 대한 지침 패키지입니다. 관련 작업에서 불러올 수 있고 직접 호출도 가능합니다. 프런트엔드 디자인 스킬이라면 타이포그래피, 레이아웃, 시각 방향을 안내합니다. 명령은 슬래시로 실행하는 재사용 프롬프트입니다. 테스트 생성을 반복 요청한다면 전체 설명 대신 짧은 명령을 쓸 수 있습니다.

Claude Code에서는 스킬도 슬래시 호출이 가능하고 기존 명령 파일도 여전히 작동하므로 개념이 겹칠 수 있습니다. MCP는 Claude를 도구·서비스에 연결합니다. 설정은 동작을 바꾸고 훅은 도구 실행 뒤처럼 세션의 특정 시점에 작업을 실행합니다.

## 검토 에이전트와 테스트 명령 설치

먼저 에이전트 카탈로그를 열어 코드 리뷰어를 검색합니다. 결과 유형을 확인해 에이전트와 스킬을 구분합니다. 개발 도구 범주의 코드 리뷰어 페이지에는 설명, 설치 명령, GitHub 원본 링크가 있습니다. 미리보기나 코드 보기에서 지침도 읽을 수 있습니다. 이름은 목적을 알려주지만 실제 작동 방식은 지침을 읽어야 압니다. 소개된 리뷰어는 정확성, 유지보수성, 테스트, 잠재 보안 문제를 다룹니다. 변경 작업을 하는지 등 사용 도구도 확인해야 합니다.

템플릿이 특정 프레임워크를 가정하는지, 다른 에이전트를 언급하는지, 설치된 도구를 요구하는지 점검합니다. 템플릿은 시작점이므로 프로젝트에 맞춰 고칠 수 있습니다.

스택 빌더에서 코드 리뷰어를 고른 뒤 명령 카테고리에서 `generate tests`를 검색합니다. 해당 명령은 대상 파일이나 컴포넌트를 받아 기존 테스트 구조를 살피고 프로젝트 패턴에 맞춰 동작과 오류를 테스트하도록 지시합니다. 스택 빌더는 선택한 항목을 모아 한 번에 설치할 명령을 만듭니다.

설치 프로그램에는 Node.js, npm, Claude Code 설정이 필요합니다. 구성요소를 추가할 프로젝트 폴더에서 다음과 같이 실행합니다.

```bash
npx claude-code-templates@latest --agent development-tools/code-reviewer --command testing/generate-tests
```

예시 중에는 확인 프롬프트를 건너뛰는 `--yes` 옵션도 있습니다. 첫 설치에서는 진행 과정을 볼 수 있도록 프롬프트를 남겨두는 편이 좋습니다. 설치 후 리뷰어는 `.claude/agents/code-reviewer.md`, 테스트 명령은 `.claude/commands/generate-tests.md`에 생깁니다. 파일을 직접 열어 팀의 검토 우선순위와 테스트 규칙에 맞게 수정할 수 있습니다.

## Claude Code에서 사용

같은 프로젝트에서 Claude Code를 실행하고, 폴더를 만든 뒤 이미 실행 중이었다면 다시 시작합니다. React 가입 양식을 검토할 때 `@`를 입력해 code reviewer 에이전트를 고르고, 검증 오류, 상호작용 문제, 누락된 오류 처리를 검토하되 구체적인 파일 위치를 보고하고 앱 파일은 수정하지 말라고 요청할 수 있습니다. 결과는 코드에 비춰 확인합니다. 문제를 재현할 수 있는지, 수정 제안이 애플리케이션과 맞는지 점검합니다. 보고서가 길다고 더 좋은 것은 아닙니다. 재현 가능한 버그 하나가 일반적인 제안 스무 개보다 유용할 수 있습니다.

같은 컴포넌트에 `/generate-tests`를 실행하고 파일 경로를 제공합니다. 기존 테스트 프레임워크에 맞춰 빈 입력, 잘못된 값, 성공 제출, 실패 요청을 테스트하라고 할 수 있습니다. 명령은 반복 절차를 제공하고 요청은 대상과 요구사항을 제공합니다. 생성된 테스트를 프로젝트 명령으로 실행한 뒤 실패가 앱 문제인지 잘못된 테스트 가정인지 확인하고 브라우저에서도 양식을 시험합니다.

## 스킬, MCP, 설정, 훅

예를 들어 창의적 디자인 범주의 프런트엔드 디자인 스킬을 검색해 지침을 검토할 수 있습니다. 설치 후 `.claude/skills` 아래 개별 폴더의 대문자 `SKILL.md`에 저장됩니다. 지원 파일이 함께 있을 수 있으므로 폴더 전체를 확인합니다. Claude Code에서 `/front-end-design`을 호출해 가입 페이지의 시각적 위계를 개선하되 기존 검증을 유지하고 좁은 화면에서도 작동하게 해 달라고 요청할 수 있습니다. 대상 사용자, 원하는 분위기, 보존할 조건을 알려야 합니다.

MCP는 외부 도구나 서비스와 연결합니다. 계정, 인증 정보, 로컬 프로그램이 필요할 수 있으니 구성과 요구사항을 읽고, 필요한 작업이 있을 때만 추가합니다. 설정은 시간 제한 같은 동작을 바꾸고, 훅은 수정 후 포맷처럼 세션의 특정 사건에 작업을 자동 연결합니다. 이벤트와 실행 명령, 필요한 포매터가 있는지 확인합니다.

## 진단 및 분석 도구

`npx claude-code-templates@latest --health-check`는 로컬 설정을 점검하고 진단과 권장 사항을 보여줍니다. 일반 권고가 현재 환경에 맞는지 결과별로 읽어야 하며, 진단만 원한다면 이후 프로젝트 설정은 거절할 수 있습니다.

`npx claude-code-templates@latest --analytics`는 브라우저 대시보드를 열어 로컬 기록에 따라 토큰 사용량, 대화, 세션, 에이전트 활동을 볼 수 있습니다. 저장된 세션 기록이 없으면 화면이 비어 있을 수 있습니다. `--chats`는 Claude 대화를 보고 응답을 따라가는 브라우저 인터페이스를 엽니다. 긴 작업을 기다릴 때 진행을 확인하기 편리합니다. 베타 세션 분석의 모델 정보와 비용은 저장된 사용량에서 계산한 추정치이지 청구서나 구독 한도 잔량이 아닙니다.

원격 터널도 문서화돼 있습니다. 대화에는 코드와 프롬프트가 있을 수 있으므로 URL에 누가 접근 가능한지 주의해야 합니다. `--plugins`는 플러그인과 마켓플레이스를 살펴보는 대시보드를 엽니다.

## 사용 제안

이 프로젝트의 강점은 구성요소를 찾아 지침을 검사하고 작은 묶음으로 설치하는 과정입니다. 모든 템플릿이 모든 코드베이스에 맞는다고 가정하지 말아야 합니다. 폭넓은 지침, 강한 의견이 담긴 지침, 사용하지 않는 도구를 전제로 하는 지침도 있습니다. 먼저 자주 반복하는 한 작업에 필요한 것만 설치해 시험하고 도움이 되는 부분을 남기세요. 컬렉션은 무료지만 모델 사용과 연결 서비스 비용은 별도입니다.
