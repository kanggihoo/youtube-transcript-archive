# Cursor 핵심 개발자 Lauren Tan: AI 에이전트를 실전에서 제대로 신뢰하는 법 (xAI GrokBot 워크숍)

## 한 줄 요약

에이전트 활용의 핵심은 마이크로매니지먼트에서 벗어나 신뢰를 구축하는 데 있으며, 이를 위해 앱을 직접 구동·계측하는 '검증 스크립트'와 에이전트가 딴짓을 못 하도록 원천 차단하는 '하드 제약(Dune 아키텍처)'을 구축해야 월 1,000개 이상의 PR을 안전하게 자동 머지할 수 있다.

## 신뢰 곡선(Trust Curve)과 엔지니어링 매니지먼트

- **신입 온보딩과의 유사성**: 코딩 역량은 뛰어나지만 도메인 맥락이 없는 신입 엔지니어를 가르치듯, 에이전트에게 양질의 토큰(스킬과 규칙)을 주입해 더 높은 지능의 잠재 공간에서 패턴을 찾도록 유도
- **인간 병목 탈피**: 에이전트가 쓴 코드를 사람이 직접 빌드하고 디버깅하는 수작업에 갇혀 있으면 병렬화 불가. 에이전트에게 실행·계측 권한을 부여해 피드백 루프를 닫아야 함
- **자율 머지 단계 도달**: 신뢰가 검증된 시스템에서는 하룻밤 사이에 에이전트가 20개 이상의 PR을 자동으로 머지하고 인간은 메인 브랜치에서 모니터링만 수행

## 핵심 무기: 실행형 검증(Verification)과 피처 맵(Feature Map)

- **CDP 기반 애플리케이션 직접 조작**: Chrome DevTools Protocol, 시뮬레이터 유틸리티를 통해 에이전트가 직접 UI를 조작하고 CPU 트레이스, 메모리 스냅샷을 분석
- **피처 맵(Feature Map)**: 모호한 버그 신고(스크린샷 한 장과 물음표 등)가 들어와도 에이전트가 DOM 선택자, 단축키, 기능 경로를 스스로 찾아갈 수 있도록 전체 UI 지도를 문서화
- **이발(Evals)과 힐 클라이밍**: 에이전트가 평가받는 사실을 인지하지 못하도록 격리된 디렉터리에서 스킬을 테스트하고, `/loop`를 통해 10점 만점이 나올 때까지 스킬 자체를 자동 개선

## Dune 아키텍처: 에이전트를 위한 하드 제약 설계

1. **지름길을 최선의 경로로 (The shortest path is the best path)**: 에이전트는 본능적으로 가장 빠른 방법을 택하므로, 그 지름길이 가장 우수한 아키텍처가 되도록 제약 설계
2. **`useEffect` 전면 금지**: 리액트 앱의 주요 성능 저하 원인인 `useEffect` 사용 시 CI 실패 처리
3. **코드 주석(Comments) 금지**: 에이전트가 남기는 불필요한 역사적 맥락과 엉뚱한 가정을 방지하기 위해 주석 작성 금지
4. **스레드 및 프로세스 격리 강제**: Electron의 메인 스레드와 렌더러 스레드 간 잘못된 의존성 임포트를 CI 레벨에서 의존성 그래프 검사로 원천 차단하여 60fps 보장
5. **기능(Feature) 단위 디렉터리 응집**: 관련 코드를 한 디렉터리에 모아 에이전트의 불필요한 탐색 비용 최소화

## 소프트 규칙 vs 하드 제약

- **소프트 규칙의 한계**: `AGENTS.md`, 프롬프트 지침, AI 리뷰 봇 등은 에이전트가 언제든 무시하거나 잊어버릴 수 있어 이것만으로는 코드베이스가 망가짐
- **하드 제약의 절대성**: 컴파일러(Rust 등), 린터, 엄격한 CI 빌드 실패만이 에이전트의 결함을 막는 유일한 방벽. 인간이 코드 리뷰에서 지적하는 모든 패턴은 즉시 자동화된 린트 룰이나 CI 제약으로 승격시켜야 함
- **비개발자 기여 활성화**: 철저한 가드레일이 갖춰지면 PM이나 디자이너도 에이전트를 통해 안전하게 프로덕션 코드를 수정하고 PR을 올릴 수 있음
