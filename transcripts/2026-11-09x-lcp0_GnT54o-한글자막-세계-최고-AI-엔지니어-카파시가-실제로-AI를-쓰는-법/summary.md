# 카파시가 실제로 AI를 쓰는 법

## 결론부터

크리에이터 Nick Saraev는 최근 2주간 Andrej Karpathy의 글과 댓글에서 확인했다는 AI 활용 방식을 정리한다. 요지는 코드를 읽지도 쓰지도 않고 Claude에게만 말하며, 프롬프트는 짧게, 설명은 그림으로 받고, 거슬리는 것은 바로 만들어 해결한다는 것이다.

## 핵심 내용

- **기본 설정(발표자 전언):** Claude Code Mac 앱에서 Opus 5.5를 medium effort로만 쓰고 max는 쓰지 않는다. 코드를 읽지도, 쓰지도, 터미널 명령을 직접 실행하지도 않는다. 설명은 항공 정비 매뉴얼식 제한 영어인 ASD-STE100으로 받는다.
- **프롬프트와 설명:** 요구사항을 많이 넣으면 앞선 요구와 모순되어 결과가 나빠질 수 있다고 보고 프롬프트를 짧게 쓴다. 보안 강화는 "Check recent cyber stuff", 배포는 서버 IP와 "update, deploy, secure, harden, optimize"만 줬다고 한다. 이해가 안 되면 글 대신 다이어그램, HTML 페이지, 설명 영상을 요청한다.
- **검증과 위임:** 공개 벤치마크를 믿지 않고 Epoch의 ECI(벤치마크의 벤치마크)를 가리킨다. 위도·경도로 "땅/바다"를 물어 세계 지도를 그리는 식으로 직접 시험한다. 데이터 작업은 싼 필터로 거른 뒤 Sonnet 서브에이전트에 맡기고 Opus가 지휘하게 한다. 앱을 공유하는 대신 데이터와 프롬프트를 공유하고, 거슬리는 유튜브 대신 Hacker News 추천작만 모은 HackerTube를 만들었다.

## 배울 점과 적용 조건

- 모델에게 긴 요구사항 목록을 주기보다 짧게 시키고 결과를 보며 고치는 방식이 때로 낫다는 관점이다. 이 영상은 근거를 제시하지 않으므로 직접 비교해 봐야 한다.
- 이해가 안 되는 주제는 글 설명 대신 다이어그램·HTML을 만들게 하는 방법은 바로 시도할 수 있다.
- 싼 필터 → Sonnet 서브에이전트 → Opus 지휘 구조는 대량의 비정형 데이터를 처리할 때 비용을 줄이려는 용도에 맞다.

## 근거와 한계

- **영상의 근거:** 발표자가 본 카파시의 글과 Hacker News 댓글에 대한 서술. 화면에 링크나 인용문은 자막에서 확인되지 않는다.
- **평가:** 모두 전해 들은 일화다. "짧은 프롬프트가 더 낫다", "max effort는 불필요하다"는 비교 실험 없이 개인 취향으로 제시된다. 카파시가 코드를 전혀 보지 않는다는 주장은 일반 개발에 그대로 옮기기 어렵다.
- **확인 범위:** 영어 자막 기반이다(한국어 자막 트랙은 받아지지 않아 영어 원문이 저장되어 있다). 카파시의 발언 자체와 그가 Anthropic에 재직한다는 영상 내 언급은 외부 미검증이다.
- **홍보성:** 특별한 징후는 없다.
