# I Tested 10 MCP Servers. These Are the Ones Worth Using For Local AI

## 한 줄 요약

로컬 AI를 쓰는 개발자를 위해 파일, 웹, 데이터베이스, Git, 브라우저, 검색 영역의 MCP 서버 10개를 하나씩 용도와 예시로 소개하며, 전부 쓰지 말고 내 워크플로에 맞는 것만 고르라고 합니다.

## 파일과 웹 접근

- File System MCP: AI가 허용된 파일과 폴더만 보고 수정하게 합니다. 프로젝트를 통째로 붙여 넣는 대신 백엔드 폴더를 뒤지게 할 수 있고, 꼭 필요한 폴더에만 권한을 줘야 합니다
- Firecrawl MCP: 문서 링크를 주면 관련 정보를 대신 가져옵니다. 여러 페이지를 열어 복사해 붙여 넣는 수고를 덜어 줍니다
- Fetch MCP: 읽힐 페이지를 이미 알 때 URL을 주고 내용을 가져와 설명하게 합니다. 단순하지만 문서를 자주 다룰 때 유용합니다
- Puppeteer MCP: 브라우저로 사이트를 조작합니다. JavaScript, 폼, 버튼, 동적 콘텐츠가 있는 사이트처럼 HTML만으로 부족한 경우에 씁니다
- Brave Search MCP: 로컬 모델의 오래된 지식을 보완하려고 현재 웹을 검색하게 합니다. 라이브러리, API, 문서에서 특히 유용합니다

## 데이터베이스

- SQLite MCP: 로컬 데이터베이스를 직접 조회해 쿼리를 만들고 결과를 설명합니다. 작은 앱, 프로토타입, 테스트에 맞습니다
- PostgreSQL MCP: 같은 방식으로 PostgreSQL을 다룹니다. 예를 들어 최근 이틀간 로그인 실패가 많은 사용자를 찾게 할 수 있습니다. 데이터가 중요하므로 읽기 전용으로 시작하는 편이 안전합니다

## 코드 변경과 사고 과정

- GitHub MCP: 저장소, 이슈, 풀 리퀘스트, 커밋을 다룹니다. 큰 PR의 변경 요약과 보안 검토가 필요한 지점을 짚는 데 쓰되, 직접 하는 코드 리뷰를 대체하지는 못합니다
- Git MCP: 로컬 버전 관리 쪽으로, 커밋, 브랜치, 변경 내용을 다룹니다. 최근 두 커밋 사이에서 버그를 일으킨 변경을 찾게 할 수 있습니다. Git과 GitHub는 별개입니다
- Sequential Thinking MCP: 외부 도구가 아니라 복잡한 문제를 단계별로 쪼개어 푸는 방식입니다. 원인이 여럿인 디버깅에서 첫 번째 설명으로 바로 결론 내지 않게 해 줍니다

## 마무리

10개 서버는 AI 개발에 유용한 영역을 폭넓게 덮지만 전부 쓸 필요는 없습니다. 워크플로에 맞는 것을 골라 로컬 AI에게 실제로 필요한 도구와 정보만 주라고 권합니다.
