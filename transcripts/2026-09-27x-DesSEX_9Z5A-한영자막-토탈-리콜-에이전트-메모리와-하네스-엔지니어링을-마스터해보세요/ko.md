# 한국어 번역

## 이번 세션의 목표

이번 세션에서는 에이전트 메모리와 하네스, 직접 하네스를 만드는 법을 다룹니다. 모델에 관한 뉴스가 계속 나오지만 언어 모델은 추론에서 바뀌지 않는 부분입니다. 오늘은 하네스에 초점을 맞추겠습니다. 발표자는 Oracle에서 7년간 일했고 그중 약 4년간 개발자 옹호 역할을 했으며, Andrew Ng와 에이전트 메모리 강좌를 공개했다고 소개합니다.

먼저 에이전트 스택과 데이터 계층, AI 애플리케이션의 여러 형태, 에이전트의 정의, 하네스를 구성하는 일곱 계층을 설명한 뒤 지속 학습을 다룹니다.

## 에이전트 스택과 데이터 계층

에이전트 스택은 애플리케이션, 데이터, 모델, 인프라, 컴퓨팅의 다섯 계층으로 볼 수 있습니다. 애플리케이션은 사용자가 보는 제품이고, 데이터에는 메모리·지식·검색·인코딩이 포함됩니다. 모델은 추론을 맡고, 인프라는 오케스트레이션과 모델 선택을 담당합니다. 컴퓨팅은 클라우드, GPU, 데이터베이스 엔진입니다. 데이터 외의 네 계층은 점점 상품화되어 복잡성이 추상화되고 있습니다. 개발자가 가장 많이 통제할 수 있는 것은 데이터 계층입니다.

데이터 계층에서 하네스는 게이트웨이와 MCP, 메모리, 시맨틱, 검색, 컨텍스트 계층, 도구와 스킬로 구성될 수 있습니다. 게이트웨이와 MCP는 LLM이 Outlook 같은 프로그램을 호출할 함수들을 정의해 외부 세계와 연결합니다.

AI 앱에는 수동적인 LLM 챗봇, 백그라운드에서 일부 작업을 하는 RAG 앱, 자동화된 워크플로, 자율적으로 움직이는 에이전트가 있습니다. 발표자의 정의로 에이전트는 LLM과 하네스입니다. 추론은 LLM이 맡고, 파일·데이터베이스는 기억을 제공하며, 도구는 행동을 가능하게 하고, 입력은 환경을 인식하게 합니다.

하네스 엔지니어링의 목표는 비결정적인 추론 모델을 둘러싸 신뢰할 수 있고 반복 가능한 결과를 얻는 것입니다. 같은 입력에도 모델은 다른 답을 낼 수 있지만, 하네스를 통해 자동화의 신뢰성과 자율성의 유연성을 결합할 수 있습니다. 모델은 공통 API를 통해 교체 가능하도록 두고 하네스에 집중할 수 있습니다.

## 하네스를 구성하는 일곱 계층

하네스에는 메모리가 물리적으로 저장될 저장 계층, 인코딩·검색·검색결과 회수를 다루는 메모리 엔지니어링, 회사 고유의 숨은 용어와 지식을 다루는 시맨틱 계층, 에이전트 루프, 컨텍스트 엔지니어링 등이 필요합니다. 컨텍스트 창은 해결 중인 일에 가장 관련 있는 정보로 유지하고 불필요한 내용은 줄여야 합니다.

## 파일과 데이터베이스의 메모리 저장

파일은 만들고 덧붙이기 쉬우며 모델이 익숙하게 다룹니다. 비정형 데이터에 편리하고 POSIX 의미 체계를 따라 Debian, Ubuntu 등 운영체제와 잘 맞습니다. 반면 파일에는 트랜잭션과 동시성 제어가 부족할 수 있습니다. 데이터베이스는 구조적이며 검색 기능이 강하지만, 반드시 SQL만 써야 하는 것은 아닙니다. 두 가지 중 하나만 고르기보다 필요에 따라 함께 쓸 수 있습니다. 발표자는 파일과 데이터베이스 각각의 장단점을 검토하고 하이브리드 구성이 유용하다고 주장합니다.

메모리 계층에는 데이터를 어떻게 인코딩하고 검색할지, 어떤 결과를 컨텍스트에 넣을지를 설계해야 합니다. 조직 고유 용어나 암묵적인 업무 지식을 시맨틱 계층에서 설명하면 모델이 이미 안다고 가정해 누락하는 일을 줄일 수 있습니다.

## 에이전트 루프와 컨텍스트

에이전트 루프는 모델이 도구를 요청하고 하네스가 실행해 결과를 다시 전달하는 반복입니다. 작업이 완료되거나 중단 조건에 이를 때까지 이어집니다. 컨텍스트 엔지니어링은 모델이 지금 해야 할 일에서 벗어나지 않도록 필요한 정보를 골라 창에 담는 일입니다. 불필요한 대화 이력을 모두 넣는 대신 검색으로 관련 메모리를 가져오고, 최신 사실을 반영하며, 컨텍스트가 지나치게 커지지 않게 합니다.

## 실습: 에이전트 하네스 구축

발표자는 GitHub Code Spaces에서 실행할 워크숍 저장소를 소개합니다. 노트북에서 모델 호출만 하는 가장 단순한 상태부터 시작해 검색, 회수, 인코딩 등 기능을 하나씩 더해 19개 실습을 진행합니다. 각 할 일에는 설명 문서와 해답이 제공됩니다.

앱북은 하네스 구성요소를 개별적으로 시험할 수 있게 합니다. 시연 앱은 Oracle OCI 생성형 AI 서비스를 통해 모델을 호출하며, 컨텍스트 창에 어떤 도구와 스킬이 들어갔는지, 스키마, 도구 호출과 SQL 실행 등 추적 정보, 토큰 수를 보여줍니다. 예시 질의는 상품 범주별 매출을 조회하며 에이전트가 오류를 만나도 루프와 오류 복구로 계속 시도합니다.

도구가 수천 개일 때는 계층형 도구 상자 패턴을 쓸 수 있습니다. HNSW 그래프 색인에서 노드마다 벡터 검색을 수행해 관련 도구를 찾습니다. 도구나 스킬 설명이 서로 비슷하면 LLM으로 설명을 보강해 벡터 검색에서 구분되도록 할 수 있습니다.

루프에는 무한 재시도를 막는 한도가 필요합니다. 발표자는 사용하는 모델에 따라 최대 도구 호출 횟수를 8~12회 정도로 설정하는 사례를 들고, 모델이 얼마나 오래 시도할지 정하는 ‘인내심’ 변수를 제안합니다. 쉬운 문제에는 소형 모델을, 어려운 문제에는 프론티어 모델을 보내는 라우팅도 가능합니다. 문제별 전문 소형 모델을 오케스트레이터와 조합하면 토큰 효율을 높일 수 있다는 것이 발표자의 견해입니다.
