# How To Use Claude Code To Build Insanely Beautiful Sites With Opus 5.5

## 한 줄 요약

AI가 만든 사이트가 다 비슷해 보이는 건 모델이 아니라 과정의 문제이며, 기획, CLAUDE.md, Hallmark 스킬, design.md, Vercel 배포, Scroll World 스킬의 6단계를 따르면 Claude Code로 차별화된 시네마틱 스크롤 웹사이트까지 만들 수 있다는 영상이다.

## 시작 전 준비와 Claude Code 기본기

- 터미널은 Warp, 파일 확인은 VS Code, 모델은 디자인에 강하다는 Opus 5.5를 사용한다. 간단한 작업에는 Sonnet, 복잡한 작업에는 Fable을 쓴다
- 터미널 명령어는 `ls`(목록), `cd`(이동), `mkdir`(폴더 생성)이면 충분하고, 프로젝트 폴더 안에서 `claude`를 실행한다
- 자주 쓰는 기능: `escape`로 중단, `@파일명`으로 파일 지정, `context`로 사용량 확인, `compact`로 요약, `clear`로 새 대화, `rename`/`resume`으로 세션 저장과 복귀, `escape` 두 번으로 이전 메시지로 되돌리기

## 1단계: plan 모드로 먼저 기획

- plan 모드(`plan` 명령어 또는 shift+tab)는 파일을 수정하지 못하게 막고 질문만 하게 한다. 만들기 전에 세부 사항을 정하고 엉뚱한 작업을 피할 수 있다
- 기술 스택(Next.js), 섹션 구성, 디자인 스타일, 콘텐츠 보유 여부 등을 묻고 계획을 제시한다. 이를 실행시키면 첫 랜딩 페이지가 나오지만 여전히 AI가 만든 듯한 모습이다

## 2단계: CLAUDE.md에 비즈니스 맥락 고정

- 새 세션은 이전 기억이 없으므로, CLAUDE.md가 채팅 시작 시 컨텍스트에 주입되어 이를 보완한다
- `init`으로 만들 수 있지만 단순한 프로젝트에서는 실행 방법과 코드 구조만 적고, 사이트의 목적과 각 섹션의 역할은 빠진다. 이 영상에서는 건축 설계 회사 Forma의 잠재 고객 확보라는 비즈니스 맥락을 직접 추가했다
- 여러 번 수정해도 웹사이트의 의도가 유지되게 해준다

## 3단계: Hallmark 스킬로 AI 티 나는 디자인 걷어내기

- 스킬은 특정 작업 방식을 지시하는 지침 파일이다. Hallmark는 AI 에이전트가 흔히 쓰는 디자인 패턴에서 벗어나는 규칙을 제공한다
- Claude Code 입력창 맨 앞에 `!`를 붙이면 터미널 모드로 설치 명령어를 실행할 수 있다
- 시각 스타일만 물어보고 사이트를 다시 만들었고, 배치가 달라지고 여백이 다듬어져 AI 티가 줄었다

## 4단계: design.md로 색상과 폰트 잠그기

- 디자인 스킬로 레이아웃은 바뀌어도 모델은 학습된 기본 색상과 폰트를 쓴다. 예를 들어 Opus는 어떤 스킬을 써도 따뜻한 크림색이나 오프화이트로 기울어진다
- design.md는 색상, 폰트, 여백을 기록해 모델의 기본 선택을 덮어쓰는 파일이다. aura.build 같은 곳에서 받아 프로젝트 폴더에 넣고 이름을 design.md로 바꾼 뒤, 읽고 개편하되 구조와 애니메이션은 유지하라고 지시한다
- 직접 만든 고유 디자인이 필요하면 채널 커뮤니티(AIABS Pro)의 design.md 플래너 스킬을 쓸 수 있다고 소개한다
- 이후 변경이나 요소 추가에도 같은 디자인 규칙이 지켜져 일관된 브랜딩이 유지된다

## 5단계: GitHub와 Vercel로 배포

- 새 기능이 기존 기능을 망가뜨릴 수 있으므로 GitHub 커밋이라는 체크포인트로 저장하고, 문제가 생기면 이전 커밋으로 돌아간다
- 로컬 커밋을 리포지토리로 보내면 원격 커밋이 되고, Vercel이 이를 읽어 실제 사이트에 반영한다
- GitHub CLI로 로그인(일회용 코드와 승인)한 뒤 비공개 리포지토리에 업로드하고, Vercel에서 프로젝트를 import한다. 테스트가 실패하면 로그 오류를 Claude에게 넘겨 조사시킨다
- Vercel CLI도 설치해 두면 이후 배포 문제를 Claude Code가 직접 찾아 고칠 수 있다

## 6단계: Scroll World 스킬로 3D 스크롤 사이트 만들기

- 스크롤하면 생성형 AI 영상으로 만든 3D 시네마틱 장면을 카메라가 지나가는 페이지를 만든다. GitHub 리포지토리의 명령어로 설치한다
- 먼저 브랜치를 만들어 라이브 사이트를 보호한다. 브랜치는 원본의 복사본이고, 머지는 브랜치의 커밋을 메인에 합치는 것이며, GitHub는 머지 전에 풀 리퀘스트로 검토하게 한다
- 세계의 맥락, 모습, 카메라 움직임을 묻고, 모바일 버전을 고르면 모바일용 영상도 따로 만든다. 이번에는 데스크톱 9개, 모바일 9개로 총 18개 클립이 계획됐다. 클립 설명은 직접 하지 않아도 되고 마음에 안 들면 나중에 수정할 수 있다
- 기본 영상 생성은 Higgsfield이고 대안은 Manid이며, 이번에는 Runway를 지정했다. 다른 플랫폼을 쓰려면 MCP가 있어야 한다
- 결과는 다섯 단계의 이야기와 단계별 애니메이션, 전환 효과를 갖췄고, 모바일은 데스크톱 영상을 자른 것이 아니라 자체 화면 비율에 맞춘 영상을 쓴다

## Code Rabbit으로 PR 검토와 전체 스캔 (스폰서)

- Code Rabbit은 PR이 열리면 자동으로 변경 파일을 리뷰해 버그와 보안 문제를 표시하고 수정을 알려준다. 14일 무료 체험이 있다
- 이번 PR은 파일이 많아 리뷰에 약 15분이 걸렸고, 워크스루와 시퀀스 다이어그램, 변경 스택(5개 레이어 중 2개가 위험 표시)을 제공했다. 11개 이슈를 major와 minor로 정렬했고, 각 이슈마다 Claude Code에 바로 줄 수 있는 프롬프트가 붙는다
- 내장 AI 에이전트에게 변경이 사이트에 미치는 영향을 물을 수 있고, 이슈를 열어 자동 수정 패치를 받아 PR에 커밋할 수 있다
- AI deep scan은 리포지토리 전체를 훑는다. 이번에는 폼의 이메일 필드 보안 위험 1건을 찾아 fix 버튼으로 새 PR을 만들어 고쳤다
- 검토를 마친 뒤 PR을 머지하면 scroll world 사이트가 도메인에 라이브로 반영된다
