# AWS Networking Full Course in 2 Hours (FREE) — 한국어 요약 번역

> 원문 전체를 문장 단위로 옮긴 번역본이 아니라, 강의 흐름을 따라 각 파트의 내용을 한국어로 정리한 번역 요약입니다. 원문 표현을 그대로 옮기지 않고 요지만 담았습니다.

## 강의 소개

- AWS 네트워크는 서비스 목록이 아니라 하나의 연결된 시스템으로 설명합니다. 트래픽이 시작한 곳에서 도착하는 곳까지 따라가며 각 구성 요소의 역할을 봅니다.
- 5개 모듈로 나뉩니다. 1모듈은 기초와 VPC·서브넷·CIDR, 2모듈은 주소·라우팅·DNS, 3모듈은 보안 그룹과 네트워크 ACL, 4모듈은 인터넷 게이트웨이·NAT·로드밸런서와 3계층 VPC 구조, 5모듈은 VPC 간 연결과 온프레미스·원격 접속입니다.
- AWS 계정이나 네트워크 경험이 없어도 따라갈 수 있다고 안내합니다.

## 모듈 1: 네트워크 기초

- 주소, 라우팅, 방화벽은 AWS 이전부터 있던 개념이고, AWS는 이를 가상으로 제공할 뿐이라고 설명합니다.
- 계정 → 리전 → 가용 영역(AZ) → VPC → 서브넷 순서의 계층을 소개합니다. VPC는 리전 단위 리소스이고 서브넷은 하나의 AZ에만 속합니다. 기본 VPC는 실험용이고 운영에는 직접 만든 VPC를 쓰라고 권합니다.
- CIDR 표기법을 실제 계산으로 풉니다. /16은 65,536개 주소이고, 서브넷마다 AWS가 앞 4개와 마지막 1개를 예약해서 /24는 사용 가능한 주소가 251개라고 짚습니다.
- 모듈의 핵심 질문은 세 가지입니다. 리소스는 어디에 있고 주소는 무엇인가, 다음에 트래픽은 어디로 가는가, 그 트래픽은 허용되는가.

## 모듈 2: 주소, 라우팅, DNS

- EC2 인스턴스의 주소 종류(사설, 공인, 탄력적 IP, IPv6)를 비교하고 각 주소가 무엇을 보장하는지 설명합니다.
- 라우트 테이블은 로컬 경로에서 시작해 기본 경로(0.0.0.0/0)까지 보며, 여러 경로가 겹치면 가장 구체적인(가장 긴 프리픽스) 경로가 이긴다고 설명합니다.
- 가장 중요한 교훈으로 "경로가 맞다고 해서 트래픽이 허용되는 것은 아니다"를 강조합니다. 이는 다음 모듈로 이어집니다.
- VPC 내부 DNS 해석 방식도 다룹니다.

## 모듈 3: 방화벽과 접근 제어

- 두 가지 방화벽을 비교합니다. 보안 그룹은 리소스 단위이고 상태 저장(stateful)이며 허용 규칙만 둡니다. 네트워크 ACL은 서브넷 단위이고 상태 비저장(stateless)이며 번호 순서의 규칙으로 명시적 거부도 가능합니다.
- 같은 요청을 두 방화벽에 통과시키며 양방향 흐름을 따라가고, 응답 트래픽이 임시 포트 범위에서 막히는 흔한 문제를 짚습니다.
- VPC 플로 로그로 수락·거부 기록을 확인하는 법을 설명합니다. 로그가 많은 비용을 낼 수 있어 거부 트래픽 위주로 켜는 방식을 권합니다.
- IAM이 네트워크 설정 변경 권한을 정한다는 점도 다룹니다.

## 모듈 4: 인터넷, NAT, 로드밸런서

- 퍼블릭 서브넷은 공인 IP가 있는 서브넷이 아니라 인터넷 게이트웨이로 가는 경로가 있는 서브넷이라고 구분합니다.
- 애플리케이션 서버와 DB는 프라이빗 서브넷에 두는 것이 일반적입니다. 바깥으로 나가는 트래픽은 NAT 게이트웨이를 거치며, NAT 게이트웨이는 AZ마다 하나씩 두는 것이 표준입니다. 한 곳에만 두면 그 AZ 장애 때 다른 AZ의 외부 통신도 끊깁니다.
- NAT 게이트웨이는 시간당 요금과 처리량(GB) 요금이 붙어 청구서에서 놀라기 쉽다고 경고합니다. NAT 인스턴스는 직접 관리하는 대신 작은 환경에서 비용을 줄일 수 있다고 소개합니다.
- ALB와 NLB의 위치와 서브넷 주소 공간 확보를 설명합니다.
- 3계층 VPC(서브넷 6개, 라우트 테이블 4개, 보안 그룹 3개)를 하나의 완성된 구조로 묶고, AZ 하나가 죽어도 동작하는 구성을 보여 줍니다.

## 모듈 5: VPC 너머의 연결

- 연결 대상에 따라 선택지를 나눕니다. 두 VPC는 피어링, 여러 네트워크는 Transit Gateway, AWS 서비스는 VPC 엔드포인트와 PrivateLink, 사무실 네트워크는 Site-to-Site VPN이나 Direct Connect, 개인 사용자는 Client VPN입니다.
- 피어링은 관계가 적을 때 좋고, 연결이 늘어나면 Transit Gateway가 낫다고 봅니다. 중앙 출구와 검사 지점을 둘 때도 허브 구조가 쓰입니다.
- 인터페이스 엔드포인트는 시간·AZ·데이터량 기준으로 과금되며 NAT보다 싸지만 공짜는 아니라고 설명합니다.
- Direct Connect는 예측 가능한 지연과 대역폭을 주지만 준비에 몇 주에서 몇 달이 걸리고, 단일 회선은 단일 장애점이므로 VPN 백업을 권합니다.

## 마무리

- 모든 내용을 "트래픽을 따라가기" 하나로 묶습니다. 어디서 출발하고, 어디로 가야 하며, 어떤 경로를 거치고, 어떤 보안 통제를 통과하는지 순서대로 묻습니다.
- 수동으로 따라가 본 뒤 AWS Reachability Analyzer로 자동 검사할 수 있다고 소개합니다.
- 다운로드 자료(체크리스트, 연결 결정 트리, CIDR 계획 시트, 보안 그룹·ACL 카드, 비용 카드, 용어집, 모듈별 면접 질문 등)를 안내합니다. 자료를 받는 방식과 조건은 자막만으로는 확인할 수 없습니다.
