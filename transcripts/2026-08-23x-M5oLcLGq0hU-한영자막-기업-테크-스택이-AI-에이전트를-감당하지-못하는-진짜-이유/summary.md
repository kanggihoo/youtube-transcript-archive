# 기업 테크 스택이 AI 에이전트를 감당하지 못하는 진짜 이유

## 한 줄 요약

엔터프라이즈 AI 에이전트의 성공은 모델 성능이 아니라 감사 추적을 위한 불변 이벤트 로그, 제로 트러스트 오브젝트 스토리지 격리, 인간-에이전트 동등성이라는 아키텍처 프리미티브를 기초부터 설계하는 데 있다.

## POC 성공 후 마주치는 4대 난관

단순 데모나 POC 단계의 성공 이후, 프로덕션 상용화 단계에서 기존 엔터프라이즈 테크 스택은 4가지 벽에 부딪힙니다:

1. **감사 추적(Audit Trail)**: 단순 개발자 로그(Datadog 등)가 아니라, 법정에서 증거 체인(Chain of Evidence)으로 제출 가능한 완전한 행동 및 데이터 접근 기록 요구 (SOC 2, HIPAA, HITRUST)
2. **민감 데이터 보호**: 복잡하고 거대한 비정형 의료/금융 데이터를 최소 권한으로 통제하고, 데이터 유출 및 프롬프트 인젝션 차단
3. **동적 에스컬레이션**: AI가 확신이 없거나 고위험 판단일 때 예측 불가능하게 인간에게 개입을 넘기는 메커니즘
4. **신뢰할 수 있는 평가(Evals)**: 비결정론적 LLM과 데이터 드리프트 상황에서 프로덕션 수준의 정확도 지속 측정

## 엔터프라이즈를 위한 4가지 핵심 아키텍처 프리미티브

### 1. 불변 이벤트 로그 (Immutable Event Log)
- 시스템의 단일 진실 공급원(Source of Truth)으로 타임스탬프 기반 추가 전용(append-only) 로그 구축
- 과거 특정 시점의 시스템 상태를 완벽히 재현(Replay)할 수 있어 감사 추적과 디버깅이 데이터 저장 패러다임 자체에서 자연스럽게 해결됨

### 2. 오케스트레이션과 분리된 스키마 기반 오브젝트 스토리지
- 이벤트 로그에는 실제 민감 데이터가 아닌 스키마 기반 데이터 블롭의 '참조(Reference)'만 저장
- 개발자가 민감 정보(PHI)를 직접 열람하지 않고도 데이터 형태만 보며 에이전트의 행동을 디버깅/관측 가능
- 사용 시점에만 토큰을 발급하는 제로 트러스트(Zero Trust) 구조로 치명적인 삼각관계(Lethal Trifecta) 및 인젝션 방어

### 3. 인간-에이전트 동등성 (Human-Agent Equivalency)
- LLM과 인간을 동일한 최상위 '에이전트' 인터페이스로 정의
- 워크플로 체인 중간 어디서든 인간에게 에스컬레이션이 일어나도 하위 단계는 작업 주체가 인간인지 AI인지 신경 쓸 필요가 없음
- 공통 컨텍스트를 에이전트용 '프롬프트'나 인간용 'UI'로 자유롭게 변환 매핑

### 4. 아키텍처에서 자연스럽게 파생되는 평가(Evals)
- **불변 로그 재생**: 특정 과거 시점으로 돌아가 프롬프트/모델/코드 변경의 영향을 정확히 A/B 비교
- **인간-에이전트 비교**: 동일 작업을 인간 전문가와 AI에게 맡겨 차이를 실시간 채점
- **프로덕션 환경 내 평가**: 고객 온프레미스 VPC 외부로 데이터를 반출하지 않고 안전하게 인플레이스 평가 수행

## POC 위에 덧붙이지 말고, 제약 조건을 토대로 설계하라

실패하는 프로젝트는 POC 데모 코드 위에 보안/감사/평가를 사후 덧붙이기(bolt-on) 방식으로 얹어 깨지기 쉬운 시스템을 만듭니다. 성공하는 프로젝트는 규제와 보안 제약 조건을 아키텍처의 1급 시민으로 두고, 견고한 프리미티브 위에 비즈니스 로직을 구축합니다.
