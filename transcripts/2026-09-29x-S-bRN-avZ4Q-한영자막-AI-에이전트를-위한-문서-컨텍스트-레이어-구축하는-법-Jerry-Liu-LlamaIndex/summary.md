# AI 에이전트를 위한 문서 컨텍스트 레이어 구축하는 법

### 한 줄 요약

에이전트가 아무리 똑똑해져도 성능을 좌우하는 것은 컨텍스트이고, 10조 페이지가 넘게 PDF·워드·파워포인트에 갇힌 지식을 열려면 문서 파싱, 시맨틱·저장소, 워크플로의 세 레이어가 필요하다는 발표입니다. LlamaIndex의 Jerry Liu는 그중 파싱(OCR)이 출발점이며, 파이프라인과 VLM을 섞은 하이브리드 방식이 비용과 정확도의 균형점이라고 말합니다.

### 2026년의 RAG는 에이전트 하네스와 컨텍스트 레이어

- 2023년의 나이브 RAG는 청크 분할, 임베딩, 벡터 DB, 단순 top-K 검색, LLM 생성이라는 고정된 단계였습니다
- 지금은 에이전트 루프와 도구 사용이 좋아져 검색의 복잡성이 에이전트 계층으로 옮겨 갔습니다. 검색 도구가 기본적이어도 에이전트가 좋은 검색어를 스스로 골라 반복합니다
- 컨텍스트 논의는 윈도우 관리에서 어떤 MCP 서버와 스킬을 연결할 것인가로 올라갔습니다
- 프로그램을 정의하는 수단이 코드에서 영어로 이동했고, 앞으로는 작업 대신 목표와 채점 기준만 주면 에이전트가 가용한 컨텍스트로 해결하는 방향이라고 봅니다

### 컨텍스트가 전부이고 문서가 그 컨테이너

- 무한히 똑똑한 에이전트도 올바른 작업과 조직의 방대한 컨텍스트에 접근할 수 있어야 가치를 냅니다
- 웹 검색, MCP·스킬 커넥터, Snowflake·Databricks 같은 웨어하우스 외에 SharePoint, Box, Dropbox, S3에 저장된 문서가 전체의 90%라고 합니다
- 문서는 비정형 컨텍스트의 범용 컨테이너이며, PDF·파워포인트·워드·엑셀에 10조 페이지가 넘는 인간 고유의 지식이 갇혀 있습니다

### 에이전트 네이티브 문서 플랫폼의 세 레이어

- 문서 파싱: 문서를 정확하고 토큰 효율적인 마크다운과 메타데이터로 디지털화합니다
- 시맨틱·저장소: 사람과 에이전트를 위한 문서 관리로, 에이전트가 문서를 수집·저장·조작하는 인터페이스입니다
- 워크플로: 송장 처리, KYC, 보험금 청구처럼 반복되는 일은 범용 에이전트에 맡기지 않고 비용과 정확도를 조율한 전용 워크플로로 만듭니다
- 에이전트 네이티브 문서 형식, 버전 관리, 편집, 서비스형 힐클라이밍은 아직 풀리지 않은 과제로 남아 있습니다

### 문서 OCR이 어려운 이유

- PDF는 인쇄용으로 만들어져 글자는 좌표를 가진 글리프로, 표는 선분과 셀 위치의 텍스트로 저장됩니다. 다단 레이아웃에서는 저장 순서가 읽는 순서와 일치한다는 보장도 없습니다
- 워드와 파워포인트는 PDF보다 구조화되어 있지만 독자적인 XML에 군더더기가 많습니다. 서식과 의미 메타데이터는 끌어올리고 태그는 무시하면서 페이지 구조를 볼 수 있게 렌더링해야 합니다
- 휴리스틱·파이프라인 방식(PyPDF, PyMuPDF 등)은 사람이 짠 규칙에 기대고, 단발성 VLM 방식은 텍스트만 있는 페이지에서 환각이 생기고 비용이 크며 의미와 근거가 부족합니다
- LlamaIndex는 둘을 결합한 하이브리드가 비용과 정확도의 파레토 프런티어에 있다고 봅니다. 문서 OCR의 프런티어는 범용 프런티어 모델보다 항상 더 정확하고 저렴하다는 것이 이유입니다. 최신 모델의 시각 이해를 맞춤형 워크플로로 증류할 수 있기 때문입니다
- 상용 서비스 LlamaParse는 PDF·워드·파워포인트 엔진 최적화, 저가 특화 모델부터 프런티어 모델까지의 자동 라우팅, 표·차트 등에 특화된 파인튜닝 VLM으로 구성됩니다

### ParseBench 벤치마크

- 사람이 검증한 2,000페이지로 표, 차트, 내용 충실도, 의미적 서식을 측정하며 구문 정확성이 아니라 에이전트의 이해에 맞춰 최적화했습니다
- parsebench.ai에 공개되어 있고 Hugging Face와 Kaggle에서도 받을 수 있으며, 프런티어 모델, 오픈 웨이트 모델, 특화 OCR 등 약 50가지를 비교합니다
- 이 결과로 문서 이해가 아직 100% 해결되지 않았다고 말합니다

### 정확도, 비용, 지연 시간의 세 영역

- 고정확도: 보험·금융 같은 규제 산업에서는 99%에서 거의 100%가 필요합니다. 추출 오류가 재무 모델 붕괴나 사기 적발로 이어질 수 있어 페이지당 비용을 더 내고 깊은 에이전틱 추론을 씁니다
- 저비용: SharePoint에서 하루 100만 건 넘게 갱신되는 문서를 RAG용으로 색인하는 경우입니다. 다소 부정확해도 에이전트가 나중에 문서를 파고들어 보완할 수 있으므로 확장 가능한 오프라인 파이프라인이 맞습니다
- 초저지연: Claude Cowork에 문서 천 개를 올리고 1분 안에 처리해야 하는 실시간 상황입니다. VLM 다수로 대규모 처리하기는 어느 OCR 서비스에도, LlamaParse에도 어렵습니다

### 에이전트 루프에 넣는 LightParse

- Rust 기반의 무료 오픈소스 파서로, MIT 또는 Apache 라이선스라고 기억한다고 말합니다. 가장 빠른 오픈소스 파서이며 VLM 없이는 가장 정확한 마크다운 파서라고 소개합니다
- 원클릭으로 설치하는 스킬로 제공되어 Claude Code, Claude Cowork, Codex 같은 에이전트에 쉽게 연결됩니다
- 사용 방식은 먼저 LightParse로 모든 문서를 빠르게 훑고, 표나 차트처럼 값을 깊이 이해해야 하는 페이지에서만 LlamaParse 같은 VLM 기반 도구를 쓰는 것입니다

### 정보 추출과 문서 검색

- 송장, 경비 보고서, 영수증, 보험금 청구 등을 대규모로 처리해 하위 시스템에 넣을 구조화된 출력을 얻는 기능이 LlamaParse에 있습니다
- 저비용과 높은 정확도에 맞춰 조율되어 있고, 추출된 모든 값에 원본 문서까지 거슬러 올라가는 세밀한 인용이 붙으며, 신뢰도 점수로 불확실한 값을 시스템에 넣기 전에 표시할 수 있습니다
- 문서 검색은 BM25, grep, 벡터 검색, 읽기와 스크롤을 포함하는 확장된 도구 세트입니다
- 이 기능들은 상용 플랫폼과 오픈소스 제품에서 모두 쓸 수 있습니다. 나머지 미래 주제는 시간 관계상 건너뛰었고 슬라이드를 온라인에 공유하겠다고 합니다
