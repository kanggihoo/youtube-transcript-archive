# 에이전트는 목표를 받아 허용된 도구로 시스템을 조회하고 다음 행동을 정하는 AI이며, 금융권에서는 자율성보다 권한·감사·통제가 우선이다. MCP는 에이전트와 사내 시스템 사이의 연결을 표준화할 수 있지만, 사내망과 보안 검토 때문에 외부 서버를 곧바로 연결하는 방식은 어렵고 내부 검증 도구 생태계가 더 중요할 수 있다.

## 챗봇에서 도구를 쓰는 에이전트로

기존 챗봇은 입력된 정보로 답하지만 에이전트는 메일, 일정, 업무 시스템 등 허용된 도구를 호출하고 결과를 확인하며 절차를 진행한다. 금융 업무에서는 규정·상품 검색이나 문서 분류·정보 추출처럼 사람의 결정을 보조하는 방식이 현실적이다.

## MCP가 줄이는 연결 복잡도

에이전트 10개와 시스템 10개를 각각 연결하면 100개 연동이 필요하지만, 양쪽에 MCP 표준 인터페이스를 두면 영상의 예시에서는 20개로 줄어든다. 공통 문서 검색, 지식 검색, 업무 조회 도구를 여러 에이전트가 재사용할 수 있다.

## 금융권의 통제와 내부 MCP

사내망에서 외부 MCP 서버에 접근할 수 있는지, 권한과 감사 기록을 어떻게 관리할지 검토해야 한다. 따라서 외부 도구를 자유롭게 연결하기보다 내부에서 검증되고 승인된 문서 검색·업무 조회 도구를 MCP로 표준화하는 것이 실질적인 가치가 될 수 있다. 에이전트의 권한 범위와 사람이 승인해야 할 동작을 명확히 해야 한다.
