# 한국어 번역

데모에서 한 번 작동하는 AI 에이전트를 만드는 것과 실제 작업을 끝내는 에이전트를 만드는 것은 다릅니다. 코딩 에이전트는 저장소를 읽고 여러 파일을 바꾸고 테스트를 실행하며 실패를 고쳐야 합니다. 다른 에이전트는 도구와 웹사이트를 사용하거나 구조화된 데이터를 반환하고, 사용자가 전에 말한 내용을 기억해야 할 수도 있습니다. 모델은 시스템의 한 부분일 뿐입니다. 나머지를 돕는 오픈소스 프로젝트 10개를 소개합니다.

## 1. OpenHands — 실제 저장소에서 코딩 작업

에이전트에게 GitHub 이슈를 주고 버그를 고치라고 하면 저장소를 읽고 파일을 찾고 변경을 만들고 테스트를 실행하며 실패가 나면 계속 작업해야 합니다. OpenHands는 에이전트가 코드를 살펴보고 파일을 편집하고 명령을 실행하며 작업을 진행할 도구와 작업 공간을 제공합니다. OpenHands Software Agent SDK로 이런 코딩 에이전트를 만들 수 있고, 로컬 환경이나 격리된 작업 공간에서 실행할 수 있습니다.

## 2. OpenAI Agents SDK — 에이전트 루프와 핸드오프

자체 앱 안에서 에이전트를 만들고 지시를 따르며 도구를 호출하고 결과를 받아 계속 작업하게 할 때 사용하는 SDK입니다. 도구, 핸드오프, 가드레일, 세션, 추적 기능 등 실행에 필요한 구성요소를 제공합니다. 개발자는 에이전트가 할 수 있는 일과 사용할 도구를 정의하고 SDK는 상호작용을 실행합니다.

## 3. Google ADK — 여러 단계를 순서대로 실행

정보 수집, 결과 검토, 최종 답변 작성 등 여러 단계를 가진 에이전트와 워크플로를 만들기 위한 개발 키트입니다. 하나의 큰 프롬프트에 절차를 모두 넣는 대신 에이전트, 도구, 작업 순서를 정의해 워크플로를 명시적으로 구성합니다.

## 4. Pydantic AI — 문단 대신 타입이 정해진 출력

지원 요청 시스템에서 우선순위, 범주, 요약처럼 특정 필드가 필요한 경우 출력 형식을 타입이 있는 모델로 정의해 나머지 애플리케이션에서 쓰기 전에 검증합니다. 구조화된 출력, 도구 등 타입 기반 에이전트 앱 개발 기능을 제공합니다.

## 5. Browser Use — 브라우저를 인터페이스로 사용

필요한 시스템이 웹사이트이고 편리한 API가 없을 때 에이전트가 브라우저에서 페이지를 이동하고, 컨트롤을 누르고, 정보를 입력하고, 결과를 읽도록 합니다. 웹사이트는 바뀔 수 있고 접근이 제한될 수도 있으므로 안정적인 API가 있다면 브라우저 자동화가 이를 대체하지는 않습니다.

## 6. GitHub Spec Kit — 코드보다 요구사항 먼저

코딩 에이전트가 요구사항을 제대로 이해하기 전에 구현부터 시작하는 문제를 줄이기 위해 개발 절차를 추가합니다. 만들 것을 설명하고 기술 계획을 세운 뒤 작업 목록을 나누고 구현합니다. 에이전트 런타임이라기보다 에이전트가 코드를 바꾸기 전에 명확한 요구사항과 작업을 마련하는 도구입니다.

## 7. LiteLLM — 모델 라우팅과 대체 경로

어려운 작업에는 한 모델, 단순한 작업에는 다른 모델을 사용하거나 제공자 장애에 대비한 대체 경로를 두고 싶을 때 모델 제공자들을 공통 인터페이스로 연결합니다. 이 인터페이스를 통해 뒤에서 모델을 바꾸고 라우팅, 대체 경로, 비용 제어를 추가할 수 있습니다.

## 8. Letta — 현재 대화를 넘어서는 메모리

사용자가 오늘 알려준 정보를 다음 주에도 에이전트가 기억해야 하는 경우를 다룹니다. 상호작용 사이에 메모리와 정체성을 유지하는 상태 기반 에이전트를 중심으로 설계해 같은 사용자와 계속 일하는 비서에 활용할 수 있습니다.

## 9. DSPy — 작업을 프로그램으로 정의하고 최적화

프롬프트를 쓰고 결과를 본 뒤 수동으로 고치는 대신 작업을 프로그램으로 정의하고 단계별로 나눕니다. 예시와 평가 결과를 활용해 프로그램을 개선합니다. 결과를 측정하고 최적화해 프롬프트를 매번 손으로 다시 쓰는 부담을 줄이려는 방식입니다.

## 10. Promptfoo — 사용자에게 닿기 전에 에이전트 테스트

프롬프트, 모델, 도구가 바뀔 때 결과도 바뀔 수 있습니다. Promptfoo는 같은 평가를 반복 실행해 시스템 변경 후 동작이 달라졌는지 확인하게 합니다. 같은 테스트를 실행해 사용자에게 문제가 닿기 전에 회귀를 찾는 데 쓸 수 있습니다.

에이전트를 만드는 일은 문제의 일부입니다. 도구 제공, 애플리케이션에 맞는 출력 보장, 웹사이트 사용, 여러 모델, 메모리, 코딩 작업, 테스트도 고려해야 합니다. 한 프로젝트에서 10개를 모두 쓸 필요는 없지만 에이전트가 실제 일을 맡기 시작하면 이런 문제를 만나게 됩니다.
