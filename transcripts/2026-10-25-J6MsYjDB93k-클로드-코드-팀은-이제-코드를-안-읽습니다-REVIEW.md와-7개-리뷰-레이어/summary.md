# 클로드 코드 팀은 이제 코드를 안 읽습니다 | REVIEW.md와 7개 리뷰 레이어

## 결론부터

개발동생은 Claude Code 팀이 공개한 코드 리뷰 방식을 7개 레이어로 풀어 설명하고 자기 프로젝트에 들이는 4단계를 제안합니다. 결론은 어떤 리뷰도 모든 것을 잡지 못하므로 검증 단계를 겹쳐 쌓고, 사람은 위험이 큰 판단에만 쓰되 AI 리뷰어 자체도 검증해야 한다는 것입니다.

## 핵심 내용

- 발표자가 전하는 Claude Code 팀의 수치는 6~9월 머지된 PR이 2배 넘게 늘고 머지 후 되돌린 비율이 약 40% 줄었으며, 라운드 반복을 줄인 뒤 한 번에 통과하는 비율이 65%에서 78%로 올랐다는 것입니다.
- 7개 레이어는 다음과 같습니다. ① PR 전 에이전트 자체 검증과 별도 서브에이전트 리뷰 ② 모든 PR에 AI 코드 리뷰(버그 찾는 에이전트와 진위 확인 에이전트 분리) ③ 보안 리뷰 ④ 필수 CI ⑤ 위험도 분류에 따른 사람 승인(낮음 0명, 중간 1명, 높음 2명, PR 작성자도 인원에 포함 가능) ⑥ 머지 큐와 기능 플래그, 릴리스 채널 ⑦ 배포 후 모니터링, 온콜, 플래그를 끄는 긴급 스위치.
- 사고와 되돌려진 PR을 AI 리뷰어의 "기출 문제집"(eval 데이터셋)으로 쌓아 프롬프트·모델이 바뀔 때마다 다시 풀게 하고, 리뷰 코멘트에 단 해결 답글도 오탐 여부를 가르는 평가 데이터로 쓰라고 합니다. REVIEW.md는 무엇을 지적하고 무엇을 넘길지 적는 파일입니다.

## 배울 점과 적용 조건

- 처음부터 전부 만들지 말고 4단계로 시작합니다. PR 템플릿에 Testing·Risk·How to revert 필드 추가, 모든 PR에 AI 리뷰·보안 리뷰·필수 CI 추가, 실제 리뷰 코멘트를 보고 REVIEW.md·lint·테스트 보강, 배포 후 복구 설계입니다. 사람 승인은 처음엔 엄격하게 두고 안정되면 풀라고 권합니다.
- REVIEW.md는 오픈 표준이 아니며, 발표자에 따르면 GitHub 연동 코드 리뷰에서만 적용되고 로컬 `/code-review`에는 적용되지 않으므로 직접 읽게 지시해야 합니다.
- CI에서 보안 리뷰를 자동 실행하면 API 키 종량 과금이 붙습니다. 발표자는 24시간 켜 둔 맥 미니를 GitHub Actions 러너로 등록해 구독 요금제로 돌린다고 합니다.

## 근거와 한계

- **영상의 근거:** Anthropic 팀의 공개 수치 인용과 발표자 본인의 사용 경험(전 팀의 유사 정책, 맥 미니 러너)입니다. 화면 시연이나 자체 측정 결과는 자막에서 확인되지 않습니다.
- **평가:** 레이어 구성은 일관되고 같은 주제의 다른 영상(`S49gppZl8H0`)과 겹치는 부분이 많습니다. 다만 "PR 2배, 되돌림 40% 감소" 같은 수치는 조건과 비교 기준이 영상에 없고, 발표자 스스로도 보안 리뷰가 모든 문제를 잡는다고 보장하기 어렵다고 말합니다. 제목의 "코드를 안 읽습니다"는 영상 내용(저위험 PR에서 사람 승인 생략)보다 강한 표현입니다.
- **확인 범위:** 자막 기반 평가이며 Anthropic 원문은 확인하지 않았습니다. 수치와 REVIEW.md 적용 범위(GitHub 연동만)는 영상 내 주장, 외부 미검증입니다.
- **홍보성:** 길벗출판사의 도서 협찬이 설명란과 영상 중간(약 1분)에 고지되어 있고 도서 증정 이벤트가 있습니다. 광고 구간은 본문과 분리되어 있으며 기술 설명에는 영향이 없어 보입니다.
