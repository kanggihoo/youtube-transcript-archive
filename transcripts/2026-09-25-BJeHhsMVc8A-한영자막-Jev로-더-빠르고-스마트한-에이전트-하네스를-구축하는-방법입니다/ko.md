# 한국어 번역

저는 LangChain 오픈소스 팀의 제품 관리자 Sydney입니다. TypeSafe AI의 새 모델 Jev로 에이전트 하네스를 만드는 방법을 소개하겠습니다.

## 에이전트 루프와 구조화 출력

요청을 LLM에 보내면 도구를 호출하고 결과를 받아 처리합니다. 도구 호출 루프를 계속하거나 작업이 끝났다고 판단해 결과를 반환합니다. 이 루프는 강력하지만 LLM은 텍스트를 받아 텍스트를 생성하므로 예측하기 어렵습니다. 코드 기반 애플리케이션은 원시 텍스트가 아니라 구조화된 타입에 의존하므로 도구 호출과 구조화 출력을 사용합니다. 도구 호출은 ID를 포함한 주문 조회 요청처럼 구조화된 요청을 보내고 도구는 구조화된 데이터를 반환합니다. 구조화 출력은 JSON 스키마를 지정해 최종 결과를 그 형식에 맞춥니다.

## Jev는 시스템 1 의사결정 모델

Jev는 TypeSafe AI의 시스템 1 모델입니다. 시스템 1 모델은 상태와 질문을 입력받아 소프트웨어에서 직접 사용할 수 있는 타입이 지정된 답과 확률을 반환합니다. 전통적인 LLM처럼 텍스트를 받아 텍스트를 생성하는 방식은 아닙니다. 발표자는 분류 작업에서 LLM보다 20~200배 빠르고 40~400배 저렴할 수 있다고 소개하지만, Jev는 LLM을 그대로 대체하는 모델이 아니라 특화된 판단 작업을 맡는 도구입니다.

시스템 1이라는 이름은 Daniel Kahneman의 《생각에 관한 생각》에서 가져왔습니다. 빠르고 저렴한 직관의 시스템 1과 느리고 비싼 추론의 시스템 2를 대비합니다. 영상의 PII 분류 데모에서 LLM은 구조화 답변까지 약 5초 걸렸고, Jev는 거의 즉시 개인정보가 포함됐을 확률 98%를 반환했습니다.

## Jev가 다루는 질문 유형

Stripe 연결이 3일째 실패해 매출을 잃고 있으니 도와달라는 고객 메시지를 예로 듭니다.

- **선택**: 어느 팀이 처리할지 고릅니다. Billing 점수는 0.84, 신뢰도는 0.596입니다.
- **점수**: 고객이 얼마나 화났는지 같은 척도형 판단을 냅니다. 예에서는 불만스럽지만 매우 화난 수준은 아니라고 평가합니다.
- **불리언**: 메시지가 긴급한지 예/아니요 판단을 합니다. 예의 긴급성 확률은 0.999입니다.

상태 하나에 질문 여러 개를 넣으면 Jev가 병렬로 답할 수 있어 여러 질문에서 효율적이라고 발표자는 설명합니다.

## LangChain 통합과 활용

LangChain Type-Safe 통합에서 Type-Safe 분류기를 가져오고 API 키를 발급받은 뒤 상태와 질문을 넣어 Jev를 호출할 수 있습니다.

### 모델 라우팅

간단한 작업과 복잡한 작업에 모두 가장 강력한 모델을 쓸 필요는 없습니다. LangChain 팀은 작업의 복잡도에 따라 빠르고 저렴한 모델과 강력하고 비싼 모델을 바꾸는 내부 코딩 에이전트를 시험하고 있습니다. Jev는 거의 즉시 프롬프트를 기준에 맞춰 평가해 모델을 고를 수 있습니다.

### 위험한 도구 호출 차단

LangChain의 자동 모드 미들웨어는 도구 호출이 위험한지 Jev로 판단하고 실행 시점에 차단할 수 있습니다. 발표자는 기존 위험 분류가 느려 코딩 에이전트에서 자동 모드를 껐지만, Jev가 빨라 다시 켰다고 말합니다. 데이터베이스나 중요한 파일 삭제 호출을 위험하다고 분류해 막는 예를 듭니다.

### 온라인 평가 심사

대규모 평가에서 모든 실행 기록을 사람이 검토하기는 어렵습니다. 입력과 에이전트 답변에 채점 기준을 함께 제공하면 Jev가 정답 여부, 참조 일치, 근거 여부, 출처 인용 여부를 기준별로 점수화할 수 있습니다. 발표자는 LangChain 블로그의 결과를 인용하며 Jev가 LLM 심사자보다 저렴하고 빠르며 평가 간 신뢰성과 일관성이 더 높았다고 주장합니다.

LangChain Type-Safe 패키지는 `uv pip install langchain-typesafe`로 시작할 수 있으며 TypeSafe에서 API 키를 얻습니다.
