# Pstack은 과한 오버스펙일까요? 그래도 써봐야 하는 이유

## 한 줄 요약

Cursor와 React 코어 출신 Lauren Tan이 만든 Pstack은 사후 기획 대신 코드로 증명하며, 다중 모델 경쟁(Arena)과 자체 실행형 검증 스크립트로 비결정론적 AI의 환각을 철저히 차단하는 프로덕션급 에이전트 엔지니어링 프레임워크다.

## Pstack의 핵심 아키텍처와 라우팅

- **Potato Mode 라우터**: 사용자 프롬프트를 분석해 20여 개 이상의 전문 스킬과 22개 플레이북 중 최적의 실행 경로를 자동 결정
- **기획 없는 코드 중심주의**: "기획을 믿지 않으며, 최고의 명세는 코드다"라는 철학 하에 탁상공론식 계획 스킬을 배제하고 즉시 코드 탐색(Probing)과 현실 충돌을 통해 설계를 진화
- **두려움 없는 병렬성 (Fearless Parallelism)**: Git 워크트리와 브랜치 격리를 바탕으로 다중 에이전트 작업을 충돌 없이 취합

## 실전에서 빛나는 차별화 스킬들

| 스킬명 | 핵심 역할 | 실무 가치 |
|---|---|---|
| **Arena** | 3~4개의 이종 모델(Claude, GPT, Grok 등)을 동일 문제에 투입해 경쟁 | 각 모델의 최상 장점만 선별 접목(Graft)하여 최고 품질 커밋 완성 |
| **Why** | PostHog, Slack, Sentry, ADR 문서를 MCP로 통합 추적 | 단순 코드 히스토리를 넘어 "왜 그렇게 결정했는가"의 비즈니스·아키텍처 맥락 복원 |
| **Recall** | 프로젝트 장기 중단 후 복귀 시 작업 상태 스캔 | 어디까지 진행되었고 다음 단계가 무엇인지 즉각 파악 |
| **Interrogate** | 다중 모델을 투입해 작성된 코드를 상호 교차 심문 | 엄격한 품질 표준 검증 및 잠재 결함 적발 |
| **Create Verification** | 애플리케이션 동작을 실제로 입증하는 전용 스크립트 작성 | 비결정론적 LLM의 할루시네이션 및 가짜 정상 동작(False Green) 원천 차단 |
| **Bro / Onslaught** | 복잡한 에이전트 로그를 쉬운 일상어로 재해석 / AI 특유의 클리셰 문체 제거 | 개발자 인지 과부하 완화 및 깔끔한 문서화 지원 |

## 핵심 엔지니어링 6대 원칙

1. **게으름 프로토콜 (Laziness Protocol)**: 코드를 더 작성하기보다 과감히 삭제하고, 목표 달성을 위한 최소 변경으로 유지보수성 극대화
2. **제1원칙 재설계 (Redesigning from First Principles)**: 기능 추가 시 덧붙이기(bolt-on) 대신, 첫날부터 이 기능을 지원했다면 어떻게 설계했을지 고민하여 구조 단순화
3. **독자 부담 최소화 (Minimizing Reader Load)**: 불필요한 추상화를 걷어내고 에이전트 PR의 가독성을 극대화
4. **설계 공간 소진 (Exhaust the Design Space)**: 여러 대안을 먼저 탐색한 뒤 가장 검증된 설계안 채택
5. **지렛대 구축 (Build a Lever)**: 반복 수작업을 에이전트에게 시키는 대신 전용 CLI나 자동화 스크립트를 빌드하여 활용
6. **컨텍스트 윈도우 보호**: 메인 스레드를 오염시키지 않도록 서브 에이전트에게 독립 윈도우를 배분하고 결과만 취합

## 비용 대 효용 분석

Pstack은 일반 단독 프롬프트 대비 시간은 2배, 토큰 비용은 수배 이상 소모합니다. 따라서 단순 UI 수정이나 빠른 프로토타입에는 과하지만, 안정성이 절대적인 프로덕션 백엔드 및 대규모 코드베이스에서는 투입 비용 이상의 무결성을 보장합니다.
