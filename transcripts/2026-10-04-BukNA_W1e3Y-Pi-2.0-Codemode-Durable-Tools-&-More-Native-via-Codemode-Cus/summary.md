# Pi 2.0 (Codemode, Durable Tools & More!): Native via Codemode, Custom Model Routing & Pi Durable

## 한 줄 요약

오픈 소스 에이전트 하네스 Pi 1.0은 code mode로 MCP를 네이티브 지원하고, 모델 라우팅과 지연 도구 로딩으로 메인 모델에 닿는 작업량을 줄이며, 별도 패키지 Pi durable로 재시작을 넘어 이어지는 장기 대화의 기반을 제공합니다. 발표자는 매번 "실제 작업에서 정확도, 재시도, 총비용을 재보라"고 단서를 붙입니다.

## code mode: MCP를 스크립트 뒤로 숨긴다

Pi는 그동안 네이티브 MCP를 일부러 넣지 않았습니다. MCP 통합이 도구 설명과 큰 결과를 모델 컨텍스트에 쏟아붓는다는 비판 때문입니다. 새 접근은 에이전트가 작은 JavaScript 프로그램을 써서 도구를 호출하고 결과를 합친 뒤 필요한 출력만 돌려주는 것입니다.

- 중간 데이터는 스크립트 안에 머물고, 대화로 얼마나 돌려보낼지는 사용자가 정합니다
- 호출 사이에 유지할 JSON은 명시적 저장 헬퍼를 씁니다. 일반 변수는 실행 사이에 살아남지 않습니다
- JavaScript는 샌드박스지만 호출하는 도구의 권한은 그대로입니다. 중간에 실패해도 이미 끝난 호출은 취소되지 않아 오류 처리가 필요합니다
- 로컬(표준 입출력)과 원격(HTTP) MCP 서버, 사용자 수준과 프로젝트 수준 설정, OAuth를 지원하고 code mode 노출이 기본값입니다
- 이미 쓰는 통합 하나로 범위가 정해진 작업(예: 릴리스의 미해결 이슈 수집)부터 시작하라고 권합니다

code mode로 접근하는 전문 모델도 있습니다. 분류기 Jev는 구조화된 상태와 질문을 받아 선택, 예/아니오, 확률 점수를 돌려줍니다. 이미지 모델은 프롬프트와 참조 이미지를 받습니다. 둘 다 일반 모델 선택기에 나오지 않고, 확률은 모델의 판단이라 표본 검증이 필요하며, 생성 이미지는 자동 저장되지 않습니다.

## 가상 모델과 지연 도구 로딩

- **가상 모델(라우터)**: 익스텐션이 선택 가능한 모델 하나를 등록하고 요청마다 실제 모델과 사고 수준을 고릅니다. 어려운 계획에는 강한 모델, 일상 구현에는 싼 모델을 쓰는 식입니다. 단점은 모델을 바꾸면 프롬프트 캐시 재사용을 잃을 수 있고 분류기가 지연을 더한다는 점이라, 단일 모델 기준선과 비교하라고 합니다. 데모는 Opus로 계획하고 GPT 6 Luna로 구현하며 Jev가 전환 시점을 정합니다
- **지연 도구 로딩**: 도구를 직접 선언, code mode 경유, 검색으로 찾아 활성화하는 지연 도구로 나눕니다. 관련 없는 서비스의 선언을 미리 싣지 않아 컨텍스트를 아낍니다. 도구 설명 품질이 발견 성공을 좌우하므로 정확한 이름이 없는 평범한 요청으로 시험하라고 합니다

## 캐시 워밍과 세션 이력

- **캐시 워밍**: 긴 도구 실행이 프롬프트 캐시보다 오래 갈 때 Pi가 갱신을 보냅니다. 캐시 미스로 아끼는 비용이 5센트 이상일 것으로 추정될 때만 하고, 사용량은 세션 합계에 포함됩니다. 유휴 워밍은 선택이며 `/session`에서 다음 결정을 볼 수 있습니다
- **대화 중간 시스템 메시지**: 지침이나 도구가 바뀐 시점을 기록하고, 세션 재개나 브랜치 이동 때 그 시점의 프롬프트와 도구 상태를 재구성합니다. 지원되는 모델에서는 이전 캐시 접두부 보존에도 도움이 되지만 제공자별로 확인해야 합니다

## 터미널과 최종 1.0의 잔 변경

- 새 기본 테마 `system`이 터미널의 전경·배경·ANSI 색을 읽어 대비를 조정하고, 라이트/다크 전환도 따라갑니다
- 전체 화면 모드가 기본이 되어 편집기와 상태 영역이 고정됩니다. `/settings`나 시작 플래그로 일반 스크롤백 모드로 돌아갈 수 있습니다
- GPT 5.6 요청의 프롬프트 토큰이 기본 도구와 code mode 기준 약 5,300에서 3,300으로 줄었다는 팀 보고(약 40%). 모든 작업의 총비용이 그만큼 준다는 뜻은 아닙니다
- code mode 오류에 복구 힌트, Anthropic 코드 복사 로그인, 더 강한 MCP 인증 검사, 조용한 시작 옵션

## Pi durable: 재시작을 견디는 대화

코딩 에이전트와 별개인 실험적 패키지로, 장기 에이전트 대화를 가진 애플리케이션을 만들기 위한 기반입니다.

- 하네스 하나가 여러 대화를 동시에 돌리고, 대화마다 모델·도구·지침·작업 디렉터리가 다릅니다. 포크가 가능하고 여러 클라이언트가 같은 하네스에 붙어 조종할 수 있습니다
- 체크포인트를 저장해 프로세스가 멈춘 뒤 새 프로세스가 재개합니다. 중단된 도구는 재실행이 안전하다고 선언한 경우에만 자동 재실행되고, 아니면 에이전트가 중단 사실과 그때까지의 출력을 받습니다. 같은 요청 ID는 중복 접수를 막지만 외부 동작이 정확히 한 번 일어난다는 보장은 아닙니다
- 저장소는 메모리(재시작 불가), SQLite, JSONL. 한 번에 한 프로세스만 백엔드를 소유하고, 기본 SQLite는 전원 장애에서 최신 커밋을 보장하지 않으며, API는 실험적입니다. 컨텍스트 한계는 그대로라 압축 예제가 따로 있습니다
- 영속 백그라운드 서브에이전트, 진행 중인 도구 호출은 원래 구현으로 끝내고 이후 호출만 교체본을 쓰는 확장 갱신 예제가 있습니다. 발표자는 이것들이 구성 요소이며 믿을 만한 서비스로 만들려면 엔지니어링이 필요하다고 봅니다

## 설치와 비용

`pi.dev`의 설치 프로그램이나 npm(Node 22.19 이상)으로 설치하고, `pi --version` 확인 후 `/login`으로 계정이나 API 키를 연결하고 `/model`로 모델을 고릅니다. 첫 작업으로는 프로젝트 구조와 검사 실행법을 설명시키라고 합니다. Pi와 Pi durable 모두 MIT 라이선스지만 모델·서비스 비용은 따로 듭니다. 메인 모델, 분류기, 이미지 생성, 라우터를 합친 세션 전체 비용을 봐야 한다고 강조합니다.

## 발표자의 판단 기준

가장 마음에 든 점은 메인 모델에 닿는 작업량을 통제할 수 있다는 것입니다. 커스텀 워크플로를 유지할지는 답이 정확한가, 재시도가 줄었나, 총비용이 내려갔나로 정하라고 합니다. 전용 plan 모드와 서브에이전트 워크플로는 여전히 익스텐션이나 패키지의 몫이라, 바로 쓰고 싶은 워크플로가 있으면 제공 여부를 먼저 확인하라고 합니다.
