# 36%에서 100%로: 자기 개선 에이전트는 어떻게 스스로 스킬을 작성할까요? — Runlayer Rafal Wilinski

## 한 줄 요약

Runlayer의 Rafal Wilinski는 에이전트의 성공·실패 실행 기록에서 스킬을 자동으로 증류하고 MCP로 회사 전체에 배포하면, 에이전트 하나의 성공률(36%에서 100%)뿐 아니라 조직 전체의 학습 순환이 생겨 경쟁사가 복제할 수 없는 해자가 된다고 주장합니다.

## 스킬이 중요하고, 문제도 있는 이유

- 에이전트가 오래 일할 수 있게 될수록 잘못된 방향으로 깊이 파고들 위험도 커져서, 초기 궤적을 잡아 주는 스킬이 시간, 토큰, 돈을 아껴 줍니다
- 가치 있는 스킬은 롤백 절차나 이탈 고객 응대 문구처럼 회사 깊숙이 박힌, 아무도 다시 발견하고 싶지 않은 지식입니다
- 스킬의 세 가지 문제는 로컬 우선이라 개발자 중심이라는 점, 플레이북을 남기는 데 노력이 든다는 점, 모든 LLM 클라이언트가 스킬을 지원하지는 않는다는 점입니다
- `npx skills` 같은 설치 방식에는 프롬프트 인젝션이나 과도한 권한 요구가 섞일 수 있다고 발표자는 경고합니다

## MCP를 스킬 배포 계층으로

- 스킬은 지식을, MCP 도구는 역량을 줍니다. MCP는 스킬을 전달하는 프로토콜로도 쓸 수 있습니다
- 원격 MCP 서버를 회사의 단일 진실 공급원으로 두면 비기술 직군의 클라이언트까지 지원하고, 정책 강제와 역할별 최적 버전 제공, 중앙 관리가 가능합니다
- Skills over MCP 워킹 그룹이 있고 공식 스펙은 리소스 쪽이지만 지원이 들쭉날쭉해 Runlayer는 도구 방식을 씁니다

## Voyager에서 배운 자기 개선

- 2023년 Voyager는 마인크래프트에서 발견한 것을 도구 호출 코드 형태의 스킬 라이브러리에 저장해 재사용했습니다. 핵심은 탐험을 재사용 가능한 절차적 지식으로 바꾸는 것입니다
- Runlayer는 성공한 실행 기록을 최전선 LLM에 넘겨 스킬을 증류하며, 성공은 스킬의 신뢰도를, 실패는 빠진 안전장치와 예외 상황을 보강합니다. 사람의 개입 없이 비동기로 돌아갑니다
- 사례: Sonnet 4.6으로 AWS Lambda에서 Chromium 포크를 돌리는 과제가 성공률 36%였는데, 한 실행이 해법을 찾아 스킬이 되자 이후 100%가 됐습니다. 탐색 공간이 줄어 토큰과 비용도 줄었습니다
- 최전선 지능은 빌려 쓰는 것이라 사라지거나 나빠질 수 있으니, 쓸 수 있을 때 쓸모 있는 절차를 증류해 두어야 한다는 논리입니다

## 조직 단위의 학습 플라이휠

- 비슷한 실행을 묶어 스킬을 증류하고, 프롬프트 인젝션과 PII 등을 검사한 뒤 스킬 라이브러리에 올리고, MCP 게이트웨이로 모든 클라이언트와 에이전트에 제공합니다
- 한 에이전트가 푼 어려운 문제가 조직 전체의 플레이북이 되어 같은 문제를 다시 풀 필요가 없어집니다
- 모델이 범용품이 되는 시대에 해자는 이 플라이휠로 쌓은, 통제되고 복리로 쌓이는 회사 고유의 지식이라고 발표자는 말합니다. 모델 지능 지원 중단에 대비하고 모델을 바꾸지 않고 비용을 낮추는 효과도 있습니다
