# 자바 생태계 전체를 18분 만에 설명합니다

## 한 줄 요약

자바는 언어 하나가 아니라 컴파일러(javac)·JVM·JDK·프레임워크·빌드 도구·테스트·버전 정책이 맞물린 생태계이고, 각 구성 요소가 어떤 문제를 푸는지만 알면 JDK, JVM, Maven, Spring 같은 이름들이 복잡해 보이지 않는다는 입문 설명입니다.

## 코드가 실행되는 경로

- 소스(.java)를 javac가 컴파일해 기계어가 아닌 바이트코드(클래스 파일)를 만듭니다. 정적 타입이라 일부 오류를 실행 전에 잡지만 논리 오류와 런타임 오류까지 막지는 못합니다
- JVM이 바이트코드를 각 OS와 프로세서에서 실행해 주므로 보통 플랫폼마다 다시 컴파일하지 않습니다. 이것이 이식성("한 번 작성하면 어디서나 실행")의 토대입니다
- 자주 실행되는 코드는 JIT 컴파일로 기계어로 바뀌어 오래 도는 애플리케이션의 성능이 좋아집니다. 다만 짧게 사는 프로그램에서는 시작 시간과 메모리가 여전히 문제일 수 있습니다

## JVM, JRE, JDK는 무엇이 다른가

- JVM은 바이트코드를 실행하고, JRE는 JVM에 런타임 라이브러리를 더한 실행 환경이며, JDK는 컴파일러 등 개발 도구까지 담은 것입니다
- 최신 배포판은 JRE를 따로 주지 않는 경우가 많아, 학습과 개발에는 JDK를 설치하면 됩니다
- OpenJDK 빌드는 Oracle, Eclipse Temurin, Amazon Corretto 등 여러 곳에서 배포하며 라이선스·지원·업데이트 정책이 다릅니다. 평판 좋은 배포판을 고르고 프로젝트가 지원하는 버전을 쓰라고 합니다

## 메모리와 동시성

- 객체는 힙에 쌓이고 가비지 컬렉터가 도달할 수 없는 객체를 회수합니다. 그래도 계속 커지는 캐시처럼 참조를 쥐고 있으면 메모리 누수가 생깁니다
- 배열 범위 검사 같은 런타임 검사가 많은 메모리 오류를 막아 주지만 애플리케이션이 자동으로 안전해지는 것은 아닙니다
- GC마다 성격이 달라, G1은 범용 균형형이고 ZGC는 큰 힙에서도 멈춤 시간이 매우 짧습니다
- 자바 21의 가상 스레드는 DB나 외부 서비스를 기다리는 시간이 긴 작업을 아주 많이 동시에 처리할 때 유용합니다. CPU 연산을 빠르게 하거나 DB 병목을 없애 주지는 않습니다

## 라이브러리, 프레임워크, 데이터 접근

- 라이브러리는 내 코드가 호출하는 기능(예: JSON 변환의 Jackson)이고, 프레임워크는 구조를 제공하며 적절한 때에 내 코드를 호출합니다
- Spring의 핵심은 의존성 주입이고, Spring Boot는 기본값과 자동 구성으로 설정 부담을 줄여 현대 자바 백엔드의 흔한 출발점이 되었습니다. Quarkus와 Micronaut은 시작 시간과 자원 사용량 개선을 겨냥한 대안입니다
- DB는 표준 API인 JDBC로 접근하고, Hibernate는 객체와 레코드를 매핑(ORM)하며, Spring Data가 흔한 작업을 더 단순하게 해 줍니다

## 빌드 도구와 의존성 보안

- 라이브러리는 JAR로 배포되고 Maven Central 같은 저장소에 올라 있습니다. Maven(pom.xml)과 Gradle이 내려받기, 전이 의존성 해결, 컴파일, 테스트, 패키징을 자동화합니다
- 2021년 12월 Log4Shell은 Log4j의 취약점이 다른 라이브러리를 통해 간접 포함된 채 전 세계에 퍼진 사례입니다. 의존성 목록 관리, 취약점 스캔, 업데이트가 필요하며 자바의 메모리 안전 기능은 라이브러리 취약점까지 막아 주지 못합니다

## Kotlin, 테스트, 도구

- JVM에서는 Kotlin 같은 다른 언어도 돌아가며 자바와 상호 운용됩니다. 구글은 새 안드로이드 개발에 Kotlin을 우선 언어로 권장하지만 안드로이드 앱은 표준 JVM이 아니라 자체 런타임 ART에서 실행됩니다
- 테스트는 JUnit과, 의존성을 모의 객체로 바꾸는 Mockito를 씁니다(결제 테스트에서 실제 카드 대신 모의 서비스를 쓰는 식). 도구로는 JDK 내장 JShell, IntelliJ IDEA, Eclipse, VS Code가 있습니다

## 버전 고르기와 자바가 맞는 곳

- 자바 10부터 6개월 주기로 릴리스하며 일부가 LTS입니다. 초보자에게는 LTS가 무난하고, 프로젝트가 요구하는 버전과 지원 여부를 확인해야 합니다. 옛 시스템에는 자바 8이 아직 많고, 일부 엔터프라이즈 API는 javax에서 Jakarta로 옮겨 갔습니다
- 엔터프라이즈, 금융, 백엔드 서비스, 데이터 인프라에 잘 맞습니다. 극도로 낮은 메모리, 아주 작은 배포 크기, 매우 빠른 시작 시간이 최우선이면 최선이 아닐 수 있습니다
- 결론은 모든 기술을 외우기보다 각 구성 요소의 역할부터 이해하라는 것입니다
