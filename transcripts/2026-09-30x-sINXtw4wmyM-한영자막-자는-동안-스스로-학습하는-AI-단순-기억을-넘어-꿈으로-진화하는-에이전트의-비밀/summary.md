# 자는 동안 스스로 학습하는 AI: 단순 기억을 넘어 꿈으로 진화하는 에이전트의 비밀

### 한 줄 요약

에이전트의 메모리는 마크다운 파일 시스템에 버저닝·해시 기반 동시성 제어·권한·이식성 같은 안전장치를 더해 프로덕션에 올리고, 세션 밖에서 배치로 트랜스크립트를 분석해 메모리를 고치는 '드리밍'을 더하면 에이전트가 세션을 넘어 계속 학습한다.

### 컨텍스트 엔지니어링의 1년: 통하는 단순한 것부터

발표자는 Anthropic 응용 AI 팀의 Lamis로, 모델 지능은 조직 고유의 컨텍스트 없이는 복리로 불어나지 않는다고 본다. 흐름은 CLAUDE.md(단순하지만 터무니없이 효과적이나 길어지면 비대해짐) → 에이전트가 세션 안에서 스스로 읽고 쓰는 메모리 도구 → 점진적 공개로 컨텍스트 문제를 푸는 스킬(다만 무엇에 스킬이 필요한지는 사람이 정함) → 현재 최선이라고 보는 **파일 시스템으로서의 메모리**다. 마크다운으로 채우고, 에이전트가 bash·grep으로 검색하게 하며, 색인을 잘 두고, 쓰기는 에이전트에게 자율권을 준다.

### 프로덕션에서 터지는 문제와 네 가지 원칙

여러 에이전트의 동시 쓰기, 조직 전체 컨텍스트 오염, 사람·에이전트 협업 추적, 낡거나 악의적으로 주입된 메모리가 문제다. 대응 원칙은 다음과 같다.

- **버저닝**: 롤백할 수 있게 하고, 어느 세션·트랜스크립트에서 나온 변경인지, 누가 했는지 기록한다
- **동시성**: 쓰기 전후로 해시를 구해 다르면 쓰지 못하게 하고, 메모리를 다시 읽어 수정안을 재작성한 뒤 재시도한다
- **권한 관리**: 조직 전체 지식은 읽기 전용, 에이전트 개인 스크래치패드는 쓰기 가능
- **이식성**: 공들여 다듬은 메모리를 여러 제품 표면과 시스템에서 쓸 수 있도록 깔끔한 API를 둔다

효과로는 같은 작업을 두 번째에 더 정확히 하고, 토큰을 덜 써 속도와 비용이 개선되며, 개발자가 제품에 집중할 여력이 생긴다고 한다.

### 인밴드 메모리의 한계와 '드리밍'

세션 안의 메모리는 작업과 메모리 관리가 자원을 놓고 경쟁하고, 에이전트가 자기 세션만 봐서 세션 간·에이전트 간 반복되는 실패 패턴을 못 본다. 그래서 학교의 교장처럼 전체를 보는 **아웃오브밴드 프로세스**를 둔다. 드리밍은 기존 메모리 저장소와 일정 기간의 트랜스크립트(도구 호출과 메타데이터 포함)를 에이전트에게 주면, 오케스트레이터가 서브 에이전트 플릿으로 분석해 변경안이 담긴 새 저장소를 내놓는 배치·비동기 작업이다. 예로는 빠진 주제를 커리큘럼에 추가하기, 계속 실패하는 도구 설정 고치기, 조직 전체의 엠 대시 남용 금지 공지가 있다. 각 변경안에는 근거 트랜스크립트와 얼마나 만연한지의 통계가 붙고, 사람이 수락·거절한다. 토큰을 추가로 쓰지만 에이전트가 한 번에 끝내게 되어 전체 비용은 오히려 준다고 주장한다. 메모리(즉시 개선)와 드리밍(넓은 가시성과 전용 자원)은 병렬로 돌아간다.

### Q&A에서 나온 것

- 기업용 구현은 Claude Managed Agents의 메모리·드리밍 API에 버저닝과 해싱이 들어 있다고 안내한다
- 권한은 드리밍 작업에 붙일 트랜스크립트를 메모리 저장소와 같은 권한 집합으로 제한해 맞출 수 있다
- 데이터베이스를 다시 발명하는 게 아니냐는 질문에는, 잘 통한다고 확인된 기본 요소를 결정적 방식으로 하네스에 코드화하는 것이라고 답한다
