# 처음부터 다시 구성해 봤지만… 결국 Zed가 이깁니다!

## 한 줄 요약

Flo Woelki는 Neovide와 Neovim 설정을 처음부터 다시 만들어 봤지만 Zed가 더 빠르게 느껴져 프로젝트 작업은 Zed로 돌아왔고, Neovim은 단일 파일 수정용으로만 쓴다고 말합니다. 결론은 완벽한 설정은 없으니 편안하게 느끼는 방식을 찾으라는 것입니다.

## 테마와 폰트가 바뀐 이유

- 요즘 가장 자주 받는 질문이 어떤 에디터, 폰트, 테마를 쓰느냐는 것입니다. 설정은 설명란의 저장소에 공개해 두었습니다
- 지금은 Zed에서 Tokyo Night 테마와 Terminus Nerd Font Mono 폰트를 씁니다. 영상에서는 GitHub Dark 테마와 Monaspace Neon 폰트를 그대로 씁니다
- 바꾼 이유는 단순히 새로운 조합을 써 보고 싶어서이고, 앞으로 영상용 설정은 다시 바뀔 수 있다고 합니다

## Neovide로 옮기려다 돌아온 과정

- Neovide의 그래픽 개선, 특히 뛰어다니는 커서가 마음에 들었는데 Zed에는 이것이 없습니다. 언젠가 Zed 소스를 살펴보고 직접 구현해 볼 수도 있다고 합니다
- Neovim 구성 파일을 전부 지우고 플러그인을 추가·삭제하며 처음부터 다시 만들었습니다
- 가장 중요한 트리 플러그인(Neo-tree)의 소스 선택기가 프로젝트 크기에 따라 몇 초씩 멈췄고, 특히 Git 상태 소스가 느렸습니다. 설정 실수일 수도 있지만 수정된 파일을 구분해 보는 기능이 꼭 필요했던 터라 만족스럽지 않았습니다
- 금세 Zed에 익숙해졌다고 느꼈고, 근육 기억 때문일 수도 있지만 Zed에서 더 빠릅니다. 플러그인이나 복잡한 설정 없이 필요한 기능이 내장돼 있기 때문일 수 있다고 합니다

## 지금의 사용 방식

- 프로젝트에는 Zed, 설정 파일 하나를 고치거나 파일을 잠깐 볼 때는 Vim/Neovim을 씁니다
- AI는 Zed의 내장 AI 패널 대신 새 터미널에서 open code나 Claude CLI를 쓰는 방식을 선호합니다. 단축키(space th)로 오른쪽에 터미널을 엽니다
- 아쉬운 점은 현재 파일을 오른쪽으로 분할한 뒤 터미널이 열린다는 것입니다. 파일 없이 터미널만 오른쪽에 열리기를 원하지만, 이는 Zed의 비동기적 특성에서 오는 문제라고 설명합니다. Zed를 포크해 고치는 영상을 보고 싶다면 댓글로 알려 달라고 합니다

## 결론: 편안함이 우선

- 코드를 읽거나 쓸 때 편안함을 느끼는 자신만의 방식을 찾아야 합니다
- 완벽한 설정도, 모두에게 맞는 공통 설정도 없습니다
