# 기능 또는 개선사항 브레인스토밍

브레인스토밍은 대화를 통해 무엇(**WHAT**)을 만들지 답합니다. 그 후 `ce-plan`이 동일한 통합 계획 아티팩트에 어떻게(**HOW**)를 보강합니다. 이 스킬은 코드를 구현하지 않습니다. 아티팩트 날짜 작성을 위한 **현재 연도는 2026년**입니다.

**결과물:** 제품 동작, 범위 경계, 성공 기준을 임의로 지어내지 않고도 기획/계획 단계에서 보강할 수 있는 적절한 규모의 결과물: 경량(Lightweight) 작업의 경우 채팅 단락, 파일 작성이 필요한 경우 `<root>/plans/` 아래의 요구사항 전용 통합 계획.

**브레인스토밍 경로 완료 조건:** 해당 아티팩트가 작성되어 계획 준비 완료 검사(Ready for Planning Check)를 통과했거나, 대화에서 다운스트림 소비자가 식별 가능한(IDed) 형태로 필요로 하는 결정을 도출하지 않았고 사용자도 요구하지 않아 파일이 작성되지 않았으며, 4단계 핸드오프가 제시되었을 때입니다.

**경량(Lightweight) 작업은 채팅으로 끝납니다.** 0.3단계는 아무것도 디스패치하기 전에 요청과 제한된 인라인 읽기를 통해 티어를 분류합니다. 티어가 불확실할 때는 더 무거운 쪽을 선택합니다. 경량 작업(규모가 작고 경계가 명확하며 모호성이 낮음)은 파일, 접지 탐색기(grounding scout), 접근 방식 생성, 주장 검증기 없이 채팅 단락으로 끝납니다. 파일은 다운스트림 소비자가 식별 가능한 형태로 필요로 하는 결정이 있거나 사용자가 요청한 경우에만 작성됩니다.

기억에 의존하지 않고 `references/phase-0.md`에 의해 결정되는 세 가지 경우에는 **중단하고 대신 라우팅**합니다. 각각 고유한 방식으로 실행을 종료하므로 위의 완료 기준이 적용되지 않습니다: 비소프트웨어 작업(0.2~4단계 대신 `references/universal-brainstorming.md` 적용), 지정된 외부 후보에 대한 판정 질문(`ce-pov` 핸드오프 제안), 그리고 둘 다 아닌 경우(빠른 도움, 사실적 질문, 단일 단계 작업 - 직접 답변).

기능 설명은 사용자가 작성했든 호출 스킬이 전달했든 호출에 포함된 내용입니다. 전달된 내용이 없으면 사용자에게 무엇을 탐색하고 싶은지 묻고 응답을 받을 때까지 진행하지 마세요.


## 아티팩트 루트 (Artifact Root)

`<root>/` 경로를 처음 구성하거나 읽을 때 `<root>`를 해석(resolve)하며, 그보다 일찍 하지 않습니다. 아무것도 건드리지 않는 스크래치 전용 또는 리포지토리 없는 실행은 이를 완전히 건너뜁니다.

<!-- ce-docs-root:start -->
**아티팩트 경로를 구성하기 전에 CE 아티팩트 루트 `<root>`를 확인하세요.**

- `docs_root`는 `<repo-root>/.compound-engineering/config.yaml`에서만 **읽습니다** (`<repo-root>` = `git rev-parse --show-toplevel`). `config.local.yaml`에서는 읽지 않습니다. 설정되지 않은 경우 -> 이전과 동일하게 `<root>`는 `docs`입니다.
- 설정된 값을 **검증합니다**: 심볼릭 링크가 해석된 실제 경로가 리포지토리 내부에 유지되고 리포지토리 루트도 아니며 `.git/` 아래도 아닌 리포지토리 상대 디렉토리여야 합니다. 그렇지 않은 경우 `docs_root`와 해당 값을 명시하는 오류와 함께 중단합니다. 절대 `docs`로 대체(fallback)하지 마세요.
- `<root>`를 유일한 아티팩트 위치로 **사용합니다**: 없으면 생성하고, 각 경로를 이 스킬의 자체 하위 디렉토리가 포함된 `<root>/<subdir>`로 구성하며, `docs`를 함께 읽지 마세요.
<!-- ce-docs-root:end -->

`brainstorm_output`과 `brainstorm_model`은 대신 이 규칙에 따라 해석됩니다:

<!-- ce-config-layers:start -->
**두 개의 리포지토리 파일에서 일반 CE yaml 키를 해석합니다.**

- `<repo-root>/.compound-engineering/config.local.yaml`을 읽은 다음 `config.yaml`을 **읽습니다** (`<repo-root>` = `git rev-parse --show-toplevel`). 없는 파일은 건너뜁니다. Gitignore는 해석을 변경하지 않습니다.
- 첫 번째 활성(주석 처리되지 않은) 값으로 **결정합니다**. 스칼라 값의 경우 빈 값은 미설정으로 간주되며, 잘못된 값은 다음 레이어로 넘어가고 그 다음 스킬 기본값으로 넘어갑니다. 리스트 및 맵의 경우, 빈 리스트나 맵을 포함하여 존재하는 키가 전체 키를 대체합니다.
- `docs_root`에는 이 규칙을 **사용하지 마세요** — 해당 키는 `config.yaml` 전용입니다.
<!-- ce-config-layers:end -->

## 실행 흐름 (Execution Flow)

단계는 다음 순서로 실행됩니다. 각 단계에는 올바르게 실행하기 위해 반드시 필요한 파일이 명시되어 있습니다. 해당 단계에 도달했을 때 파일을 읽고, 이 표만 보고 작업을 수행하지 마세요.

| 단계 | 먼저 읽을 파일 | 해당 파일에만 포함된 내용 |
|---|---|---|
| 첫 번째 질문 전 및 전체 실행 동안 (비소프트웨어 경로 포함) | `references/interaction-rules.md` 읽기 | 핵심 원칙 및 상호작용 규칙: 턴당 질문 1개, 환경이 해결할 수 없는 결정만 질문, 블로킹 질문 도구 기본값 및 이를 재정의하는 시각적 프로브 게이트, 질문이 진정으로 개방형인 경우, 이 스킬이 완전히 명시하는 하나의 `ce-prototype` 라우팅 테스트 |
| 대화에 포함된 결정을 확정된 것으로 취급하기 전 | `references/settled-decisions.md` 읽기 | 확정 테스트; 건너뛰면 이미 결정된 질문을 다시 묻거나 검토되지 않은 주장을 승격시키게 됨 |
| 0.0 출력 모드 | `references/output-mode.md` | `OUTPUT_FORMAT` 우선순위; 토큰 파싱 규칙 |
| 0.1–0.4 재개, 분류, 라우팅, 스코프 | `references/phase-0.md` | 재개 스캔; 중단 및 라우팅 분류; 스코프 티어; 일관된 작업 게이트; 두 가지 트립와이어(tripwires); 작업 스파인(spine) |
| 1 아이디어 이해 | `references/dialogue.md` | 컨텍스트 스캔 및 접지 탐색기; 선택적 Slack 리서처; 압박 테스트; 사각지대 및 시각적 프로브 게이트; 기존 `CONCEPTS.md` 및 검증된 코드와의 충돌 게이트; 1.3단계 종료 조건 |
| 2–2.6 접근 방식, 종합, 검증 | `references/approaches.md`, 종합 작성 전 `references/synthesis-summary.md` 추가 읽기 | 접근 방식 생성; 모델 격상(elevation); 스코핑 종합; 주장 검증기 |
| 3 계획 작성 | `references/plan-write.md`, 그 다음 `references/brainstorm-sections.md` 및 형식에 대한 렌더링 참조 문서 | 문서 작성 타당성 여부; 섹션 계약; 계획 준비 완료 검사(Ready for Planning Check) |
| 4 핸드오프 | `references/handoff.md` | 옵션 세트 및 표시 조건; 렌더링 모드 규칙; `ce-plan`에 전달되는 내용을 포함한 선택별 디스패치; 마무리 요약 |

이 규칙들은 별도의 읽기 없이도 유지됩니다:

**`OUTPUT_FORMAT`은 상호 배타적입니다** — 마크다운 또는 HTML 중 하나만 사용하며 둘 다 사용하지 않습니다. 파이프라인 모드(LFG 또는 `disable-model-invocation` 컨텍스트)에서는 강제로 `md`가 됩니다.

**브레인스토밍 경로에서 파일이 작성될 때 아티팩트 계약은 변경되지 않습니다**: `<root>/plans/YYYY-MM-DD-HHMM-<type>-<topic>-plan.<md|html>`에 작성하며, `HHMM`은 작성 시점의 로컬 실제 시간(wall-clock time)을 사용합니다. 프론트매터에는 `artifact_contract: ce-unified-plan/v1`, `artifact_readiness: requirements-only`, `product_contract_source: ce-brainstorm`이 포함됩니다. 본문은 목표 캡슐(Goal Capsule)과 제품 계약(Product Contract)으로 구성됩니다. 목표 실행 블록(Goal Launch Block)이나 리더 인덱스(Reader Index)를 출력하지 **마세요**. 비소프트웨어 경로는 이를 전혀 작성하지 않습니다.

**파일이 작성될 때, 계획 준비 완료 검사(Ready for Planning Check)에서 하나라도 실패하면 작성이 완료되었다고 선언하거나 4단계로 진입하지 마세요.** 채팅 결과는 검사 없이 4단계로 진입합니다. 즉흥적으로 만든 4단계 메뉴는 또 다른 침묵의 실패입니다: 숨겨져야 할 옵션이 노출되고 잘못된 페이로드가 다운스트림으로 전달됩니다.

1.1단계 접지 탐색기, 2.6단계 주장 검증기, 선택적 Slack 리서처는 모델 이름으로 하드코딩되지 않고 작업 형태에 따라 티어가 나뉩니다. 디스패치하기 전에 `references/model-tiers.md`를 읽으세요. 모델 격상은 별도의 메커니즘입니다(`references/reasoning-elevation.md`).
