# 작업 실행 명령 (Work Execution Command)

## 결과물 (Outcome)

- **결과:** 계획, 명세서 또는 구체적인 작업 프롬프트로부터 완전히 구현되고 로컬에서 검증된 변경 세트.
- **다음 소비자:** 단독(standalone) 사용 시 배송(shipping) 워크플로우가 검증된 변경사항을 리뷰 및 전달로 이끕니다. 호출자 반환 모드(Return-to-Caller Mode)에서는 호출한 워크플로우가 구조화된 구현 및 검증 엔벨로프(envelope)를 수신하고 남은 게이트를 소유합니다.
- **완료 조건:** 범위 내의 모든 작업이 완료되고, 필수 검증 증거가 기록되며, 관련 검사가 통과하고, 실행이 소유된 배송 핸드오프(코드 리뷰 영수증 또는 명시적 건너뛰기 문구 포함 — 3-4단계 참조), 완전한 반환 엔벨로프, 또는 명시적 차단 요소 중 하나에 도달했을 때입니다.
- **의도:** 계획을 재협상하거나 표준 통합 권한을 이전하지 않고 요청된 기능을 완료합니다. 워커(worker)는 바운딩된 단위를 받으며, 호스트 오케스트레이터는 실제 변경사항을 검사하고 권한 있는 검증 및 표준 커밋을 소유합니다.

## 실행 워크플로우 (Execution Workflow)

**번들 참조 로딩은 안전 우선 차단(fail-closed) 방식입니다.** 아래에 명시된 모든 번들 참조 또는 스크립트 경로는 하네스가 제공한 스킬 전체 경로를 사용하여 이 스킬이 로드된 `SKILL.md` 디렉토리에서 해석합니다. 번들 파일을 찾기 위해 타겟 리포지토리를 절대 glob하지 마세요. 해당 단계에 들어갈 때 단계의 소유자 참조를 읽으세요. 해당 단계 전에 읽은 것은 충족된 것으로 간주하지 않으며, 다시 읽도록 명시된 소유자는 이미 컨텍스트에 있더라도 해당 단계에서 다시 읽습니다. 하네스가 해당 디렉토리를 노출하지 않거나 필수 파일을 읽을 수 없는 경우, 프로토콜을 어림짐작하거나 네이티브 방식으로 계속 진행하는 대신 해당 규칙이 적용되는 작업 전에 중단하고 누락된 참조를 보고하세요.

### 0단계: 입력 트리아지 (Input Triage)

**복구 활성화가 우선입니다.** 일반적인 계획, 경로, 빈 입력 또는 단순 프롬프트 분류 전에 기존 실행을 재개, 검사, 정리(reap/clean up)하려는 시맨틱 요청을 인식하세요. 복구는 새로운 워커를 디스패치하거나, 새 경로를 선택하거나, 다른 계획을 발견하거나, 완료된 검증을 재실행하거나, 배송 마무리 단계로 진입하지 않습니다. 누락된 실행 ID는 추측하지 않고 요청합니다.

다른 모든 입력 결정 전에 `references/input-triage.md`를 읽으세요. 사소한(Trivial) 단순 프롬프트(1~2개 파일, 동작 변경 없음)는 작업 목록을 건너뛰고 작성 전 엔진 게이트를 통과합니다. 순수하게 기계적인 diff 또한 PR 이후 감시 없이 배송됩니다. 불확실할 때는 더 완전한 경로를 선택합니다. 이번 세션의 `ce-plan`이 이미 규모를 산정한 단순 프롬프트는 다시 계획하지 않고 실행합니다. 사용자가 고민할 결정은 질문으로 표출하며 절대 `ce-plan`이나 `ce-brainstorm`으로 되돌리는 경로로 넘기지 않습니다. 소스 해석, 제어 문법, 복구, 읽기 전용 발견, 계획 준비 상태, 비코드 라우팅, 빈 입력 발견 및 단순 프롬프트 접수를 소유합니다. 읽을 수 없는 소유자가 있으면 제어 데이터나 실행 불가능한 아티팩트가 코드 작업으로 넘어가지 않도록 트리아지를 중단합니다.

트리아지가 호출자 반환 모드(Return-to-Caller Mode)로 진입하면 즉시 `references/return-to-caller.md`를 읽으세요. 해당 실행에 대한 마무리 소유자를 기록합니다. 로드할 수 없으면 단독 동작으로 되돌아가지 않고 변경(mutation) 전에 중단합니다.

### 1단계: 빠른 시작 (Quick Start)

1. **작업 공간 확립.** 브랜치 이동, 편집, 디스패치 또는 커밋 전에 `references/workspace-setup.md`를 읽으세요. 쓰기 가능한 체크아웃 선택, 계획 명확화, 브랜치 배치, 작업 전 인벤토리, 충돌 처리, 작업 설정을 소유합니다. 쓰기 가능한 표준 체크아웃 없이 쓰기를 수행하거나 사용자의 명시적인 동일 세션 지시 없이 실제 기본 브랜치에서 쓰기를 수행하지 마세요.

   **WIP/쓰기 게이트.** 사용자가 제공하지 않은 것은 커밋하거나 게시할 수 없습니다. 작업 단위가 이미 더티(dirty) 상태인 파일을 필요로 하는 경우, 단독 모드는 이를 포함할지 제외할지 한 번 묻습니다. 호출자 반환 모드는 묻거나 편집하지 않고 충돌 및 복구 경로와 함께 차단됨(blocked)을 반환합니다. 읽을 수 없는 작업 공간 소유자가 있으면 브랜치 이동 또는 편집 전에 중단합니다.

2. **엔진 결정 후 전략 결정.** 제한된 계획 접수 및 작업 도출 후, 실행 단위를 선택하거나 쓰기, 디스패치, 커밋하기 전에 `references/execution-engines.md`를 읽고 경로 결정 게이트를 완료하세요. 이는 타입 바인딩의 유무와 관계없이 적용됩니다. 네이티브 실행은 해당 소유자가 이를 선택하거나 허용된 대체 경로를 모두 소진한 경우에만 적합합니다. 엔진 선택은 0단계 마무리 소유자를 절대 변경하지 않습니다.

   교차 모델(cross-model) 실행이 선택된 경우, 내용이나 권한이 해당 경로를 넘어가기 전에 `references/cross-model-execution.md`를 읽으세요. 컨트롤러 초기화, 초기화 후 엔진 잠금, 제한된 송출, 트랜잭션, 복구, 영수증을 소유합니다. 네이티브 디스패치로 어림짐작하지 마세요.

   인라인, 직렬, 병렬 실행을 선택하거나 워커를 디스패치하기 전에 `references/execution-strategy.md`를 읽으세요. 스케줄링, 격리, 단위 패킷, 워커 수명 주기, 통합을 소유합니다. 호스트 오케스트레이터가 권한 있는 검증 및 표준 커밋을 유지합니다.

### 2단계: 실행 (Execute)

사소한(Trivial) 경로를 포함하여 첫 번째 구현 쓰기 전에 `references/implementation-loop.md`를 읽으세요. 증거 선택, 구현, 검증, 완료 중단, 점진적 커밋, 패턴 준수, 지속적 테스트, 단순화 경계, UI 작업, 진행 상황 추적, 확정된 결정 처리를 소유합니다.

커널의 쓰기 게이트는 계속 활성 상태로 유지됩니다. 모든 구현 커밋은 해당 단위가 소유한 파일로 경로가 제한됩니다. 단순 커밋(bare commit)은 사용자의 기존 인덱스를 흡수할 수 있으므로 금지됩니다.

### 3-4단계: 품질 검사 및 마무리 작업 (Quality Check and Finishing Work)

작업 및 로컬 검증이 완료된 후, 단독 모드는 품질 검사 또는 전달 전에 `references/shipping-workflow.md`를 반드시 읽어야 합니다. 단순화(simplify), 리뷰 영수증 및 대체 메커니즘, 잔여물, 최종 유효성 검사 및 전달을 소유합니다.

**코드 리뷰 완료 게이트 (단독 모드 전용).** `shipping-workflow.md`에 실제로 완료된 `ce-code-review` 영수증이나 정확한 승인된 건너뛰기 상태 중 하나가 기록될 때까지 실행은 **완료되지 않은 것**이며 커밋/배송 스킬을 호출하거나 배송 완료를 보고해서는 안 됩니다. 머릿속 자체 리뷰나 이미 적용된 결과로 대체하지 마세요. 이 게이트는 호출자 반환 모드에는 적용되지 않습니다.

## 호출자 반환 모드 (Return-to-Caller Mode)

호출자 반환 모드는 구현 및 로컬 검증만 수행합니다. 3-4단계로 진입하거나 최종 단순화, 코드 리뷰, PR 생성, CI 감시, 베이비시팅 또는 기타 단독 배송 작업을 실행해서는 안 됩니다. 해당 게이트는 호출자가 소유합니다.

결과를 출력하기 직전에 `references/return-to-caller.md`를 다시 읽으세요. 완전한 엔벨로프, 증거 완료 게이트, 경로 및 모델 영수증, 복구 시맨틱, `standalone_shipping_skipped: true`를 단독으로 소유합니다. 이 커널로부터 완전한 엔벨로프를 임의로 재구성하지 마세요.

계획 또는 구현이 상태를 생성한 후 해당 필수 읽기가 실패하면 변경된 모든 파일, 커밋, 작업 공간 및 컨트롤러 영수증을 보존하세요. 이 커널에서 최소한의 차단된 복구 결과를 반환합니다: `status: blocked`, `plan_path`, 알려진 경우 `run_id`, `changed_state`, 누락된 소유자를 명시하는 `blockers`, `recovery_path`. 부분 상태를 지우거나, 성공을 보고하거나, 단독 마무리 단계로 빠지지 마세요.
